# 로컬 퀴즈 · 풀이시간 · 개념별 학습 분석

기존 최소 RAG의 검색 결과를 받아 문제를 생성하고, 브라우저에서 풀고, 응답·시간을 SQLite에 저장한다. 학생 기록은 벡터 인덱스와 별도 보관한다. 이 프로젝트의 `sources/` 및 기존 영상 산출물은 수정하지 않는다.

## 실행

일반 Mac Terminal에서 프로젝트 루트의 `퀴즈_학습분석_실행.command`를 실행한다. 기존 `.venv-rag`를 사용하며 추가 라이브러리 설치는 없다. 브라우저 주소는 `http://127.0.0.1:8765`다. 서버의 Python 파일을 수정했다면 **Ctrl+C로 종료 후 같은 실행 파일로 재시작**해야 한다. 저장된 문제와 학습 기록은 유지된다.

1. 테스트 학습자 이름을 입력한다. 브라우저에 ID를 보관하며 실제 서비스 인증이 아니다.
2. 과목·학기·분반을 선택한다. 기본 강좌의 **동작 확인용 예제**로 즉시 풀거나 **Gemini로 5문항 생성**을 누른다. 특정 개념을 선택하면 해당 개념의 후속 연습 세트를 만든다.
3. 답안 제출 후 정답·해설·출처·활성시간·경과시간을 확인한다.
4. 개념별 학습 기록에서 정오답·시간 신호를 확인한다. 기록이 적으면 판단을 보류한다.
5. 숏츠 연결 데이터 버튼은 JSON을 생성·다운로드한다. HeyGen 호출이나 영상 제작은 아직 하지 않는다.

기존 `outputs/rag-mvp/corpus.json`이 필요하다. 자료가 없다면 `RAG_최소흐름_실행.command`로 먼저 준비한다. 새 강좌의 인덱스는 최초 문제 생성 시 생성하며 기존 임베딩 캐시를 재사용할 수 있다. Gemini 호출은 사용자의 터미널에서 실행된 서버가 처리한다. 외부 API 테스트를 금지하려면 `.venv-rag/bin/python -m quiz_mvp --offline`으로 실행한다.

## 과목·학기·분반 분리 (schema v2)

- 강좌(`offering_id`)는 과목 코드 + 학기 + 분반 조합으로 생성한다. 동일 조합의 중복 생성은 거부한다. 개념 ID가 같아도 취약도 집계 키는 **학습자 + 강좌 + 개념**이다.
- 화면에서 강좌를 선택한 후 자료·퀴즈·기록을 사용한다. 새 강좌에는 자료와 퀴즈가 없다. 기존 스택 자료는 **등록 버튼을 명시적으로 눌렀을 때만** 해당 강좌에 복사한다.
- 현재 자료 등록은 기존 추출 과정이 만든 `version=1`의 `corpus.json`만 받는다. 본문 해시, 필수 출처, 중복 ID, `native_xml_text_coverage_checked` 상태를 검사한다. 이는 기존 검증 산출물을 가져오는 기능이며, 임의 JSON의 내용을 원본과 다시 대조하거나 PDF/PPT/영상 원본을 새로 추출하는 기능은 아니다. 미검증 OCR 청크 등록은 거부한다.
- 등록 시 강좌 ID를 청크에 붙이고 `outputs/quiz-mvp/courses/<강좌 ID>/<자료 버전>/`에 저장한다. 벡터 인덱스도 같은 강좌·자료 버전 폴더에서 별도로 만든다. 자료가 없는 강좌에서 다른 강좌의 인덱스를 대신 검색하지 않는다. 동일 텍스트의 API 캐시는 재사용할 수 있지만 검색 대상은 분리한다.
- 자료 재등록은 해당 강좌의 활성 자료 버전을 교체한다. 이전 버전 파일·기존 퀴즈의 스냅샷과 채점 근거는 보존한다. 청크를 나누거나 임베딩 모델을 바꿔도 학습 기록이 인덱스와 함께 지워지지 않는다.
- `quizzes`, `attempts`, `responses`, `events`, `materials`에 강좌 ID를 보관한다. `students`는 공통 학습자 ID이고 `enrollments`로 강좌 등록을 따로 관리한다. 개념 목록도 강좌별이다.
- 분석은 먼저 강좌로 응답을 제한한 뒤 첫 풀이·반복 풀이·힌트·시간 기준을 계산한다. 다른 과목뿐 아니라 다른 학기와 분반의 학생도 비교 시간 표본에서 제외한다. 숏츠 연결 JSON에도 강좌 정보가 들어간다.
- `/api/courses`, `/api/enrollments`에서 강좌 생성·선택을 처리한다. 강좌별 API는 `X-Student-ID`와 `X-Offering-ID`를 요구하며, 등록 여부·문제/풀이 소속을 검사한다. 다른 강좌의 ID로 퀴즈·풀이·생성 작업을 조회할 수 없다.
- 브라우저의 이어 풀기 키도 학습자+강좌별로 분리한다. 강좌 변경 전에 기존 타이머를 정지하고, 이전 강좌에서 늦게 도착한 응답은 새 화면에 적용하지 않는다.

**기존 데이터 이전:** 새 서버를 처음 시작하면 기존 DB를 `learning.sqlite3.pre-course-v2.sqlite3`에 백업하고 schema v2로 이전한다. 이전 문제·풀이·이벤트 JSON과 해시는 바꾸지 않는다. 기존 자료와 기록은 `legacy-stack` 강좌(자료구조 기존 테스트 / 학기 미지정 / 기본 분반)에 연결한다. 실제 학기·분반을 임의로 추정하지 않는다. 이전은 한 번만 수행한다. 기존 서버 실행 중 DB를 직접 이전하지 않고, 새 서버가 포트 바인딩에 성공한 뒤 이전한다.

이는 로컬 기능 분리다. 테스트 사용자는 스스로 강좌를 생성·등록할 수 있으며 브라우저 ID 헤더는 실제 인증 수단이 아니다. 운영용 교수/학생 권한, 수강 명단 검증은 별도 구현이 필요하다.

## RAG 변경 후에도 유지되는 구조

```text
quiz_mvp/materials.py: 강좌·자료 버전 선택 → rag_mvp/evidence.py 공통 검색 → EvidenceBundle v1 + offering_id
    ↓ 본문·출처·청크 ID·corpus_version
quiz_mvp/generation.py: 객관식 생성·재검증
    ↓ 불변 QuizSnapshot + 고정 concept_id
quiz_mvp/store.py: 학습 DB, 응답·시간 이벤트, 개념별 분석
    ↓ LearningContentRequest v2
향후 숏츠 대본 생성 → HeyGen (미연결)
```

- `EvidenceBundle v1`: `schema_version`, `retriever_version`, `corpus_version`, `query`, `sources`. 자료 검색 방법을 바꾸더라도 이 형식을 유지한다. 강좌별 퀴즈는 ScopedRag를 통해 같은 검색 함수를 사용한다. 기존 `python -m rag_mvp` 단독 CLI는 기존 테스트 자료용으로 유지되며 강좌별 학습 기록을 읽지 않는다. 향후 다강좌 챗봇도 ScopedRag를 사용해야 한다.
- 기본 강좌의 개념 ID는 `stack.lifo`, `stack.push`, `stack.pop`, `stack.peek`, `stack.complexity`, `stack.underflow`를 사용한다. 새 강좌 생성 시 개념 ID=이름 목록을 지정한다. 같은 강좌 안에서는 ID를 유지한다. 개념을 통합·분리할 때는 별도 매핑/마이그레이션이 필요하다.
- 출제 시 문제·선택지·정답·해설·난이도·개념 버전·검증 결과·근거 원문 전체를 SQLite에 복사한다. 청크/인덱스를 재생성해도 이전 문제의 채점은 출제 당시 스냅샷을 사용한다.
- 문제 세트는 덮어쓰지 않는다. 원본 정정으로 기존 정답이 틀렸다고 확인된 경우 **문제 폐기·재채점·영향 분석 기능은 추후 추가해야 한다.** 현재 새 인덱스가 옛 정답을 자동 수정하지 않는다.
- 임베딩 모델 변경 시 인덱스만 재생성하고, SQLite 학습 DB는 유지한다. 저장소 교체 시 `Store` 인터페이스를 유지하고 SQL 데이터를 이전한다. 현재 클라우드 DB/배포는 연결하지 않았다.

## 출제 및 정답 검증

기초 2 / 적용 2 / 심화 1의 5문항을 만든다. 단원 진단은 서로 다른 개념을 골고루 배치하고, 특정 개념 연습은 같은 개념에서 서로 다른 사고 과제를 요구한다. 교수님 PPT에서 검색한 근거 안에서만 생성하도록 지시한다.

JSON 형태, 선택지 네 개·중복 여부, 지정 개념·난이도, 원문 인용 일치를 검사한다. 별도 Gemini 호출에는 출제 모델이 만든 **정답 번호와 해설을 전달하지 않고** 풀게 한다. 두 결과의 정답이 일치하고 단일 정답·근거·난이도 검사가 통과해야 저장한다. 최종 해설은 재풀이 결과를 사용하며 그 인용도 검사한다. 하나라도 실패하면 세트 전체를 보류한다. API 캐시에 후보 응답은 남지만 학습용 퀴즈 목록에 게시하지 않는다.

동일 모델을 별도로 호출한 검사이므로 독립적인 정답 보증은 아니다. 특히 유사한 문제의 반복과 난이도 적절성은 추가 평가가 필요하다. 현재 중복 차단은 같은 문제·선택지에 대한 정확 일치이며 의미가 비슷한 모든 문제를 제거하지 않는다.

생성 요청은 동시에 하나만 실행하며, 기본 40회 호출 상한과 기존 Gemini 재시도·캐시 정책을 따른다. 자료 인덱스가 없으면 해당 강좌 청크 수만큼 임베딩 호출이 먼저 필요하고, 캐시가 있으면 재사용한다. 인덱스 준비 뒤 정상 경로는 문항당 검색용 임베딩·생성·검증 각 1회(5문항 최대 15회, 검색 캐시로 감소 가능)다. 무료/유료 사용은 기존 API 계정 설정을 따른다. 브라우저를 닫아도 서버가 살아 있으면 작업이 계속되지만, 서버 재시작 시 실행 중 작업을 자동 복구하는 상시 워커는 아니다.

## 시간 측정

- 문제를 표시한 이벤트를 서버가 받은 시각부터 계산한다. 클라이언트가 보낸 임의의 완료 시간은 사용하지 않는다.
- 5초 간격 확인 이벤트, 탭 숨김/복귀, 창 포커스 이탈/복귀, 수동 일시정지 이벤트를 기록한다.
- 활성 상태의 이벤트 간격이 15초를 넘으면 초과분은 불확실 시간으로 기록한다. 장시간 연결 중단이나 절전 시간을 전부 풀이시간으로 인정하지 않는다.
- 전체 경과시간 / 추정 활성시간 / 비활성시간 / 불확실시간을 따로 저장한다. 화면 상태로 추정한 값이므로 실제 집중시간·부정행위 방지를 보장하지 않는다.
- 제출은 이벤트 ID 및 상태 버전으로 중복 처리를 막는다. 새로고침·중복 시작은 기존 미완료 풀이로 이어진다. 제출 후에만 정답과 해설을 브라우저에 전송한다.
- 힌트를 보면 해당 문제를 도움받은 풀이로 기록한다. 같은 문항을 다시 풀거나 힌트를 사용한 기록은 새로운 숙달 근거에 포함하지 않는다.

## 학습 분석 v3

객관식 정오답은 서버가 출제 당시 정답과 비교한다. 학생·강좌별 개념에 대해 서로 다른 문제의 **첫 풀이**를 집계한다. 힌트 사용 첫 풀이는 분석에서 제외한다. 3문항 미만은 판단 보류다. 첫 단원 진단 5문항만으로 모든 개념을 확정할 수 없다.

기초 1.25 / 적용 1.0 / 심화 0.75의 가중치로 오답 비율을 계산한다. 가중 오답 비율 0.5 이상은 취약 가능성, 0.25 이상은 복습 권장, 그 미만은 현재 응답에서 안정적으로 표시한다. **이 가중치·경계값은 검증된 교육측정 모델이 아닌 초기 실험 설정이다.** 개념별 난이도별 정오답 집계도 API에 제공한다.

활성 풀이시간은 기록하고 중앙값으로 표시하되, 불확실 시간이 있는 기록은 시간 중앙값과 비교에서 제외한다. 같은 강좌에서 같은 문항을 맞힌 다른 학생의 첫 풀이가 5명 이상일 때 그 중앙값과 비교한다. 해당 개념에서 비교 가능한 문제 3개 이상이고 시간 비율의 중앙값이 1.5를 넘으면 상대적으로 느린 신호를 표시한다. 정답이 안정적이면 이를 속도 연습 후보로 구분하며 단순히 오래 걸렸다는 이유로 개념 취약으로 바꾸지 않는다. 표본이 부족하면 시간 기준 부족이다. 실제 학생·문항 데이터로 보정이 필요하다.

## 학생·강좌별 챗봇

화면의 **이 강좌의 개인 학습 챗봇**에서 질문한다. 학생 ID + 강좌 ID로 대화를 저장하고, 새로고침/서버 재시작 후에도 조회한다. 강좌를 바꾸면 그 학생의 해당 강좌 대화만 표시한다. 최근 30개 질문·답변을 먼저 보여 주고 이전 대화 버튼으로 더 조회한다.

```text
학생·강좌 등록 확인
 → 질문 저장 (pending, 중복 요청 ID 검사)
 → 강좌별 ScopedRag / LlamaIndex 자료 인덱스 준비·검색
 → 같은 학생·강좌의 최근 대화 + 관련 과거 대화 + 최신 취약도 조회
 → Gemini에 현재 강의 근거와 개인화 맥락 전달
 → 출처·인용 검증 → 답변 저장 또는 근거 부족 보류
```

**역할 분담:** LlamaIndex는 강좌별 벡터 검색을 담당한다. 백엔드는 학생·강좌 접근 검사, 대화 저장, 취약도 계산, 프롬프트 구성 및 결과 검증을 담당한다. 현재는 LlamaIndex ChatEngine/Memory를 쓰지 않고 공통 검색 어댑터와 별도 영속 대화를 조합한다. 프레임워크 소스 코드를 수정하지 않는다.

- `chat_turns`: 학생 ID, 강좌 ID, 질문, 답변, 생성 상태, 요청 ID, 시각과 출제/답변 근거 버전, 답변 생성 당시 맥락 스냅샷을 저장한다. 기존 퀴즈·응답 테이블을 변경하거나 지우지 않는 추가 테이블이다.
- 대화 원문은 모두 보관한다. 모델에는 최근 6턴과 최근 200개 완료 대화 중 키워드가 관련된 과거 최대 3턴을 전달한다. 질문은 턴당 700자, 답변은 1,000자로 제한한다. 이는 제한된 맥락 선택이며 전체 과거 대화의 완전한 기억이나 AI 요약 기능은 아니다.
- 짧은 후속 질문의 검색을 돕도록 직전 질문 최대 500자를 검색어 뒤에 붙인다. 과거 답변은 사실 근거로 인정하지 않고 현재 강좌 자료에서 다시 검색한다. 자료가 바뀌어도 이전 답변에 사용한 근거와 버전은 기록에 남는다.
- 답변 시 최신 퀴즈 분석을 조회하고 질문·검색 자료와 관련된 최대 8개 개념의 정오답 수, 판단 상태, 시간 신호를 전달한다. 취약 가능성/복습 권장은 단계적인 설명에 활용하고, 3문항 미만 판단 보류나 시간 정보만으로 약점을 단정하지 않도록 지시한다. 교수 말투 모방은 제외한다.
- 대화 자체로 취약도 수치를 새로 계산하지 않는다. 이번 연결은 **기존 퀴즈 기반 취약도 → 챗봇 설명 개인화**이며, 대화 내용으로 취약도를 추정하는 기능은 별도 검증 후 추가할 수 있다.
- 답변은 현재 검색 근거의 출처 ID와 원문 인용을 검사한다. 인용이 틀리면 후보 답변을 표시하지 않고 보류한다. 인용 존재 검사는 의미적 정답이나 개인화 품질의 보증은 아니다.
- 질문 전송은 요청 UUID로 중복을 막고 같은 학생·강좌에 동시에 두 질문을 처리하지 않는다. 퀴즈 생성과 챗봇은 현재 로컬 서버의 AI 작업 잠금을 공유한다. 서버가 살아 있으면 화면을 닫아도 생성은 계속된다. 재시작 시 미완료 대화는 실패 상태로 남기며 자동 재호출하지 않는다. 실패한 질문을 다시 입력할 수 있다.
- 개인화 Gemini 응답 캐시는 `outputs/quiz-mvp/chat-cache/<학생 ID>/<강좌 ID>/`로 분리한다. 검색용 임베딩 캐시는 기존 자료 캐시를 사용한다. 모델 요청에 이름·학생 ID는 넣지 않지만 질문 내용, 선택된 대화 및 학습 신호는 Gemini에 전달된다.
- UI는 모델 출력에 HTML을 실행하지 않고 텍스트로 표시한다. 강좌 변경 뒤 늦게 도착한 다른 강좌의 대화 응답을 버린다. 퀴즈 풀이 중 질문하면 타이머를 일시정지한다. 외부 도움 사용을 완전히 감지하는 시험 감독 기능은 아니다.

API는 `GET /api/chat?before=<seq>`, `POST /api/chat` (`question`, `request_id`), `GET /api/chat/<turn_id>`이며 모두 학생·강좌 헤더와 등록 확인을 요구한다. 클라이언트가 임의로 보내는 과거 대화/취약도 대신 서버 DB에서 읽은 값을 사용한다.

새 서버를 재시작해야 챗봇 API와 테이블이 추가된다. 오프라인 모드는 저장 대화 조회만 제공하고 AI 답변을 꾸며 내지 않는다. 에이전트 검증은 모의 Gemini·실제 SQLite/HTTP 처리기·실제 LlamaIndex 검색 테스트로 구성하며, 실제 Gemini 응답과 브라우저 화면은 사용자의 일반 Terminal 서버에서 확인해야 한다.

## 숏츠 연결

`POST /api/shorts`는 개념 ID·분석 요약·출제 당시 근거 스냅샷을 `LearningContentRequest v2`으로 만든다. 학생 이름/ID는 포함하지 않는다. 향후 최신 RAG로 근거를 재확인하고 대본 생성·HeyGen 제작을 연결할 수 있다. 현재 상태는 `prepared_only`, `video_generated=false`다.

## 파일

|---|---|

| `chat_store.py` | 학생·강좌별 영속 대화·중복 요청·중단 상태 관리 |
| `test_chat.py` | 대화 격리·취약도 전달·실패 복구·HTTP 흐름 검사 |
| `courses.py` | 강좌·등록·개념 목록·기존 DB 이전 |
| `materials.py` | 강좌별 자료 버전·인덱스·검색 범위 제한 |
| `test_courses.py` | 과목·학기·분반 분리, 이전, 교차 접근 차단 검증 |
| `test_frontend.cjs` | 브라우저 상태 코드의 강좌별 키와 지연 응답 처리 단위 검증 |
| `store.py` | 버전별 SQLite 저장·채점·시간 누적·학습 분석 |

| `web/` | 학습자·문제·타이머·결과 화면 |
| `test_learning.py` | 생성 계약, 중복 제출, 시간, 재풀이, RAG 갱신 후 기록 유지 등 검사 |

실제 서비스용 로그인, 분반별 권한, 서버 간 작업 큐, HTTPS 배포, 개인정보 보관/삭제 정책은 아직 미구현이다. 서버는 `127.0.0.1`에만 바인딩하는 로컬 개발용이며 외부에 그대로 배포하지 않는다.

## 검증 명령

```sh
.venv-rag/bin/python -m unittest rag_mvp.test_mvp quiz_mvp.test_learning quiz_mvp.test_courses quiz_mvp.test_chat -v
node quiz_mvp/test_frontend.cjs
```

네트워크 없이 실행하는 모의 API 테스트와 실제 API 생성 기록을 구분한다. 격리 실행 공간에서 포트 열기가 금지되면 소켓 HTTP 테스트 하나만 건너뛰고, 실제 HTTP 요청 처리기를 메모리 스트림으로 검증한다. 일반 Mac Terminal에서는 `QUIZ_REQUIRE_HTTP=1`로 소켓 테스트까지 필수 실행한다. 실행 파일에도 이 검사를 포함했다.
