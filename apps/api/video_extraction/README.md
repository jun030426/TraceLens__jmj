# 분야별 코드 위치

이 폴더 안의 실제 구현 파일을 이동했습니다. 분야별 복사본·심볼릭 링크·`.py.md` 안내 파일은 만들지 않았습니다.

| 하위 폴더 | 내용 |
|---|---|
| `ppt/` | `other_data.py`, `other_data_guarded.py`: PPT 원문 XML 검사와 v2 처리. 영상·음성 검토도 호출하는 실행기입니다. |
| `pdf/` | PDF 전용 파이프라인은 아직 미구현입니다. |
| `video/` | 영상 프레임·이미지 판독, 좌표·잘림·구분선 검사 |
| `audio/` | 전사·원음 대조·중복 누락 검사·수정·사용 데이터 선별 |
| `ink/` | 필기·기호·음성 연결, 수정 정책·복구·검증·선별 |
| `shared/` | API·저장·전처리·공통 검사. `media.py`는 화면과 음성 최초 추출 모두에 사용됩니다. |
| `review/` | 정답 표본·평가·오프라인 재검토 |
| `tests/` | 회귀 테스트 |
| `fixtures/` | 기존 검사 근거와 표본. 경로를 유지했습니다. |

최상위 `__main__.py`는 통합 실행 진입점입니다. `python -m video_extraction`과 프로젝트 최상위 `.command`의 이름·위치는 그대로이며, 내부 import와 호출 경로는 새 위치로 갱신했습니다. 예: `python -m video_extraction.ppt.other_data_guarded --help`.

이번 이동 대상은 이 폴더의 파일입니다. 폴더 밖에 있던 python-pptx 최초 추출 스크립트(`outputs/extraction-repair/scripts/extract_slides.py`)는 원래 위치에 남아 있습니다. 외부 RAG·퀴즈 코드·실행 명령은 새 import 경로만 수정했습니다.

기존 결과·계획은 변경하지 않습니다. `_layout.py`와 `layout-migration.json`은 이동한 코드 위치를 찾고, 이번 경로 변경에 해당하는 정확한 코드 해시 쌍만 기존 계획과 호환시킵니다. 데이터 해시 검사나 이전부터 있던 코드 불일치는 무시하지 않습니다.

오프라인 검사 명령: `python -m unittest discover -s video_extraction/tests -t .`

# 강의영상 추출 워커

영상 파일 하나를 받아 음성 전사와 화면 추출을 별도로 보존하고, 실제 영상 시간으로 연결합니다. 기존 추출 실험과 `sources/`는 수정하지 않습니다. 벡터 DB 저장·임베딩·배포는 이 워커의 범위에 포함하지 않습니다.

## 현재 검증 범위

- FFmpeg 음성 추출·선택적 2단계 음량 정규화, PyAV 화면 선별, 로컬 faster-whisper 전사를 구현했습니다.
- Gemini 화면 추출 → 전체 화면 감사 → 중요 영역 원본 해상도 자르기 → 독립 재판독 → 원본 대조 후 변경/보류를 구현했습니다.
- 모델이 빈 문자열·공백뿐인 영역을 반환하면 원본 응답과 좌표를 보존하고 재판독합니다. 검증된 판독으로만 교체하며, 재판독 실패·검토 상한 초과·`unchanged` 응답으로 해결되지 않은 빈 영역은 `empty_extraction_block` 사유로 검토 대기합니다. 기존 완료 결과와 API 캐시는 같은 명령으로 재개할 때 재사용됩니다.
- 낮은 신뢰도 등으로 표시된 음성 구간은 원본 오디오를 Gemini로 재전사·검토하는 경로가 있습니다.
- API에는 자료 구조·필수 필드·자료형·열거값을 포함한 간소화된 JSON Schema를 전달합니다. 문자열 길이·배열 개수·좌표 범위 등 모든 원래 제약은 반환 후 로컬에서 검사하며, 검사 실패 결과는 채택하지 않습니다. 이는 내용의 사실성을 보장하지 않습니다.
- 자동 검토 단계는 테스트 대역으로 검증했습니다. 실제 Gemini 호출의 검증 상태와 결과는 각 실행 폴더의 `state.json`을 확인하세요. 네트워크 오류·할당량 초과를 완료로 처리하지 않습니다.

## 실행

### 공통 전처리와 정답 표본 준비 — API 없음

`preprocessing.py`는 현재 강의의 저장된 화면·음성·PPT 결과를 읽는 오프라인 어댑터입니다. 새 영상 전체를 추출하는 실행기가 아니며, 기존 추출 명령이나 RAG 입력 경로를 자동으로 바꾸지 않습니다. 현재 입력은 코드에 명시된 최신 수동 검토 결과입니다.

```sh
.venv-rag/bin/python -m video_extraction.shared.preprocessing \
  --source-root "${HOME}/Downloads/캡디래그자료" \
  --output outputs/preprocessing-v1
.venv-rag/bin/python -m video_extraction.review.evaluation_prepare \
  --preprocessed outputs/preprocessing-v1 \
  --output outputs/preprocessing-evaluation-v1
```

위 출력 폴더는 이미 생성되어 있습니다. 재실행은 새 폴더 이름을 사용합니다. 이전 대기 이력을 연결하려면 전처리에 `--previous outputs/preprocessing-v1`을 추가합니다. 이전 작업 ID와 근거 내용이 같을 때 최초 대기 시각을 유지합니다.

| 결과 | 내용 |
|---|---|
| `source-registry.json` | 원본 해시, 이전·현재 위치. 이름/크기는 검색 후보이며 SHA256 일치로 연결 |
| `records.jsonl` | 공통 ID, 부모 ID, 출처, 시간/좌표 체계, 원본 응답, 관찰값, 정규화값, 별도 보정 후보 |
| `review-queue.json` | 영상 미추출·보류와 음성 확인 대상을 영역/구간별로 관리. 중복 음성 경고는 같은 구간에 병합 |
| `next-batch.json` | 위험도·대기 시간과 주기적 오래된 항목 선택으로 제한된 다음 검토 묶음을 계획. 실행 기능 없음 |
| `manifest.json` | 입력·출력·구현 해시. 저장 결과와 근거의 변경 여부 확인 |
| 평가 폴더의 `references.blank.json` | 원본으로 정답을 작성하는 빈 양식. 예측은 별도 `predictions.json`에 보관 |
| 평가 폴더의 `원본표본.html` | 선택한 원본 화면과 음성 클립을 예측 없이 확인 |

정규화는 일반 텍스트의 한글 조합형·줄바꿈만 통일합니다. 코드/수식/분류 전 텍스트의 공백·문자, 표의 `null`·빈칸·`0`·`001`·자료형은 보존합니다. 표의 날짜·단위 변환은 열 의미가 선언된 뒤 구현할 대상입니다. `0/o` 세 곳은 원 관찰값과 보류를 유지하고 `0`을 후보로만 저장합니다. 후보는 화면 부모와 세부 블록에 각각 보존하므로 후보 저장 건수와 실제 의심 지점 수는 다릅니다.

`stage`(미추출/추출/검사), `judgment`(미판정/보류), 큐의 `work_status`는 서로 독립입니다. 계산 검사 통과나 좌표 수정은 내용 확정으로 바꾸지 않습니다. AI 중요도는 아직 평가하지 않아 `null`이며, 예산은 계획용 작업량 가중치로 API 호출 수·요금이 아닙니다. 이번 검토 큐는 기존 영상 검토 범위이고 PPT 내 이미지 9개는 레코드에 미추출로 보존하되 별도 분류가 필요합니다. 모든 레코드는 RAG 자동 승인 상태가 아닙니다. 해답 자료의 역할은 자식 레코드까지 유지합니다.

정답 표본은 고정 시드로 기존 키프레임 전체에서 시간순 구간별 화면 24개와 음성 60초씩 6개를 고릅니다. 오류/추출 유무에 따라 표본을 제외하지 않습니다. 화면 본문·코드·표·필기를 직접 기록하고 애매한 문자는 보류로 라벨링합니다. 음성 클립 경계에 걸친 단어는 따로 표시합니다. **수정에 이미 사용한 강의의 개발 표본이며 독립 holdout이 아닙니다.** 미선택 장면의 누락, PPT 정확도, 다른 강의 성능은 이 묶음으로 평가할 수 없습니다. 정답 작성·검토와 CER/WER/영역 누락 평가기는 후속 단계이고 아직 정확도를 산출하지 않습니다.

### 필기 변화와 음성 설명 연결

`ink_context.py`는 기존 공통 전처리 스냅샷에서 원본 프레임·전사·원음을 읽습니다. API 없이 인접 화면을 정렬하고, 같은 장표로 보이는 화면에서 추가된 색 획을 후보로 검출합니다. 지워진 색 획은 개수로 기록하며 새 필기로 취급하지 않습니다. 다음 화면에 색 획이 남아 있는지, 기존 본문 영역과 겹치는지, 같은 시간대 전사에 중요·기억·순서·다음 등의 표현이 있는지를 검토 순서에 반영합니다. 이 점수는 의미 정확도나 모델 신뢰도가 아닙니다.

```sh
# 오프라인 준비. 이미 생성된 출력 폴더는 덮어쓰지 않으므로 재준비할 때는 새 --output을 지정합니다.
python -m video_extraction.ink.context.ink_context prepare --limit 12 \
  --feedback outputs/preprocessing-reference-submissions/merged-393ec6622342de59/references.merged.json
# 아래 run은 사용자가 터미널에서 실행할 때만 Gemini API를 호출합니다.
python -m video_extraction.ink.context.ink_context run --max-api-calls 60 --delay 15
```

현재 준비본은 `outputs/ink-context-v2`이며 편의 실행 파일은 `필기음성_검증.command`입니다. 화면 115개의 인접 쌍 114개에서 383개 후보를 보존하고, 첫 실행은 12개 영역으로 제한했습니다. 미선택 371개는 삭제하지 않습니다. 한 화면에서 최대 2개를 선택하고 잠깐 나타났다 사라지는 표시는 첫 배치에서 제외합니다. 미선택 항목의 후속 배치는 추가 준비가 필요하며 자동 실행되지 않습니다.

각 영역에 필기 전·후·다음 화면, 원본 자르기, 최대 60초 원음, 겹치는 전사 구간과 사용자 검토 메모를 연결합니다. 이전 사용자의 용어·누락 메모는 의미 단서로만 전달하고 정답 전사로 바꾸지 않습니다. 필기가 발생한 시각은 두 키프레임 사이의 구간이며 정확한 획 작성 시각이나 단어 정렬이 아닙니다.

API 1차는 음성 없이 눈에 보이는 필기만 판독합니다. 2차는 실제 원음을 듣고 강조·묶음·진행 관계, 발화 시각·인용, 문맥상 용어 후보·충돌을 따로 기록합니다. 음성만으로 보이지 않는 글자를 확정하거나 `0/o`를 덮어쓰지 않습니다. 화살표의 방향은 화살촉과 끝점의 시각적 근거를 요구하고, 문맥상 "다음"이라는 말만으로 순서를 확정하지 않습니다. 모델이 없는 본문 ID나 음성 범위 밖 시간을 반환하면 채택하지 않고 검토 대상으로 남깁니다.

기본 12영역 × 2단계 = 24회 호출이며 재시도 포함 실행당 최대 60회, 요청 간격 최소 15초입니다. 중단 후 같은 명령은 완료된 영역과 API 캐시를 재사용합니다. 이미 모든 결과가 있으면 API 클라이언트를 만들지 않습니다. 입력·코드·근거 해시가 바뀐 계획은 실행을 막습니다. 결과는 항상 `approved=false`, `applied=false`이며 기존 추출·정답 초안·RAG 데이터를 수정하지 않습니다. API 처리 완료는 중요도·방향·필기 정확도 검증 완료가 아닙니다.

한계: 첫 버전은 색 필기 대상이며 검은색·흰색 필기는 검출하지 않습니다. 영상 첫 화면에 이미 있는 필기, 화면 바깥 좌우 13%와 상단 3.5%·하단 12%의 필기, 누락된 중간 장면은 놓칠 수 있습니다. 색이 추가되는 애니메이션도 후보가 될 수 있고, 원·화살표·글자의 정확한 종류는 원본 재판독이 필요합니다. 아직 필기 재현율·오탐률 개선 수치는 측정하지 않았습니다.

### 다양한 입력을 위한 공통 검사·복구 계층

`recovery.py`는 추출 도구와 별도로 동작하는 항목별 검사·복구 **계획** 계층입니다. `recovery_replay.py`로 기존 Gemini 응답을 오프라인 재처리합니다. 기존 실행과 공통 전처리 스냅샷을 덮어쓰지 않으며, 아직 기존 API 런처의 실행 경로를 교체하지 않습니다.

구조는 `원본 보존 → 도구별 어댑터 → 공통 항목 → 항목별 검사 → 복구 대기열 → 근거 검토 → 승인`입니다. 마지막 승인과 복구 실행기는 후속 구현입니다. 이번 계층의 모든 항목은 `approved_for_rag=false`이며 검사 통과는 내용 정확성의 증명이 아닙니다.

| 구분 | 공통 규칙 | 형식별 확장 |
| --- | --- | --- |
| 원본·이력 | 원본 응답과 알 수 없는 필드 보존, 출처·입력 서명·어댑터 버전 기록 | 원본 자산은 해시로 연결하고 이동 후에도 동일 자료인지 확인 |
| 좌표 | 순서·단위·기준을 명시, 경계 밖 값을 임의로 자르지 않음 | 픽셀·0~1000·비율·EMU, xyxy·yxyx·xywh·이름 있는 필드, 자른 이미지→원본 변환 |
| 시간 | 단위와 원본/클립 기준을 명시 | 초·밀리초·샘플, 샘플레이트와 클립 시작 오프셋을 이용한 변환 |
| 내용 | 원 관찰값·문맥 후보·판정 분리 | 표의 빈칸/0/문자열과 코드 공백은 기존 어댑터 정책 유지 |
| 연결 | 참조 ID의 존재·중복·의존성 검사, 의미는 별도 검토 | 표시→단어, 표시→표시, 음성→화면을 형식별 어댑터가 명시적으로 연결 |
| 미지원 형식 | 삭제하거나 다른 형식으로 강제 변환하지 않고 미처리로 보존 | 회전 좌표·다각형·3D 등은 전용 변환기가 생기기 전 보류 |

영역 경계는 후보를 찾은 범위이지 내용의 유효성 경계가 아닙니다. 경계 밖/걸침은 주변 확장 검토로 분류하고, 뒤집힌 좌표·깨진 ID 등은 오류로 구분합니다. 범위 안의 상자도 픽셀 근거 검토를 대기합니다. 공간적으로 가깝거나 발화 시각이 겹친다는 이유만으로 의미 관계를 확정하지 않습니다.

한 항목이 실패해도 다른 항목을 버리지 않습니다. 실패한 항목에 의존하는 관계만 추가 보류합니다. 좌표 축을 바꾸면 범위에 들어오는 경우에도 **미적용 가설**로만 보존합니다. 원본과 대조하기 전에는 자동 복구로 계산하지 않습니다.

복구 계획은 항목·입력·동작별 고유 키로 중복을 방지합니다. 최대 시도 횟수, 처리 항목 수, API 예산을 받아 초과 시 검토 필요/예산 보류 상태로 남깁니다. 현재 계획기는 시도 이력을 입력받을 뿐 실행·API 호출·음성 정렬·이미지 재추출을 수행하지 않습니다. 향후 실행기는 같은 키에 시도 결과를 기록해야 합니다. 픽셀/OCR 근거 검사와 경계 확장도 아직 계획상의 작업이며 자동 수행된 것으로 표시하지 않습니다.

```sh

python -m video_extraction.review.recovery_replay --output outputs/recovery-replay-v1
```

### 한 영역의 여러 표시·대상 분리와 원본 재검사

`ink_marks.py`는 기존 필기 실험을 보존하고 별도 출력 `outputs/ink-marks-v1`에서 처리합니다. 이전에 여러 강조 중 일부만 설명한 3곳과 단일 원·손글씨·취소선·방향 불명·본문 연결 누락 사례 5곳을 묶은 개발 검토입니다. 미선택 후보 371개는 이번 실행에 포함하지 않습니다.

1. 원본 전후 화면과 영역을 보고 원·밑줄·화살표·글씨를 `marks`, 표시가 가리키는 단어를 `targets`, 강조·묶음·연결을 `relations`로 각각 기록합니다. 기존 본문 ID가 없는 단어에도 원본 좌표에 연결된 임시 ID를 부여합니다. 취소된 필기와 화살촉·끝점은 별도로 보존합니다.
2. 원음과 대조하여 관계별 발화·시각·중요도·충돌을 기록합니다. 보이는 글자와 문맥상 용어 후보를 분리합니다.
3. 음성·문맥 후보 없이 원본과 시각 목록을 다시 검사하여 빠진 표시·대상, 잘못된 연결, 미할당 획을 기록합니다. 누락이나 불확실성이 남으면 보류합니다. 같은 모델의 새 검사이며 독립 정답 검증은 아닙니다.

```sh

python -m video_extraction.ink.recognition.ink_marks prepare
# 사용자가 터미널에서 실행할 API 단계
```

8영역 × 3단계로 정상 완료 시 24회 요청, 재시도 포함 실행당 최대 72회, 요청 시작 간격 최소 15초입니다. 완료된 단계는 서명과 내용 검사를 거쳐 재사용합니다. 입력·코드·근거가 바뀌면 실행을 막고, 잘못된 ID·좌표·시각 또는 불완전한 검사 목록은 검토 대상으로 남깁니다. 결과는 `여러표시_재검토.html`과 `results/`에 저장하며 항상 미승인·미적용 상태입니다.

이 단계는 이미 선택된 색 필기 영역의 해석을 보완합니다. 검은 필기·중간 장면 누락 등의 기존 검출 한계는 그대로이며, 실제 정확도 개선은 실행 결과를 원본과 대조한 뒤 평가해야 합니다. 임시 대상 ID는 개념 분류 ID가 아니며 `concept_ids`는 아직 비어 있습니다.

### 필기 통합 흐름: 화면 선택·OCR·복구·개념 연결

`ink_pipeline.py`가 위 공통 검사 계층을 사용하는 별도 실행 경로입니다. 현재 실행 준비본은 `outputs/ink-pipeline-v2`, 사용자 터미널 런처는 `필기통합_검증.command`입니다. 기존 실험의 입력·코드 해시는 유지합니다. 이번 기본 배치는 이전에 검토한 8개 영역이며 나머지 371개는 대기 상태로 보존합니다.

1. **로컬 준비:** 전·현재·후 화면의 필기 영역과 전체 화면을 비교합니다. 획의 추가·삭제와 큰 영상 차이가 없는 후보 중 선명도 점수가 높은 화면을 고릅니다. 필기 발생 시간 구간과 선택 프레임 시각을 별도로 기록합니다. 이 기준은 가림·잡음·상태 변화에 대한 휴리스틱이며 정확도 보장은 아닙니다.
2. **전처리 비교:** 원본 자르기·주변 확장·대비 보정·노이즈 완화·이진화 버전을 보존합니다. 원본 전경 획 보존율이 낮은 보정본은 제외합니다. 원본과 적격 대비 보정본을 OCR로 비교하며, 차이가 나면 보류합니다. 이진화 결과를 원본 대신 강제 사용하지 않습니다.
3. **독립 OCR:** 로컬의 `PP-OCRv5_mobile_det`와 `korean_PP-OCRv5_mobile_rec`를 명시적 경로로 읽습니다. 다운로드와 네트워크 연결을 차단한 별도 프로세스에서 실행하며, 모델·이미지 해시별 영수증을 저장합니다. 모델이 없거나 인식에 실패하면 미처리/비교 불가로 기록합니다. OCR 불일치는 원문 교정의 근거가 아니라 검토 신호입니다.
4. **음성 우선 처리:** 선택된 모든 영역의 원음을 먼저 분석하고 중요도에 따라 시각 처리 순서를 정합니다. 중요도가 낮은 항목도 처리하며, 원본 필기 목록을 음성 키워드로 삭제하지 않습니다. 시각 판독에는 이 음성 힌트를 넣지 않습니다.
5. **종류별 판독·좌표:** 글씨·수식·본문·코드·기호를 구분합니다. 좌표는 현재 자른 이미지의 `left/top/right/bottom` 0~1000으로 받으며 원본 비율 좌표로 계산 변환합니다. 화살표 끝점·취소 대상·항목 ID를 검사하고, 본문 의미를 단지 가장 가까운 단어에 연결하지 않도록 모델에 요구합니다. 실제 의미 타당성은 후속 원본 검토 대상으로 남습니다.
6. **최대 두 번의 복구:** 최초 검사에서 의심되는 항목은 주변을 확장한 원본으로 재판독합니다. 기존 상자와 화살표 끝점은 확장 좌표로 수학적으로 변환하고, 변경은 지정 항목에만 적용한 후보로 유지합니다. 무관한 정상 항목은 유지합니다. 최종 원본 감사에서 문제가 남으면 한 번 더 복구 후보를 만들되 재감사 전에는 적용하지 않습니다. 무한 반복하지 않습니다.
7. **관계·개념:** 취소선은 취소된 글씨 ID, 화살표는 연결 대상 ID를 참조합니다. 원음 인용·시각·문맥 보정 후보를 분리합니다. 모델이 제시한 개념은 근거 항목 ID가 있고 취소된 필기가 아닐 때 후보 색인에 넣습니다. Python list/tuple/set/dict의 명시적 별칭과 기존 본문·음성의 단어 매칭도 후보로 연결하며, 새로운 개념 라벨에는 별도 후보 ID를 부여합니다. 이 색인은 완성된 온톨로지나 검증된 의미 연결이 아닙니다.

```sh
# 새 출력 준비 및 기존 로컬 OCR 실행. API 호출 없음.
python -m video_extraction.ink.runner.ink_pipeline prepare --output outputs/ink-pipeline-v2
python -m video_extraction.ink.runner.ink_pipeline ocr --output outputs/ink-pipeline-v2
# 아래는 사용자가 터미널에서 수행하는 Gemini 단계
zsh 필기통합_검증.command
# 저장된 결과 보고서만 갱신
python -m video_extraction.ink.runner.ink_pipeline report --output outputs/ink-pipeline-v2
```

정상 8영역 × 4단계 = 32개 요청 단계입니다. 선택적 복구 포함 최대 48단계, 통신·응답 형식 재시도를 합쳐 실행당 최대 72회 호출, 시작 간격 최소 15초입니다. 상한·네트워크 문제로 중단되면 단계 영수증과 API 캐시로 재개합니다. 한 영역의 모델 응답 형식 실패가 반복되면 그 영역을 보류하고 다른 영역을 계속 처리합니다. 입력이나 코드가 바뀌면 기존 계획을 실행하지 않고 새 출력 준비가 필요합니다.

결과는 `필기통합_검토.html`, `results/`, `records.jsonl`, `concept-index.json`에 저장합니다. 공통 항목에는 원본 좌표·원시 응답·오류·검증 대기 상태와 후보 개념 ID를 기록합니다. 원본 자료와 이전 추출 결과, 승인된 정답 자료를 덮어쓰지 않으며 RAG 자동 게시도 하지 않습니다.

**적용 범위:** 현재 후보 검출 범위는 기존 준비 계획을 따릅니다. 전체 영상의 첫 화면 정적 필기, 검정/흰색 필기, 모든 중간 장면을 새로 탐지하는 기능까지 추가된 것은 아닙니다. 수식은 별도 유형으로 시각 모델에 전달하며 Mathpix 등 수식 전용 서비스는 연결하지 않았습니다. 낮은 해상도나 실제로 가려진 글자를 복원했다고 단정하지 않습니다. 다양한 신규 자료와 독립 정답 표본의 성능 평가는 별도 필요합니다.

- 로컬 검사는 전체 선택 프레임의 빈 화면·저해상도·좌표·빈 전사·겹친 동일 문장·불확실 문자·그림 참조를 확인합니다. 영상 전체를 디코딩하여 시간 순서·종료 시점 및 저장 프레임과 원본 영상의 해당 시각을 비교하고, 2fps로 장면 변화 후보를 검사합니다. 0.5초 미만 장면을 모두 찾는다는 의미는 아닙니다.
- 원본 PCM 음성의 0.5초 구간별 에너지·클리핑, 전사 및 단어 시각, 숫자·낮은 신뢰도·반복, 소리가 있지만 전사가 없는 구간을 확인합니다. 에너지는 음성 감지나 단어 정답 판정이 아니며 음악·잡음도 후보에 포함될 수 있습니다. 로컬 ASR을 다시 실행하거나 모델을 다운로드하지 않습니다.
- API 대상은 기본 화면 최대 12개, 음성 최대 12구간, 놓친 장면 변화 최대 6곳입니다. 가능하면 이상 신호가 없는 대조 표본도 포함하고 시간상 분산해 선택합니다. 모든 로컬 지적과 API 범위 밖 구간은 `local-checks.json`에 보존합니다. 아직 내용 중요도에 따라 선택하는 모델 단계는 추가하지 않았습니다.
- Gemini는 원본 이미지/음성을 독립적으로 읽고 원본과 재대조합니다. 화면과 겹치는 음성 전사는 문맥 단서로만 제공하며 불일치는 별도 기록합니다. 기존 추출을 덮어쓰거나 기존 보류를 해제하지 않습니다. 재판독 결과는 `approved=false`, `applied=false`인 후보이며 원본 대조 후 별도 수정 과정이 필요합니다. 영상은 선택된 앞뒤 프레임을 비교하는 경로이고, API에 전체 영상을 업로드하지 않습니다.
- 결과는 `outputs/multimodal-validation/통합검증.html`, `candidates.json`, `summary.json`에 저장합니다. HTML에서 원본 이미지와 해당 음성 클립을 직접 확인할 수 있습니다. 완료된 요청/작업은 재사용하며 입력·증거·코드가 바뀌면 같은 계획으로 실행하지 않습니다. 기본 요청 간격 15초, 실행당 최대 100회이며 실패·예산 초과는 완료로 표시하지 않습니다.
- `completed_with_review`는 **선택된 API 작업의 처리 완료**입니다. 전체 자료의 정확도 인증이나 미선택 구간 검토 완료가 아닙니다.

다른 영상은 먼저 기존 워커의 `--stage local`로 로컬 추출한 작업 폴더를 만들고 아래처럼 별도 검증 폴더를 사용합니다. `--job`을 지정하면 현재 강의의 수정 결과를 자동으로 섞지 않습니다.

```sh
python -m video_extraction.shared.multimodal_validation prepare --job /절대경로/새영상_작업폴더 --output /절대경로/새영상_검증폴더
python -m video_extraction.shared.multimodal_validation run --output /절대경로/새영상_검증폴더
```

새 평가 데이터는 실행 준비에는 필수가 아니지만 정확도 개선 측정에는 필요합니다. 지금 자료는 수정에 사용한 개발 자료입니다. 별도 강의에서 깨끗한 본문/코드, 작은 숫자·수식/표, 필기·빠른 장면 전환, 잡음·무음·전문용어가 포함된 구간을 고르고 원본 텍스트·음성의 정답을 직접 작성해야 합니다. 원본 슬라이드·소스코드가 있으면 함께 확보합니다. 보류율, 누락, 오독, 새로 생긴 오수정을 각각 비교하고, 보류를 정답이나 오답으로 일괄 계산하지 않습니다. `evaluation-template.json`의 정답/오류 수는 미작성 상태로 제공하며 모델 응답으로 정답을 채우지 않습니다.

### API 없이 기존 데이터 계산 검사 재확인

```sh
python -m video_extraction.video.local_recheck
```

기존 통합 검증의 입력·증거 해시를 확인하고 결과를 `outputs/multimodal-checks-v2/계산검사_재확인.html`과 `review.json`에 별도로 저장합니다. 원본 추출, API 응답과 기존 검증 계획은 유지합니다. 영상 전체 디코딩 결과는 해시 확인 후 기존 기록을 재사용하며, 이미지·좌표·전사·PCM 음성 검사는 다시 계산합니다. 저장된 화면 재판독 후보도 별도 검사하되 자동 승인하거나 적용하지 않습니다.

- **확인된 오류**: 잘못된 좌표·참조·시간 등 구조적 위반입니다. 이 수가 0이어도 내용 정확도가 보장되지는 않습니다.
- **단순 경고**: 잘림·중복·낮은 신뢰도 등 원본 대조가 필요한 의심 신호입니다.
- **미처리·판독 미확정**: 추출 없음, 기존 보류, 불확실 문자 등입니다. API 미선택 작업 수와 중복되므로 합산하지 않습니다.

잘림 검사는 테두리의 어두운 픽셀 비율 대신 글자 크기의 연결 획이 경계 안팎을 가로지르는지 두 밝기 기준으로 확인합니다. 긴 직선과 색 표시를 증거에서 제외합니다. 이는 흰 바탕의 어두운 문자에 맞춘 휴리스틱이며 반전 문자·저대비·붙은 획은 놓칠 수 있습니다. 경고 감소 자체를 오탐률이나 정확도 개선 수치로 해석하지 않습니다. 유지·해제·신규 경고에서 뽑은 원본 표본을 보고서에 함께 제공합니다.

### 잘림 62건 원본 직접 대조 반영

`outputs/cutoff-source-review`에는 62건의 원본·수정 후 이미지 대조와 개별 판정을 보존합니다. 20개 화면에서 좌표 53곳을 보정하고 오탐 9건을 정리했습니다. 전사 내용, 다른 필드, 기존 보류와 API 응답은 변경하지 않았습니다. 수정된 `vision/*/result.json`은 별도 파생 결과이며, 이후 기본 작업의 새 통합 검증 계획에서는 이 결과를 가장 먼저 읽습니다. 다른 영상의 `--job`에는 자동 적용하지 않습니다.

좌표·텍스트·종류를 포함한 대상 블록과 원본 이미지 해시가 모두 같을 때만 직접 대조 판정을 재사용합니다. 겹친 본문·아이콘 때문에 남는 계산 신호 13건도 지우지 않고 `reviewed_cutoff_findings`에 근거와 함께 보존합니다. 53건 수정 후에도 신호가 남는 필기 4건과 기존 오탐 9건이며, 내용 전체의 정확도 승인을 의미하지 않습니다.

```sh
# 저장된 직접 대조 판정과 기존 데이터로만 재검사합니다. API를 호출하지 않습니다.
python -m video_extraction.video.local_recheck --reviewed-results outputs/cutoff-source-review --output outputs/multimodal-checks-reviewed
```

직접 대조 판정 없이 과거 계산 결과를 재현하려면 `--reviewed-results`를 생략합니다. `source_coordinate_review`는 저장된 `decisions.json`의 판정을 적용하는 도구이며 새 이미지의 판독을 자동으로 수행하지 않습니다. 새 검토 결과는 `outputs/multimodal-checks-reviewed`에 저장하고 기존 `multimodal-checks-v2`와 API 검증 폴더는 유지합니다.

### 중복 추가 차단 25건 직접 검토

`outputs/annotation-duplicate-review`에 원본 대조 판정, 7개 화면의 필기 영역 25개, 이전 좌표 수정 62건의 판정이 함께 반영된 파생 결과를 저장합니다. 24건은 별도 필기 설명이 없던 누락이며, 화면 8의 1건은 포괄적 요약에만 있던 손글씨를 분리한 것입니다. 이 손글씨는 정확한 전사를 확정하지 못해 `[ILLEGIBLE]`과 개별 보류를 유지합니다. 포괄적 요약의 미확인 표기 `순서 제거`도 제거했습니다. 완전히 중복된 필기로 확인된 항목은 없습니다.

인쇄된 본문을 필기 전사에 복사하지 않고, 동그라미·밑줄·연결선은 `visuals.description`, 직접 읽을 수 있는 필기 숫자는 `literal_text`, 연결된 본문은 `related_block_ids`로 기록합니다. 기존 차단 기록 25개는 `annotation_duplicate_review.archived_holds`에 보존하고 다른 보류는 유지합니다. 이후 기본 작업의 새 통합 검증 계획에서는 이 파생 결과를 좌표 수정 결과보다 먼저 읽습니다.

기존 단일 레이어 추출기 두 경로의 중복 방지 조건도 수정했습니다. **종류와 내용(앞뒤 공백 제외)이 같고 위치도 겹칠 때만** 중복 추가를 막습니다. 본문과 필기가 겹치거나 같은 문구가 다른 위치에 있다는 이유만으로 버리지 않습니다. 이는 의미가 같은 다른 표현까지 자동 판정하는 기능은 아닙니다.

```sh
# 저장된 수정 결과를 사용하는 로컬 재검사. API 호출 없음.
python -m video_extraction.video.local_recheck --reviewed-results outputs/annotation-duplicate-review --output outputs/multimodal-checks-annotations
python -m video_extraction.review.pending_reconciliation --source outputs/multimodal-checks-annotations/review.json --output outputs/pending-reconciliation-annotations/review.json
```

재검사 결과는 경고 80건, 미처리·미확정 기록 132건이며, 반복 지적을 묶으면 관리 항목 110개입니다. 이 중 검토 한도 요약 9건에는 미검토 영역 45곳이 들어 있습니다. 이번 작업은 그 영역들의 내용 검토를 완료한 것이 아닙니다. 기존 API 결과와 이전 검토 보고서는 보존합니다.

### 그림·필기 분리 수정본 재검증

`그림필기_재검증.command`는 `video_extraction.video.layer_validation run`을 실행합니다. 기존 최적화 비교 실행과 별개의 v2 검증 경로이며, 이전 32개 결과와 API 캐시를 덮어쓰지 않습니다. 문제 화면 4·5·6·16·21·22·29·30·31·32번을 새로 처리하고 `outputs/vision-layer-validation/그림필기_재검증.html`에 비교 결과를 저장합니다.

- `final_blocks`에는 인쇄된 본문·코드·표를, `visuals`에는 그림 설명·필기 글자·좌표·연결된 본문 ID를 저장합니다. 글자가 없는 그림의 `literal_text`는 비어 있어도 유효합니다. 그림 설명은 모델 해석이며 원문 전사가 아닙니다.
- 본문과 같은 위치에 있는 원·밑줄은 별도 레이어이므로 본문 중복으로 삭제하지 않습니다. 본문의 종류·텍스트가 완전히 같고 좌표가 겹치는 경우에만 근거를 남겨 병합하며, 불확실성과 참조 ID를 보존합니다.
- 같은 타깃의 여러 지적을 하나의 전체 영역 검토로 병합하고 지적 내용을 전부 유지합니다. 잘린 주변 제목이 섞이지 않도록 원본 전체 화면과 대상 범위를 함께 제시합니다.
- 본문과 그림 검토 예산은 각각 8개입니다. 상한 밖 영역은 `review-plan.json`과 결과의 `deferred_regions`에 개별 저장되고 검토 필요 상태가 유지됩니다. 재개는 완료된 요청의 캐시를 재사용하며, 상한 밖 영역을 자동으로 승인하지 않습니다.
- 기존 24개 문구 검사 중 선택 화면에 해당하는 검사와 29번 표의 `(Dictionary)` 셀 검사를 수행합니다. 그림·필기 내용의 정확도는 결과를 원본과 대조해야 하며, 단위 테스트만으로 입증되지 않습니다.
- 기본 경로의 전체 영상 실행은 종전 방식입니다. 이 수정본은 우선 별도 검증에만 적용하며 전체 115개 화면에 자동 확대하지 않습니다.

### 기존 영상 실행

그림·필기 재검증이 완료된 뒤에는 `미검증_후속검토.command`로 후속 검토를 실행할 수 있습니다. `video_extraction.video.layer_followup prepare`는 API 없이 계획만 만들고, `run`만 API를 사용합니다. 현재 계획은 기존 결과의 `deferred_regions`에 남은 그림·필기 54개와 30·31·32번의 기호 9개입니다. 전체 추출·전체 감사는 반복하지 않으며 이미 검증된 영역은 재사용합니다.

- 결과는 `outputs/vision-layer-followup/미검증_후속검토.html`과 화면별 `vision/*/result.json`에 따로 저장합니다. 원본 결과·이미지·코드 해시가 바뀌면 다른 결과와 섞지 않고 중단합니다.
- 그림·필기는 최대 3개씩 재판독하고 원본 대조합니다. 배치 완료 기록이 있으면 재호출하지 않습니다. 배치 중간에 중단되어도 Gemini 요청 캐시를 재사용합니다.
- 기호는 프레임마다 `name = student[...]`의 `0/o`, 코드의 `print` 문자열 내 구분선, 출력 상자의 구분선을 각각 확인합니다. 이전 값이나 다른 판독을 제시하지 않은 두 번의 판독과 추가 원본 대조가 모두 통과해야 해당 문자 구간만 병합합니다. 같은 모델의 합의는 독립적인 정답 인증이 아닙니다.
- 애매한 문자·하이픈 개수는 이전 값을 유지하고 보류합니다. 일부 기호가 확인됐다고 기존 코드 전체의 보류를 자동으로 없애지 않습니다. 모든 대상의 처리가 끝나도 보류가 남으면 `complete_with_review`입니다.

이미 준비된 환경에서는 프로젝트 루트의 `영상추출_실행.command`를 실행하면 기존 4주차 영상 처리를 시작하거나 이어갑니다. 키는 프로젝트 `.env`의 `GEMINI_API_KEY`에서만 읽고 출력하지 않습니다.

Finder에서 `영상추출_실행.command`를 더블클릭하거나 Mac의 터미널 앱에서 해당 파일의 절대 경로를 실행합니다. 파일 내용을 복사할 필요는 없습니다. 런처는 다음 순서로 동작합니다.

1. 작은 텍스트 요청과 합성 이미지 요청으로 연결·키·모델 접근·실제 추출용 JSON 응답 형식을 확인합니다. 텍스트 시험만 성공한 상태를 전체 준비 완료로 표시하지 않습니다. 지난번 성공 캐시는 이 점검에 사용하지 않습니다. 합성 이미지 결과는 강의 추출 데이터나 정확도 측정에 넣지 않습니다.
2. 점검을 통과하면 기존 작업을 이어서 처리합니다. 완료한 음성 전사와 화면 PNG를 재사용합니다.
3. 터미널 출력을 `outputs/video-extraction/logs/`에 저장합니다. macOS에서는 실행 중 유휴 절전을 억제합니다. 작업 중에는 터미널 창을 닫지 않습니다.
4. 실패하면 원인을 표시하고 멈춥니다. 키 값을 로그에 출력하지 않으며, 키·결제·네트워크 설정을 자동으로 바꾸지 않습니다.

연결 진단 결과는 `outputs/video-extraction/연결진단.json`과 `연결진단.txt`에 저장됩니다. 진단만 하려면 동일 Python 환경에서 `python -m video_extraction.shared.diagnose --check-vision`을 실행합니다. 추출 형식 요청에서 400이 나면 단순 이미지 요청을 한 번 더 비교하여 이미지 입력 문제인지 스키마 조합 문제인지 구분할 근거를 남깁니다.

| 오류 | 의미와 다음 조치 |
|---|---|
| `gemini_dns_failed` | API 서버 주소를 찾지 못한 상태입니다. 현재 에이전트 환경에서는 이 오류가 확인되었습니다. 권한이 허용된 Mac 일반 터미널에서 실행하고, 그곳에서도 같으면 해당 네트워크의 연결·DNS·프록시를 확인합니다. |
| `gemini_tls_certificate_failed` | Python 인증서 설정을 확인합니다. TLS 검증을 끄지 않습니다. |
| `gemini_authentication_failed` | Google AI Studio에서 키 상태를 확인하고 필요한 경우 `.env`를 갱신합니다. |
| `gemini_http_403` | 키의 API 사용 권한·프로젝트 제한을 확인합니다. |
| `gemini_http_400` / `404` | 진단 파일의 Google 메시지로 요청 설정 또는 모델 접근 문제를 구분합니다. |
| `gemini_http_429` | 요청·토큰 속도 또는 할당량 제한입니다. Google AI Studio에서 제한 종류와 초기화 시점을 확인합니다. |
| `gemini_daily_quota_exceeded` | 일일 한도 오류로 확인된 경우입니다. 자동 반복 호출하지 않고, 초기화 후 재실행합니다. |

DNS 실패만으로 API 키 오류나 무료 한도 초과라고 판단할 수 없습니다. 연결 점검 성공도 전체 작업의 할당량이나 추출 정확도를 보장하지 않습니다. 오류 원인은 [Google 공식 오류 문서](https://ai.google.dev/gemini-api/docs/api-errors)를 기준으로 구분합니다.

일반적인 새 환경의 설치:

```sh
python3 -m venv .venv-video
.venv-video/bin/python -m pip install -r video_extraction/requirements.txt
.venv-video/bin/python -m video_extraction '/절대경로/강의.mp4' --normalize-audio --allow-model-download
```

로컬 처리만 실행:

```sh
python -m video_extraction '/절대경로/강의.mp4' --stage local --normalize-audio
```

같은 영상·설정으로 이어서 API 단계 실행:

```sh
python -m video_extraction '/절대경로/강의.mp4' --stage all --normalize-audio --max-api-calls 700
```

`--allow-model-download`를 처음 사용했다면 다음에도 동일한 설정으로 실행해야 같은 작업 폴더를 사용합니다. 기본값은 모델을 이미 받은 로컬 환경용 `local_files_only=True`입니다.

종료 코드: `0` 요청 단계 완료, `2` API 연결/키/할당량/호출 예산 때문에 대기, `1` 실패, `130` 중단. `--stage local`의 종료 코드 0은 영상 전체 추출 완료가 아니라 로컬 단계 완료입니다.

## 처리 순서

1. 원본 영상 SHA-256과 처리 설정으로 작업 ID를 만듭니다. 동일 작업의 중복 워커는 파일 잠금으로 방지합니다.
2. 원본 음성을 16 kHz mono PCM WAV로 보존합니다. `--normalize-audio`는 별도 파일에 FFmpeg loudnorm을 적용합니다. 무음의 무한대 측정값은 정규화를 건너뜁니다. 무음 제거·시간 압축은 하지 않습니다.
3. 영상 전체를 순차 디코딩하고 기본 2 fps로 변화량을 검사합니다. 큰 변화 또는 최대 20초 간격으로 원본 해상도 PNG를 저장합니다. 프레임 번호가 아닌 디코딩 PTS를 사용합니다.
4. faster-whisper turbo / 한국어 / beam 5 / CPU int8으로 전사합니다. 180초 단위 작업에 양쪽 3초 문맥을 더하고, 구간 중간점 기준으로 중복 귀속을 줄입니다. 완료한 음성 조각은 재실행 시 재사용합니다. 조각 경계·낮은 logprob·비음성 가능성·반복은 검토 대상으로 표시합니다.
5. Gemini가 화면의 텍스트·코드·표·수식·그림 라벨을 구조화합니다. 원문 오류까지 그대로 기록하도록 지시합니다.
6. 전체 화면과 최초 추출문을 대조합니다. 누락·깨짐 후보와 함께 코드·수식·표·도식은 정책상 추가 재판독 대상이 됩니다.
7. 의심 영역을 원본 픽셀에서 잘라 독립 판독합니다. 어려운 경우 대비·적응형 임계값 이미지를 보조로 제공합니다. 보조 이미지에서만 보이는 글자는 수정 근거로 인정하지 않습니다.
8. 원본 전체 화면과 원본 crop으로 수정 후보를 검증합니다. 불확실·충돌·중복 대상·영역 상한 초과는 보류합니다. 이전 결과는 변경 이력과 함께 보존합니다.
9. 표시된 음성 구간을 원본 오디오로 재판독합니다. 바뀐 단어에는 기존 Whisper 단어 타임스탬프를 재사용하지 않습니다. 기존 단어 정보는 별도 필드로 보존합니다.
10. 화면과 음성을 시간 겹침으로 연결합니다. 내용의 동일성을 확정하거나 양쪽을 하나의 문장으로 재작성하지 않습니다.

## 상한과 재개

- 기본 실행당 API 요청 상한은 60회입니다. 런처는 기존 전체 영상용으로 700회를 설정합니다. 재시도도 상한에 포함됩니다. 별도 연결 점검은 정상 시 2회, 오류 분리와 재시도를 포함해 최대 9회의 요청입니다. 모델 API가 유료 계정에 연결되어 있으면 요금이 발생할 수 있으며 코드가 결제 계층을 바꾸지는 않습니다.
- 요청 간 기본 간격은 15초입니다. 408/429/5xx는 최대 2회 추가 시도합니다. 일일 한도 또는 60초를 넘는 `Retry-After`라면 기다림을 짧게 줄여 재요청하지 않고 대기 상태로 종료합니다. 연결 불가와 인증 오류도 즉시 대기 상태로 종료합니다.
- 화면당 최대 6개 영역을 재판독합니다. 초과분을 조용히 버리지 않고 보류 목록에 기록합니다. `--max-regions`로 조절할 수 있습니다.
- `--max-audio-reviews` 기본값 20은 새로 검토할 음성 구간 상한입니다. 기존 결과는 재사용합니다. 남은 구간은 보류로 남습니다.
- 호출 캐시는 이미지·오디오 해시, 프롬프트, 스키마, 모델로 구분합니다. 영상이나 처리 설정이 달라지면 다른 작업 폴더를 사용합니다.
- 자료의 영상 화면과 업로드 PPT를 대조하는 기능은 아직 이 패키지에 포함하지 않았습니다. 현재 영상에 대응 PPT가 없기 때문에 영상 내부 증거만 사용합니다.
- 화면 간격은 추정 구간입니다. 0.5초보다 짧게 나타나는 내용, 아주 작은 필기·커서와 비슷한 변화는 놓칠 수 있습니다. 필요한 영상에서는 `--scan-fps`와 변화 임계값을 조정하고 표본 평가를 해야 합니다.

## 테스트

### 화면 반복 검토·묶음 요청 비교

`vision_optimized.py`는 검증 이력·원문·픽셀·새 전체 대조를 모두 통과한 영역의 반복 검토를 생략하고, 최대 3개 영역을 한 번에 읽고 검증합니다. 픽셀까지 완전히 같은 프레임만 전체 결과를 재사용하며, 이전의 보류 항목도 유지합니다. 같은 슬라이드처럼 보인다는 이유로 필기나 코드 변경이 있는 화면을 버리지는 않습니다. 8 이하 픽셀 차이는 압축 잡음 후보로 취급하지만, 이것만으로 정확성을 보장할 수 없어 새 추출과 전체 대조를 유지합니다.

기존 완료 화면 32개와 음성 문맥을 `outputs/vision-optimization/inputs`에 고정했습니다. 원본 작업과 기존 결과는 수정하지 않습니다. 기존 `영상추출_실행.command`의 경로는 유지하며, 새 방식은 품질 비교가 끝날 때까지 별도 비교 런처로 실행합니다.

```sh
python -m video_extraction.video.vision_benchmark local
python -m video_extraction.video.vision_benchmark run
python -m video_extraction.video.vision_benchmark report
python -m unittest video_extraction.tests.tests video_extraction.tests.test_speech_rules video_extraction.tests.test_vision_optimized -v
```

- `local`: 기존 정상 API 캐시를 읽기 전용으로 재현하고 호출 계획을 계산합니다. 로컬 캐시 읽기 시간을 Gemini 추론 시간으로 보고하지 않습니다.
- `run`: 독립 API 캐시에서 실제 최적화 요청을 수행합니다. 실행당 최대 300회, 기본 요청 시작 간격 15초이며 요청 재시도도 상한에 포함됩니다. 이는 프로젝트의 설정이지 Google의 고정 요금제 한도라는 뜻이 아닙니다.
- `report`: 원본·기존 결과·새 결과·내용 차이·제한된 문구 포함 검사를 표시합니다. 문구 24개는 전체 정답 전사본이 아니므로 정확도 백분율로 해석하지 않습니다.
- macOS에서는 `화면최적화_비교실행.command`를 실행합니다. API 키는 기존 `.env`에서 읽습니다. 중단 시 같은 파일을 실행하면 성공한 요청과 완료 프레임을 재사용합니다.
- 현재 워커의 잠금은 작업 폴더 단위입니다. 기존 전체 추출과 비교 추출을 동시에 돌리면 계정의 API 한도를 공유하므로 순차 실행합니다.
- `연결상태_확인.command`는 같은 Python에서 일반 OS 주소 조회와 HTTPS 응답을 검사합니다. 키·모델 생성·DNS 설정 변경 없이 검사하며, 제한된 에이전트 실행 환경과 사용자의 일반 터미널 결과는 따로 저장합니다.
- `auto_repaired`는 실제 오류 수정의 증명이 아닙니다. 새 응답의 잘못된 추가·기호 변경·필기 누락을 원본과 확인해야 합니다. 아직 검증되지 않은 새 추출을 RAG에 게시하지 않습니다.

### 발음·문맥·용어 보완 실험

`speech_rules.py`와 `speech_experiment.py`는 실행 중인 영상 워커와 분리된 실험입니다. 기존 `asr.json`과 원본 오디오는 읽기만 합니다. 실제 RAG나 기존 전사에 자동 반영하지 않습니다.

- 강의 텍스트에서 확인되는 용어에 중요도 1~3을 부여합니다. 한글 자모 거리와 **단일 받침 연음**으로 후보를 만들고, 주변 발언의 용어로 점수를 매깁니다. 두음법칙이나 한국어 발음 규칙 전체를 구현한 것은 아닙니다.
- 점수는 자체 후보 순위이며 모델 확률이 아닙니다. `hotwords`에는 숫자 가중치를 직접 전달하지 않습니다.
- 원래 올바르게 인식된 용어 어간과 복합 조사는 보존합니다. 숫자·부정·연산자 변경을 자동 적용하지 않습니다.
- 같은 음성을 turbo 무힌트, turbo 문맥·용어 힌트, small 무힌트로 재전사합니다. 세 전사가 해당 단어의 시각에서 **조사를 포함한 전체 수정 표기**를 지지할 때만 최소 범위를 수정 후보로 저장합니다. 불일치는 보류합니다.
- 최초 비교 표본은 새 출력을 보기 전에 고정합니다. `speech_bounded.py`는 넓은 힌트로 반복이 발생한 뒤 같은 표본에서 힌트 양을 줄여 비교하는 개발 실험입니다. 미사용 평가 자료가 아닙니다.

### 구분선 픽셀 검토 (API 호출 없음)

```sh
python -m video_extraction.video.separator_pixels
python -m video_extraction.video.layer_followup report
```

완료된 `outputs/vision-layer-followup`의 화면 30·31·32에서 코드/출력 구분선 6곳을 검사합니다. 원본 픽셀의 어두운 가로 선 조각을 밝기 기준 5개로 세고 개수·위치·폭·간격·잘림을 확인합니다. 계산 코드에 16이라는 정답을 고정하지 않습니다. 불안정한 결과는 보류하며 모델의 판독 일치만으로 승인하지 않습니다. ROI는 직접 검토한 세 이미지의 해시와 묶여 있으므로 새로운 화면에는 영역을 먼저 지정하고 확인해야 합니다. 임의의 문서에 적용하는 범용 OCR은 아닙니다.

`pixel-review.json`에 원본 해시, 픽셀 좌표, 밝기별 선 조각 좌표와 계산 결과를 저장합니다. 기존 API receipts와 원본 추출은 유지하고, 병합된 JSON 및 HTML에는 픽셀 판정을 적용합니다. 첫 적용 전 결과는 `before-pixel-review/`에 보존합니다. 보고서를 다시 생성해도 픽셀 판정이 유지됩니다. 과거 API 실행의 코드 해시는 변경하지 않으며, `report`는 저장된 계획과 원본 해시를 검증하여 오프라인으로 재생성합니다. 수정된 코드로 API 작업을 새로 실행하려면 별도 출력 폴더가 필요합니다.

이 검토는 `0/o`나 전체 코드 영역 보류를 해제하지 않습니다. 기존 `verified` 모델 판정도 직접 검토에서 불확실성이 확인될 수 있습니다.

API 기준 문서: [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output), [이미지 이해](https://ai.google.dev/gemini-api/docs/image-understanding), [Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash). 실제 연결·할당량·모델 접근 권한은 실행 계정으로 확인해야 합니다.
