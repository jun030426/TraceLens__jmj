# 필기 수정 후보의 원본 재검사와 반영

## 총 호출 한도 내 자동 이어 실행 (`ink_auto_continue`)

`미처리필기_개선이어검증.command`는 이제 `ink_auto_continue run`을 실행한다.
내부 묶음은 8개지만 한 묶음이 끝나면 다음 묶음을 자동 선택한다. 전체 실행에서
Gemini 클라이언트 하나를 공유하므로 재시도까지 합친 실제 API 호출 60회 한도가
묶음 전환 시 초기화되지 않는다. 요청 시작 간격은 기존 15초다.

호출 한도에 도달하면 `stop_reason=request_budget_exhausted`로 정상 중단한다.
API 결과가 저장되지 않은 항목을 완료로 만들지 않는다. 같은 명령을 다시 실행하면
기존 완료 결과를 건너뛰고 저장된 단계부터 재개하며, **새 실행에는 새 60회 한도**가
주어진다. Ctrl+C나 통신 오류도 완료 단계 캐시를 보존한다. 전체 처리가 끝난 경우의
`all_tasks_processed`는 처리 시도 완료이며 보류·관리자 검토 해소를 뜻하지 않는다.

한도 소진 후 다음 묶음의 불필요한 OCR 준비는 하지 않는다. `.run.lock`은 기존
단일 묶음 실행기와 공유한다. `run-state.json` 및 `runs/auto-*.json`에는 실행 전체
호출 통계, 방문한 묶음, 이번 실행 완료 ID, 현재 항목과 중단 이유를 저장한다.

추출 계획·코드·캐시의 서명은 변경하지 않고, 별도의 `execution-policy.json`으로
자동 실행기 버전을 고정한다. `prepare`는 로컬 준비만 하며 API를 생성하지 않는다.

## 개선 로직 이어 실행 (`ink_continue_v2`)

남은 359개 감지 필기 영역은 `미처리필기_개선이어검증.command`로 실행한다.
기존 이어 실행 16개는 제외하고, 직접 검토 버전의 관리자 9개와 기호 의미 미확정
1개는 별도 대기열로 유지한다. 기존 결과를 덮어쓰지 않는다.

처리는 새 원본 추출 → 기존 ASR 맥락 연결 → 원본 검사(누락 ID 1회 보완) →
필요한 항목만 수정 → 수정 후보 원본 재검사(누락 ID 1회 보완) 순서다.
빈 추출도 독립적인 원본 누락 검사를 거친다. 범위 가장자리에 걸린 필수 항목은
원본 전체 좌표로 변환해 복구하며 OCR 양쪽 결과와 검사 범위도 함께 변환한다.

OCR 문자 차이와 주변 짝 기호 진단을 수정 요청에 전달한다. 문장부호 차이가 있는
항목의 원본 연결 성분에서 콜론·괄호 쌍·밑줄 모양 후보를 찾고 국소 픽셀을 검사한다.
문자열 길이로 문자 좌표를 추정하지 않는다. 위치 후보는 최대 12개, 검사는 최대
48회로 제한한다. 후보 모양이 있다는 것만으로 어느 글자인지 확정하거나 OCR
충돌을 해제하지 않는다. 확인되지 않은 새 사례에는 기존 5개 직접 검토 승인을
재사용하지 않는다. 판독 충돌이 남으면 근거와 함께 검토 대상으로 저장한다.

한 번에 8개, 영역당 최대 7개 논리 호출이다. 요청 간격 15초, 통신/형식 재시도 포함
실제 API 상한 60회다. 기본 실행 파일은 위 자동 실행기를 사용해 한도 안에서
다음 묶음까지 이어간다. `ink_continue_v2 run`을 직접 호출한 경우만 한 묶음 후 멈춘다.
OCR와 미디어 준비만 실행하는 `local` 모드는 API 클라이언트를 생성하지 않는다.

출력은 `outputs/ink-continuation-v2`이다. `prepared/`에는 마지막 좌표계로 정렬된
검토 패키지, `results/`에는 추출·수정·검사 및 문자 차이/픽셀 후보 진단,
`pending.jsonl`에는 보류와 기존 의미 미확정, `administrator-review.jsonl`에는
기존 및 신규 관리자 항목이 들어간다. `records.jsonl`은 이번 새 실행의 사용 가능
기록만 포함하며 과거 전체 데이터를 합친 파일이 아니다.

## 문자 차이·원본 직접 검토 반영 (`ink_discrepancy`)

`ink_recovery`에서 남은 5개 항목은 `outputs/ink-source-review-v1`에 별도 버전으로
반영한다. API를 호출하지 않는 후처리 단계다. 기존 API 결과·정답지·원본은 수정하지 않는다.

`character_differences`는 원문을 바꾸지 않고 문자 단위 차이와 위치를 반환한다.
문장부호 모양 차이와 단어·숫자·대소문자 차이를 구분한다. 문장부호 차이라는 이유만으로
통과하거나 `O→()`, `.→:`를 일괄 치환하지 않는다. OCR의 문자열 단위 상자만으로
문자 좌표를 임의 추정하지 않으며, 확인된 원본 국소 좌표를 `pixel_probe`에 전달한다.
콜론의 두 점, 떨어진 괄호 획, 기준선 아래 가로획을 원본 픽셀로 측정하고 붉은 필기의
픽셀 수를 별도로 남긴다. 픽셀 특징은 판독의 보조 근거이며 기호의 정답을 보증하지 않는다.
국소 좌표가 없거나 획이 불분명하면 원본 검토 대기로 유지한다.

`symbol_context`는 영역 주변에서 같은 높이의 짝 필기 성분을 찾는다. 기호 후보를
제안할 뿐 정확한 유니코드나 리스트·튜플 등의 의미를 자동 확정하지 않는다.
화면 7은 사용자가 승인한 직접 검토 결과에 따라 `kind=bracket`, `text=""`로 저장한다.
원래 `ㄷ` 관찰값은 별도로 보존하고 `exact_symbol=null`, `meaning=null`,
`usable_for_semantic_assertion=false`로 기록한다. 시각 분류 확인과 의미 확정은 별개다.

`refresh_relations`는 관계 자체 검사와 대상의 사용 가능 상태를 분리한다.
관계 자체가 정상이고 모든 대상이 해결됐을 때만 종속 보류를 해제한다. 방향·좌표·취소
등 다른 오류가 있는 관계는 계속 보류한다.

확인된 4개 해제에는 `fixtures/ink_discrepancy/source-reviews.json`의 개별 검토 기록을
사용한다. 사용자의 반영 요청, 직접 관찰 근거, 원본 해시, 결과·항목 서명을 묶어
다른 이미지나 바뀐 후보에는 적용하지 못하게 한다. 이 기록은 평가용 정답지가 아니며,
향후 유사한 글자가 나왔다는 이유로 자동 승인하지 않는다. 새로운 미확인 사례는
차이 분류와 픽셀·주변 근거를 수집한 뒤 추가 원본 검토 대상으로 남는다.

재현 명령(새 출력 폴더 지정 필요):
`python -m video_extraction.ink.correction.ink_discrepancy --receipts video_extraction/fixtures/ink_discrepancy/source-reviews.json --output <새 폴더>`

`records.jsonl`은 복구 9개 영역의 결과를 포함한다. 일반 보류는 0개지만 화면 7의
기호 의미 미확정 1개와 기존 관리자 검토 9개는 유지한다. 기존 이어 실행 명령의
새 묶음에 이 직접 검토 기록을 재사용하지 않는다.

## 반복 오류 복구 (`ink_recovery`, 2026-10-28)

현재 실행 진입점은 `필기반복오류_복구.command`다. 이전 이어 실행의 실패 영역을
`outputs/ink-recovery-v1`에 별도 복구하며, 기존 16개 실행 결과와 대기 359개는
바꾸지 않는다. 이번 복구 결과를 확인하기 전에는 이전 이어 실행 명령으로 새
묶음을 진행하지 않는다. 기존 `ink_policy`를 변경하면 저장된 계획의 코드 해시가
깨지므로, 개선 로직은 `ink_recovery`에 추가했다. 이후 새 계획에서도 이 검사
경로를 사용할 수 있으며 기존 명령에 자동 소급 적용된 것은 아니다.

- 단순 강조의 `observed` 방향은 관계와 표시 모두 기존 원본 검사에서 단순 강조로
  확인됐을 때만 `not_applicable`로 정규화한다. 화살표·진행 순서·연결·취소·미확정
  관계는 그대로 검사한다. 원래 모델 응답과 정규화 이유를 함께 보존한다.
- 검사 응답의 누락·중복 ID만 최대 한 번 보완 요청한다. 정상 ID의 검사 결과는
  유지하며, 끝내 누락된 ID에는 불확실 상태를 부여한다. 다른 ID까지 일괄 실패로
  만들거나 임의로 검사 통과 판정을 채우지 않는다.
- 경계에 걸린 필수 내용은 같은 시점의 원본 전체 프레임 좌표로 전환한다.
  후보·기존 값·화살표 끝점·양쪽 OCR 결과·실제 OCR 검사 범위를 함께 변환한다.
  OCR가 안 본 추가 영역은 검사됐다고 주장하지 않는다. 원래 핵심 영역은 유지한다.
- 기존 실패 ID만 수정 대상으로 지정하고, 누락 영역 복구 외에 새 항목을 허용하지
  않는다. 수정은 한 번, 이후 후보를 원본과 새로 검사한다. 응답 보완까지 합쳐
  영역당 최대 5개 논리 호출이며 통신 재시도 포함 전체 60회 상한으로 재개 가능하다.

`prepare`는 API 없이 저장된 후보·검사 결과를 재생한다. 순수 형식 오류가 해소된
영역은 새 버전 결과로 저장하고, 아직 남은 영역만 사용자 터미널 실행 대상으로
준비한다. `local-replay/`는 로컬 재생 진단, `results/`는 반영된 새 버전,
`changes.jsonl`은 형식 정규화와 내용/좌표 수정을 구분한 변경 이력이다.
`records.jsonl`은 이번 복구 범위만 포함하며 전체 서비스 데이터가 아니다.
관리자 대기열은 이전 항목을 함께 유지한다. 보류 감소를 정확도 상승률로 해석하지 않는다.

실패한 두 배치의 9개 영역을 `fixtures/ink_recovery/`에 회귀 사례로 고정했다.
테스트는 실제 저장 결과와 원본 로컬 이미지를 사용하며 API는 가짜 클라이언트로
대체한다. 이는 코드의 분류·좌표·재개 동작 검증이며 실제 새 모델 판독 결과를
예측하거나 정답지로 승인하는 검사가 아니다.

`ink_recheck`는 `ink_pipeline`의 후속 단계다. 기존 실행 폴더와 원본을
수정하지 않고 `outputs/ink-recheck-v1`에 새 결과 버전을 만든다. 정답지나
사용자 평가 입력을 판독 근거로 사용하지 않는다.

## 처리 규칙

1. 기존 실행에서 생성한 마지막 수정 후보를 불러온다. 해당 후보가 없으면
   마지막 추출 결과를 사용한다. 입력 파일과 원본의 해시를 고정한다.
2. 선택된 원본 프레임에서 더 넓은 영역을 잘라 경계 복구에 사용한다.
   모든 상자와 화살표 점을 새 좌표계로 변환하고, 원래 검토 영역은 유지한다.
   다른 시점의 새 필기를 합성하거나 복사하지 않는다.
3. 원래 영역과 교차하는 항목 및 직접 연결된 대상만 필수 검사한다.
   주변 참고 내용과 바깥쪽 누락 후보는 보존하되 핵심 영역의 완전성과 분리한다.
4. OCR 미설치/미판독/미검사 영역/부분 단어 겹침은 미처리 상태로 구분한다.
   같은 영역의 신뢰도 있는 OCR 텍스트가 다를 때만 충돌로 보류한다.
   전처리 차이는 해당 항목의 비교 가능한 OCR 영역에서만 경고로 기록한다.
5. 원본 crop과 전체 프레임으로 내용, 좌표, 의미·관계를 새로 검사한다.
   필요하면 요청된 ID만 한 차례 수정하고 수정된 내용 전체를 다시 검사한다.
   마지막 검사 실패·중단·ID 누락·잘못된 좌표는 반영을 허용하지 않는다.
6. 원본 검사와 계산 검사를 통과한 개별 항목만 새 버전에 반영한다.
   관계는 모든 참조 항목이 통과해야 한다. 정상 형제 항목은 독립적으로 반영한다.
   `0/o`, 불분명한 취소선, 읽을 수 없는 필기는 확정 대신 보류할 수 있다.

## 실행

로컬 준비: `python -m video_extraction.ink.correction.ink_recheck prepare`

사용자 터미널 API 실행: 프로젝트 루트의 `필기수정_재검사.command`.
기본 8개 요청 단계, 수정과 재검사 포함 최대 24단계. 통신·형식 재시도 포함
호출 한도 72회/실행, 요청 간격 15초. 완료 단계는 재개 시 재사용한다.
이번 단계는 기존 음성 맥락을 후보로 보존하며 음성 API를 다시 호출하지 않는다.
다른 실행 결과는 `prepare --source <기존 실행 폴더> --output <새 폴더>`로 준비한다.
기존 파이프라인의 완료만으로 이 후속 단계가 자동 실행되지는 않는다.

## 출력 계약

- `prepared/*.json`: 변환 전 좌표계, 변환된 이전 결과와 수정 후보, 로컬 검사.
- `results/*.json`: 새 후보, 마지막 원본 검사, 항목별 판정, `effective_inventory`,
  실제 적용한 `changes`의 이전값·새값. 기존 값 중 보류인 항목도 이력상 보존된다.
- `records.jsonl`: 이번 원본 검사 통과 항목만 제공하는 공통 형식 데이터.
  `model_source_checked`는 모델과 계산 검사를 통과했다는 뜻이며 정답 승인이 아니다.
  `approved_for_rag=false`이고 전체 서비스 DB에 자동 게시하지 않는다.
- `pending.jsonl`: 남은 항목·누락·영역 검사 작업. 필수 영역 완전성은 개별 항목
  반영과 별도로 집계한다. 전사·개념 연결은 재검증되지 않았으므로 후보 상태다.
- `필기수정_재검사.html`: 원본, 항목별 상태, 실제 반영 변경, 보류 근거.

OCR 미판독이 독립적으로 해결됐다고 주장하지 않는다. 모델이 원본을 확인하면
OCR 미판독 상태를 함께 보존한 채 새 버전에 반영할 수 있다. OCR 충돌은 여전히
보류한다. 검사 통과율을 실제 정확도라고 보고하지 않는다.

## 의미 영향에 따른 후속 정책 (`ink_policy`)

완료된 `ink-recheck` 결과를 입력받아 `outputs/ink-policy-v1`에 새 버전을
생성한다. `필기정책_재검사.command`가 사용자 터미널 API 실행 진입점이다.
이전 실행 코드·결과는 그대로 유지하며 정답지와도 별도로 관리한다.

지워진 것으로 분류된 필기와 취소 표시·종속 관계는 로컬 준비 시부터
`administrator-review.jsonl`에 넣는다. 원본 위치·시간·내용은 보존하지만
활성 지식으로 내보내지 않는다. 지움 판정 자체가 잘못된 경우도 관리자가
확인할 수 있게 임시 판정임을 기록한다. 다른 정상 내용은 계속 처리한다.

조사 차이는 한글 일반 텍스트의 단일 어절 접미 조사 차이만 후보로 인정한다.
코드·숫자·영문 변수·어근 누락은 이 규칙에 들어가지 않는다. 새 원본 검사에서
주체/대상/부정/조건/순서 등의 의미가 유지됨이 확인되어야 경고로 낮춘다.
기존 전사·OCR 텍스트를 바꾸지 않고 차이를 남긴다. `가`를 무조건 지우거나
정답으로 추가하는 규칙이 아니다.

겹친 동그라미·밑줄·괄호가 단순 강조이고 대상이 확인됐으며 분리의 필요성이나
중요한 구별이 없다고 판정된 경우, `representation=emphasis_region`으로 저장한다.
이는 획 개수가 확정된 단일 도형이라는 주장이 아니다. 연결된 모든 대상이
검사를 통과해야 하며 방향·취소·구조·알 수 없는 대상은 이 완화 대상이 아니다.
기존 시간 범위가 유효한 음성 연결을 문맥 힌트로 사용하되, 설명이 없다는
이유만으로 중요하지 않다고 간주하지 않는다. 원음 API는 새로 호출하지 않는다.

부분 단어 누락은 픽셀 연결 성분으로 경계에 걸친 획과 근접한 앞뒤 글자를
찾고, 새 검사에서 상자 바깥까지 포함한 `full_text`를 독립적으로 읽게 한다.
후보와 원본 전체 단어가 다르면 모델이 `supported`라고 하더라도 코드가
다시 보류한다. 의미 유지가 확인된 조사 차이만 예외다. 수정은 최대 한 차례,
그 뒤 새 후보에 대한 원본 재검사가 필수다. 픽셀 의심은 오탐이 가능하므로
실제 누락 확정이나 글자 자동 삽입 근거로 쓰지 않는다.

`active_coverage_complete`는 관리자 분리 후 활성 내용 검사 완료 여부이며,
관리자 항목이 남아 있으면 `all_review_resolved`는 false다. 경고 허용 기록도
모델 검증 수준이며 정답 승인이나 전체 서비스 DB 게시를 뜻하지 않는다.

## 미처리 필기 이어 실행 (`ink_continue`)

`ink-context-v2`의 전체 감지 목록에서 `ink-policy-v1`의 활성 내용 검사가
완료된 원본·영역 ID만 제외한다. 현재 383개 중 8개를 제외한 375개이며,
이전 문맥 검사도 하지 않은 371개와 새 정책 적용이 필요한 4개다.
관리자 대기열은 이어 실행 보고서에도 유지하고 완료 제외와 구분한다.

`미처리필기_이어검증.command` 한 번에 8개씩 진행한다. 중단되면 현재 묶음을
먼저 재개하고, 묶음 완료 후 같은 명령을 실행하면 다음 묶음을 고른다.
한 프로세스의 API 상한은 60회이며 정상 단계는 영역당 3회, 수정 포함 최대
5회다. 완료·실패 후 검토 필요 결과는 자동으로 무한 재시도하지 않는다.

로컬 단계에서 원래 시점의 프레임을 고정하고 주변 crop·오프라인 PaddleOCR를
준비한다. 시각 추출 → 기존 ASR에서 근거 있는 문맥 연결 → 정책 원본 검사
→ 필요한 경우 수정·재검사를 수행한다. ASR 인용은 실제 제공된 세그먼트의
텍스트와 시간이 일치해야 하며 원음 확인으로 표현하지 않는다. 사람의 정답
표본/피드백은 API 입력에서 제외한다. 음성 API는 호출하지 않는다.

빈 추출은 원본에 내용이 없다는 증거가 아니므로 독립된 원본 검사를 거친다.
남은 누락은 pending.jsonl에 남기고, 관리자 검토는 administrator-review.jsonl,
새 검사 통과 데이터는 records.jsonl로 분리한다. 기존 8개 결과는 원래 실행
폴더에 보존하며 새 records.jsonl에 중복 수록하지 않는다.

이 실행 범위는 **이미 감지된 필기 영역**이다. 흑백 필기, 감지 ROI 바깥,
첫 화면의 기존 필기, 짧게 지나가 감지되지 않은 장면의 전체 재탐지는 별도
작업이다. 전처리의 본문·음성·문서 대기열도 별개이며 완료로 표시하지 않는다.

## 보수적 검토 결과 분리 (`ink_conservative_review`)

`ink-continuation-v2`의 원래 실행 계획·캐시·결과는 변경하지 않는다. 별도
`outputs/ink-conservative-review-v1/snapshots/<입력해시>`에 적용 결과를 저장하며,
`latest.json`과 `보류원인_검토.html`이 최신 검토 결과를 가리킨다. 서비스에서
이 결과를 읽을 때는 최신 스냅샷의 `records.jsonl`을 사용하고 원래 v2 결과와
중복 합치지 않는다. 서비스 DB 반영이나 정답 승인을 의미하지 않는다.

이 단계는 API를 호출하지 않는다. 후보의 글자·좌표·기호·관계를 수정하지
않고, 이미 비보류였던 판정과 기존 사용 기록이 변하면 작업을 거부한다.
OCR 오탐 해제는 해당 원본 이미지·결과·항목 해시와 직접 관찰 기록이 모두
일치할 때만 적용한다. 다른 항목이나 변경된 결과에는 승인을 재사용하지 않는다.

단순 동그라미·밑줄의 `source_geometry_partial`만 남았고, 내용·의미·대상은
원본 검사에서 지지되며 중요/방향/취소/분리 위험이 없는 경우에만 정밀도
경고로 처리한다. 이 기록은 포괄적 강조 대상만 뜻하며 정확한 원 개수나
숫자별 대응은 검증됐다고 표시하지 않는다. OCR 문자 충돌, 일부 내용 누락,
실행 방향, 취소 가능성, 좌표 범위 오류는 이 규칙으로 통과시키지 않는다.

보류는 연결 관계의 미해결 원인별로 묶지만 원래 판정을 삭제하지 않는다.
관계 자체에도 오류가 있으면 별도 원인으로 남긴다. 관리자 검토도 명시적
연결 관계가 있는 항목만 묶는다. 화면 59의 0/o는 관찰 문자열과 문맥 후보
0을 분리한 미확정 기록으로 유지하며, 강조 표시 누락 건도 별도로 보존한다.

`미처리필기_개선이어검증.command`는 기존 사용자 터미널 API 실행이 정상 종료하거나
예산 한도에 도달한 뒤 이 로컬 검토 단계를 실행한다. 이미 끝난 실행의 보고서만
갱신하려면 다음 명령을 사용한다(네트워크/API 없음).

```sh
${HOME}/Documents/Codex/2026-10-13/new-chat/work/asr-env/bin/python -m video_extraction.ink.policy.ink_conservative_review
```

검증은 현재 보류 10개(5개 영역), 기존 보류 없는 25개 영역, 오탐 해제 승인
불일치, 정상 텍스트·좌표 변조, 의미 있는 기호/화살표/취소/불명확 대상 등의
반례를 포함한다. 보류 감소율은 정확도 수치로 사용하지 않는다.

## 사용 가능 데이터 선별 (`usable_selection`)

사용자 터미널의 기존 이어 실행 명령은 API 처리 → 보수적 보류 정리 → 오프라인
사용 가능 데이터 선별을 순서대로 수행한다. API는 실행당 60회 한도를 유지하며,
한도에 도달해도 완료된 부분의 선별은 갱신한다. 전체 감지 필기 383개 중 현재
이어 실행 계획 359개와 이전 처리 24개를 함께 집계한다. 현재 계획의 미처리가
0개일 때만 `ink_processing_and_selection_complete`를 표시한다. 다른 모달리티의
전체 완료 여부는 별개이며 이 명령으로 true가 되지 않는다.

선별 원본은 작업별로 하나만 고른다: 현재 보수적 검토 스냅샷, 이전 원본 대조
반영본, 이전 이어 실행본, 초기 정책 검사본 순으로 해당 작업의 버전을 선택한다.
동일 작업의 과거 결과를 중복 연결하지 않는다. 원본·판정·효과적 추출값·저장된
원본 검사 근거가 일치해야 선별하며, 취소·관리자 검토·보류·판독 미확정·검증 전
관찰은 제외한다. 관계는 모든 연결 대상이 함께 선별될 때만 포함한다.

허용된 경고와 독립 OCR 검사 범위는 결과에 남긴다. 조사 차이는 의미 유지와
위험 없음이 확인됐을 때만 허용한다. OCR 전처리 변형 차이는 원본 직접 대조로
오탐임을 확인한 기록이 있을 때만 허용한다. 단순 강조의 부정확한 범위는 개수나
정확한 글자별 대응을 보증하지 않는 메타데이터로 취급한다.

`outputs/usable-selection-v1/latest.json`이 최신 입력 해시별 스냅샷을 가리킨다.
`text-for-chunking.jsonl`에는 관찰된 실제 텍스트만, `linked-metadata.jsonl`에는
표시·관계만 담긴다. 둘의 원본 ID와 출처는 유지한다. 임베딩·청킹은 아직 수행하지
않으며 `approved_for_rag`나 `gold_approved`를 원본에서 변경하지 않는다.
`excluded-observations.jsonl`은 제외 사유와 관찰 원본을 보존한다.

기존 `preprocessing-v1/records.jsonl`의 본문·음성·문서 등 2,124개 공통 항목은
정규화된 입력 스냅샷일 뿐이다. 이 파일의 `unassessed`나 `held` 항목은 자동 승인하지
않고 `other-modality-status.json`에 별도 상태로 기록한다. 수치는 서로 다른 단위
(원본 화면/문서 상위 항목 포함)이므로 필기 영역 수와 합산하지 않는다.

API 없이 선별만 갱신하려면 프로젝트 루트에서 실행한다:

```sh
${HOME}/Documents/Codex/2026-10-13/new-chat/work/asr-env/bin/python -m video_extraction.ink.selection.usable_selection
```

검토 원본이 바뀌어 스냅샷이 오래됐으면 먼저 `ink_conservative_review`를 다시 실행한다.

## 필기 외 데이터 (`other_data`)

`본문음성PPT_이어검증.command`가 별도 `outputs/other-data-v1`에서 실행된다.
기존 필기·영상·전사·PPT 결과를 덮어쓰지 않는다. 필기와 같은 실행 잠금을 사용해
동시에 API를 호출하지 못하게 한다. 한 실행의 전체 API 한도는 재시도 포함 60회,
요청 간격은 15초이다. 완료 작업은 건너뛰고 중단 작업의 API 응답 캐시를 재사용한다.
준비·보고서·PPT 원문 대조는 오프라인이며 실제 Gemini 호출은 run 모드뿐이다.

현재 등록된 범위는 대표 영상 화면 115개(본문 추출이 없는 83개 우선), 원래 ASR
599개 구간(기존 검토 대상 75개 우선), PPT 내장 이미지 9개이다. 세 종류를 번갈아
처리해 한 종류가 계속 밀리지 않는다. 대표 프레임 사이의 모든 영상 순간이나
ASR 구간 밖에서 빠진 음성을 모두 탐지했다는 뜻은 아니다.

PPT 5개 파일 114장은 원본 패키지의 관계 순서와 XML 텍스트·표를 직접 파싱한다.
338개 본문/표 항목의 값이 기존 추출과 일치했다. 줄바꿈·공백·숫자·표의 빈 칸을
보존하며, 원본 코드/지식을 문맥으로 고치지 않는다. `evaluation_reference`인 21개는
처리 기록에 남기되 검색용 선별에서 제외한다. 원본 4개 연결선은 의미와 연결 대상을
텍스트 파싱만으로 확정하지 않고 native-pending.jsonl에 남긴다. 슬라이드의 실제
렌더링/레이아웃 검증은 수행하지 않았으므로 visual_layout_verified=false이다.

영상의 기존 32개 결과는 공통 전처리에 보존된 수정본을 초기값으로 사용한다.
판독된 본문 문자열을 처음부터 새 모델 출력으로 교체하지 않는다. 손글씨·밑줄 등은
별도 필기 파이프라인이 담당하므로 이쪽 선별에서는 제외한다. 새 화면은 두 레이어
추출과 원본 감사, 의심 영역 재판독, 수정 후보의 원본 검증을 사용한다. 기존 미확정
항목의 보류는 모델이 동의해도 자동 해제하지 않는다. 문자열/종류/좌표 형식, 중복,
그림-본문 참조를 코드로 검사한다. 미해결 화면 범위 누락은 해당 작업 선별을 보류한다.

음성은 실제 원음의 해당 구간을 재전사한 뒤 원음을 다시 들려주어 비교한다. 전사가
변경되면 원래 단어별 타임스탬프는 새 단어에 재사용하지 않는다. 구간 타임스탬프와
원래 단어 시각은 보존하고 word_alignment_required=true로 둔다. 기존 겹침·분할
경계 문제는 별도 정렬/원음 확인이 필요하므로 선별에서 보류한다. 재검사는 같은 모델
검사이며 정답 표본 평가나 수치 정확도로 표시하지 않는다.

사용 가능한 데이터는 `other-data-v1/usable-records.jsonl`, 미확정 내용은
`review-required.jsonl`/`task-review.jsonl`에 저장한다. 전체 사용 가능 데이터 화면은
이 분야의 결과와 필기 결과를 별도 집계로 연결한다. 중복될 수 있는 화면 본문과
필기 주변 텍스트를 무작정 합쳐 임베딩하지 않는다. 임베딩은 아직 생성하지 않는다.
