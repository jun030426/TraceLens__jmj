# Lerny AI와 자료 처리 명세

버전 0.1 · 2026-10-09 · 모델 선정 전에도 구현 가능한 입력·출력·권한·품질 계약

교수 자료가 학생 콘텐츠의 사실 근거다. 모델은 표현을 바꾸고 새 연습 입력을 만들 수 있지만 근거에 없는 사실·교수 의도·시험 출제 예측을 만들어 가르치지 않는다. 공개 자료 생성과 비공개 기준 검증을 다른 작업으로 분리한다.

## 지원 파일과 초기 제한

| 자료 | 1차 처리 | 초기 제한과 실패 시 행동 |
| --- | --- | --- |
| PDF | 텍스트 추출, 필요 페이지 로컬 OCR | 파일100MiB·500쪽. 암호화 파일은 잠금 해제본 요청 |
| PPTX | 슬라이드·발표자 노트·표·이미지 분리 추출 | 100MiB·300슬라이드. 슬라이드 번호 보존 |
| DOCX·TXT·MD | 문단·제목·표 추출 | DOCX50MiB, 텍스트10MiB. 문단 위치 보존 |
| 음성 MP3·WAV·M4A | 로컬 전사, 시간 구간 보존 | 300MiB·180분. 긴 파일 분할 안내, 전사 검토 필요 |
| 예제 C·Java·Python | 소스·함수·라인 위치 추출 | 파일1MiB, 업로드만으로 실행하지 않음 |
| 구형 PPT·HWP·HWPX | 1차 직접 추출 제외 | PDF/PPTX/DOCX 변환 안내, 지원하지 않는데 성공 처리 금지 |

이 제한은 개발 기본값으로 조정 가능하다. 확장자와 MIME·실제 형식을 교차 검사하고 압축 문서의 해제 크기·파일 수·중첩을 제한한다. 매크로·외부 링크·문서 임베디드 코드를 실행하지 않는다. PPTX 노트나 DOCX 숨은 내용도 교수 검토 대상에 포함해 의도치 않은 공개를 줄인다.

일반 자료는 저장·안전 검사 후 원본 열람, AI는 별도 처리다. 처리기는 페이지/슬라이드/시작·끝 시각의 위치 정보를 끝까지 유지한다. 읽기 실패·텍스트 없음·낮은 품질 OCR·전공 용어 불확실 전사는 needs_review로 두고 자동 문항 생성에서 제외한다. 교수 수정은 TextRevision을 증가시킨다. 표·코드·수식 해석이 불확실한 영역은 사실 근거로 사용하지 않으며 근거 화면에서 원본을 확인하도록 한다.

## 청크와 검색

개발 초기 청크는 제목 경계와 문단·코드 블록을 우선하며 목표400토큰·최대700토큰, 겹침60토큰을 시작값으로 둔다. 표의 헤더와 행, 함수와 설명을 가능하면 함께 보관한다. 모든 조각에는 material_version_id, text_revision_id, locator, course_id, access_class가 붙는다. 임베딩 모델·차원 변경은 새 인덱스를 구축해 원자적으로 전환한다.

학생 검색은 공개·활성·본인 과목 필터를 먼저 적용한다. 초기 후보는 벡터검색20개와 키워드검색20개를 합쳐 순위 결합 후 최대6조각을 문맥 예산 내에서 넣는다. 한국어 검색 품질을 고정 질문셋으로 평가하고 부족하면 형태소·재순위화를 추가한다. 유사도 임계값은 모델마다 다르므로 임의의 공통 수치로 근거 존재를 확정하지 않는다. 분반 진도는 자동 추천에만 제한이며 자유 질문은 모든 공개 주차를 검색한다.

캐시·검색 결과는 access_epoch와 source revision에 종속된다. 내부 기준 전용 검색은 학생 챗봇 경로에서 호출할 수 없는 인터페이스로 분리한다. 질문이 비공개 자료 제목·정답을 정확히 추측해도 해당 내용의 존재나 원문을 확인해 주지 않는다.

## 답변 계약

1. 질문 의도를 파악하되 학생·자료 속 지시를 시스템 권한으로 취급하지 않는다.
2. 공개 검색 조각으로 답할 사실을 선택한다. 정의·수치·복잡도·성질마다 실제 근거 연결을 작성한다.
3. 답은 grounded, insufficient, conflict 중 하나로 생성한다. 별도 supplements에는 근거 개념을 설명하는 AI 생성 비유·예시만 넣는다.
4. 출처 ID가 실제 검색 결과에 있고 활성 공개 상태인지 코드로 검사한다. 근거 문장과 주장의 관계도 검사하되 모델 검증만으로 완전성을 보장하지 않는다.
5. 근거 부족이면 부족한 부분을 명시한다. 충돌이면 두 공개 출처를 표시하고 진위를 단정하지 않는다. 구조 검증 실패는 최대1회 복구 후 실패 처리한다.
6. 공개 직전에 권한과 epoch를 다시 검사하고, 통과한 완성 답변만 학생에게 전달한다.

예를 들어 큐 개념과 선입선출 설명이 근거에 있으면 줄서기 비유는 가능하다. 시간복잡도 근거가 없으면 큐의 시간복잡도를 일반 지식으로 채워 답하지 않는다. 새 예제 입력값을 만들 때 계산·실행으로 결과를 검증한다. 교수 발언처럼 따옴표로 꾸미지 않는다.

구조화 응답은 JSON Schema로 강제하고 다시 서버 검증한다. 형식 준수는 사실 정확도와 별개의 조건이다. [Ollama 구조화 응답](https://docs.ollama.com/capabilities/structured-outputs).

## 이론 문제 생성

공개 근거와 concept_id를 입력으로 objective, prompt, type, choices, public_explanation, source_ids를 생성한다. 객관식은 단일 정답·중복 선택지·근거 충분성·단서 노출을 검증한다. 서술형은 공개 질문에 필요한 개념만 묻고 요소별 배점은 생성 시 고정한다. 정의만 있는 근거로 근거 밖 구현 복잡도를 묻지 않는다.

내부 검증 작업은 비공개 해설을 사용할 수 있지만 문항 질문과 공개 해설을 직접 쓰지 않는다. 비공개 자료는 모범 정답의 일치 여부와 내부 채점 기준 검증에만 활용한다. 비공개 기준에만 있는 지식이 필요하면 학생에게 가르치거나 감점하지 않고 문항을 반려하거나 교수에게 공개 근거 보충을 요청한다. 각 rubric criterion은 학생이 배울 공개 개념의 근거도 가져야 한다.

검증 통과 문항은 자동 ready로 전환하고 교수에게 목록과 신고·중지 수단을 제공한다. 실패 문항은 최대2회 재생성 후 rejected로 남기고 무한 반복하지 않는다. 문항 품질의 승인 기준은 JSON 통과뿐 아니라 정답·근거·난이도·오류 사례를 포함한다.

## 실습 문제 생성

실습 가능한 개념은 공개 자료에 실행 가능한 연산·자료 구조·알고리즘 또는 검증할 입출력 성질이 있고 지원 언어 범위 내로 표현 가능한 개념이다. 개념별 capability에 predict/fill/implement와 지원 언어를 기록한다. 순수 용어·역사 개념에 억지 코딩 문제를 붙이지 않는다.

공개 예제와 설명에서 언어 중립 학습 목표·입출력 계약·제약을 만든 뒤 C/Java/Python variant를 생성한다. 언어별 모범 코드·공개 예시·비공개 테스트를 생성하고 서버에서 컴파일·실행한다. 같은 테스트 생성 모델의 결과만 믿지 않고 손검증 예시, 빈 입력·경계·중복·역순 등의 성질 검증과 가능한 경우 독립적인 참조 구현을 비교한다.

세 언어 모두 가능한 문제는 같은 입력과 기대 의미를 갖는다. C 포인터 표현처럼 언어 고유 목표는 강제 번역하지 않고 관련 개념의 별도 family로 만든다. 준비되지 않은 언어는 지원되는 것처럼 표시하지 않는다. 하루 문제는 미리 생성·검증된 은행에서 당일 이론 개념 → 현재 분반 진도 내 최근 실습 가능 개념 순서로 배정하며 학생이 들어올 때마다 GPU로 새 문제를 만들지 않는다. 모범 답안만 통과시키지 말고 대표적인 오답 코드가 실제로 실패하는지도 검증한다.

## 서술형 채점과 재판정

입력은 question_revision, private rubric, 학생 답안, 사용 가능한 공개 근거다. 외부 API를 호출하지 않는다. 출력은 각 criterion_id별 met/partial/unmet, 학생 답안의 인용 span, 근거 유형, unstable_reasons다. 존재하지 않는 인용·누락된 기준·중복 criterion·범위 밖 점수는 held 처리한다.

배점은 양의 정수로 고정하고 충족 배수는 2/1/0이다. 분자는 sum(weight × multiplier), 분모는 2 × sum(weight)이며 `numerator × 100 >= denominator × 70`일 때 정답이다. 판정 전에 표시 퍼센트를 반올림하지 않는다. 화면만 소수 첫째 자리로 표시한다. 69.95%를 반올림해70%로 통과시키지 않는다.

학생 피드백은 공개 기준에 따른 충족/보완 개념과 학생 본인 답안 인용으로 구성한다. 비공개 문장을 자유롭게 요약하는 작업은 거치지 않는다. 내부 기준과 학생 피드백을 별도 스키마로 제한하고 공개 근거로 설명할 수 없는 부분은 자동 피드백을 보류한다.

이의 접수 시 고정 문항·rubric·모델 버전으로 자동 재판정1회를 기록한다. 불일치나 실패는 held를 유지하고 운영 검토로 보낸다. 기존 오답으로 자동 확정하지 않는다. 운영자가 수업 판단을 해결할 수 없으면 교수에게 전달한다. 모든 변경은 GradeRevision과 관련 복습·통계 재계산으로 연결한다.

## 모델 선정과 재현성

초기 후보군은 로컬 실행 가능한 한국어·코드 지원 경량 instruct 모델 2종 이내, 양자화 모델부터 비교한다. 특정 모델이 8GB에서 충분하다고 미리 확정하지 않는다. 임베딩·OCR·전사도 무료 사용 가능한 라이선스와 배포 조건을 확인한 정확한 리비전을 기록한다. 외부 API나 클라우드 fallback을 켜지 않는다.

모든 생성에는 model_id, model_digest, prompt_version, schema_version, source_revision_ids, retrieval_config, generation_parameters를 남긴다. 원문 프롬프트의 일반 로그 저장은 금지하고 재현이 필요한 데이터는 해당 과목 권한과 보존 기간을 적용한 전용 저장소로 제한한다.

선정 실험은 공개 근거 질문60개, 근거 없음20개, 충돌10개, 주입·비공개 유출20개, 사람이 기준을 붙인 서술형60개를 사용한다. 실제 교수 자료가 준비되기 전 합성 자료로 파이프라인만 검사한다. 모델과 프롬프트를 고치는 개발셋과 최종 평가셋은 분리하고 실제 과목 품질을 합성셋 결과로 주장하지 않는다. 구체적인 통과 수치와 증거 형식은 검증 명세를 따른다.

## 숏츠 확장 경계

핵심 학습 사이클 통과 후 공개 근거 → 대본 → 사실·출처 검증 → 로컬 음성·캐릭터·슬라이드 렌더 → 검토 → 게시를 추가한다. 처음1명으로 생성 흐름을 검증한 뒤 얼굴·목소리·성격이 다른 오리지널4명을 완성한다. 실존 인물 모사와 무단 음성 복제를 제외하고 역이미지 검색·음성 권리·에셋 출처 기록을 남긴다. 자료 공개 변경은 게시 영상과 캐시에도 전파한다. 영상 모델·해상도·비용 수치는 후속 설계 대상으로 남긴다.
