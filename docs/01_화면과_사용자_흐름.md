# Lerny 화면과 사용자 흐름

버전 0.1 · 2026-10-09 · 기능 정책은 팀장 결정, 화면 구성은 구현 기준 초안

Lerny는 교수 자료로 만든 학습 콘텐츠와 학생의 학습 기록을 연결한다. 기존 TraceLens 프론트 디자인·화면 구조는 따르지 않고 새로 설계한다. 색상·로고·시각 스타일은 기능 흐름이 검증된 뒤 정하며, 이 문서는 경로·행동·상태·권한을 고정한다.

## 공통 화면 규칙

- 화면 상단에 현재 과목·학기·분반을 표시한다. 다른 과목으로 이동하면 자료·대화·학습 세션도 바뀐다.
- 서버가 반환한 권한으로 메뉴를 표시하고 모든 API에서 다시 권한을 검사한다. 숨겨진 버튼만으로 접근을 막지 않는다.
- 준비 중, 빈 목록, 실패, 권한 없음, 일부 완료를 구분한다. AI 처리 실패를 학생 오답이나 자료 없음으로 표시하지 않는다.
- 작업 대기는 새로고침 후 복원한다. 예상 시간은 측정 근거가 있을 때만 표시하고, 그전에는 대기 순서·처리 상태를 제공한다.
- 일반 자료는 저장·파일 안전 검사가 끝나면 열람 가능하다. 검색용 처리 완료를 기다리지 않는다. 거절 파일은 공개하지 않는다.
- 이론·질문·자료는 모바일 우선, 실습은 데스크톱 우선이다. 모바일 실습에는 문제·기존 코드·결과 열람과 데스크톱 이용 안내를 제공한다.
- 키보드 접근, 입력 오류 연결, 색상 외 상태 표기, 모션 감소, 실행 시각화 일시정지·단계 이동을 지원한다.

## 학생의 하루

1. 강의실에 들어가 오늘의 세션을 가져온다. 서버의 Asia/Seoul 날짜를 사용한다. 새로고침·다른 기기에서도 같은 구성을 반환한다.
2. 이론은 객관식 2개·서술형 1개, 신규 1개·복습 2개를 목표로 배정한다. 복습 부족분은 현재 진도 신규 → 이전 범위로 채운다. 신규 부족분은 복습으로 채운다. 유형까지 채울 문항이 없으면 가능한 수와 부족 이유를 표시한다. 중복 문항으로 3개를 꾸미지 않는다.
3. 힌트 사용 여부는 서버에 기록한다. 유효한 서술형을 제출한 뒤 채점이 보류되어도 참여에는 인정한다. 장애로 저장되지 않은 제출이나 빈 답안은 완료로 세지 않는다.
4. 해설을 본 뒤 다시 맞힌 결과는 같은 학습 에피소드의 재도전이다. 예정된 독립 복습과 구분하고 최초 정답률을 덮어쓰지 않는다.
5. 선택 실습 3문제는 당일 이론의 실습 가능 개념에서 예측·빈칸·구현을 각각 제공한다. 부족하면 현재 분반 진도 내 최근 배운 실습 가능 개념을 사용한다. 언어 전환 시 초안을 보존한다. 해당 문제의 언어 변형이 없으면 관련 대체 문제임을 알리고 사용자의 선택으로 이동한다.
6. 더 풀기는 복습 큐 → 현재 진도 신규 → 이전 범위 순서다. 자동 하루 추천과 달리 자유 학습에서 공개된 이후 주차도 선택할 수 있다.

문항 부족일에는 완료한 수만 사실대로 표시한다. 실제 3문항을 완료하지 않았으면 정상 3문항 완료·연속 기록으로 계산하지 않는다. 부족 상태는 교수에게 알리며 보충 생성 후 기존 답안을 유지한 채 빈 슬롯만 채운다. 이 동작은 구현 기준이며 부족일 연속 기록 보상 정책은 추후 변경 이력으로 관리한다. 안내자 토끼는 홈·완료·복습 안내를 돕고 교수 발언이나 성취를 지어내지 않는다.

채점 보류 중에는 공개 학습 기준으로 자기 점검할 수 있다. 자기 점검 기록은 참여 보조 정보이며 객관적 정답률·이해 상태를 바꾸지 않는다.

## 교수의 자료와 공개 흐름

업로드에서 `종류 → 주차 → 공개 범위 → 내부 활용 → 신규/교체`를 한 번에 확인한다. PDF라는 확장자만으로 일반 강의인지 정답인지 판단하지 않는다. PDF·PPTX 강의, 예제, 과제 안내는 공개 기본값이다. 녹취록·기출은 직접 선택하며 녹음·정답은 비공개 기본값이다. 비공개를 공개로 바꿀 때는 영향을 받는 원본·출처·학생 콘텐츠를 표시한다.

교체 자료는 원본 열람과 AI 활성 버전이 다를 수 있다. 새 원본은 저장 후 열람하고, AI 처리 중에는 구버전이 계속 검색되는지 명시한다. 기본은 새 버전 준비까지 구버전 AI 유지다. 교수는 오류가 심한 구버전을 즉시 중지할 수 있고 이 경우 해당 근거 기반 AI 콘텐츠는 준비 중으로 전환한다. 새 버전 검증이 끝나면 활성 버전을 원자적으로 바꾼다.

전사·OCR 수정은 새 텍스트 리비전을 생성한다. 교수의 개념 이름·병합은 안정적인 개념 ID에 보존하고, 자동 추출은 새 개념 제안으로만 추가한다. 과거 학습 기록을 신규 텍스트로 조용히 바꾸지 않는다.

## 과제와 시험

진행 중 과제와 연관된 문제는 `assignment_id`를 통해 해설 공개 정책을 상속한다. 제출했다는 이유만으로 과제 정답을 공개하지 않는다. 일반 연습은 제출 후 공개 근거에서 작성한 해설을 제공한다. 모의고사에서는 서버의 시험 세션 상태로 힌트·챗봇·해설 제한을 판정하며 다른 기기에서도 적용한다.

## 화면 인수 기준

F01~F16은 위 화면 또는 후속 숏츠 화면으로 연결한다. 숏츠는 핵심 관문 통과 후 추가하므로 현재 메뉴에서 동작하는 것처럼 표시하지 않는다. 빈 분반, 문항 부족, AI 대기, 자료 비공개 전환, 채점 보류, 언어 미지원, 모바일 편집 제한을 정상 화면과 함께 디자인한다. 기능 화면의 와이어프레임·컴포넌트는 이 동작 계약을 기준으로 구현 단계에서 작성한다.
