# 통합 환경 파일

Gemini 임베딩·콘텐츠, HeyGen, Supabase와 Vercel 배포 설정은 로컬에서 한 파일로 관리한다.

```text
C:\Users\USER\LernyPrivateData\secrets\team.env
```

예시는 `scripts/team.env.example` 한 곳을 기준으로 한다. 실제 키는 저장소·프론트·공유 ZIP에 넣지 않는다. 다른 경로를 쓰려면 `LERNY_ENV_FILE`을 지정한다. `Start-Team.ps1`은 기존 private 런타임을 우선 사용한다. 기존 `app.json`, `heygen.env`, DPAPI 파일은 복구용으로 보존하며 이후 수정은 통합 파일에서 한다.

| 용도 | 항목 | 설명 |
| --- | --- | --- |
| Gemini 임베딩 | `GEMINI_EMBEDDING_API_KEY` | 자료·질문 임베딩 요청에 사용 |
| Gemini 콘텐츠 | `GEMINI_CONTENT_API_KEY`, `GEMINI_CONTENT_MODEL` | 답변·문항·검토·대본 생성. 모델 ID는 실제 사용할 계정에서 확인 |
| 공통 Gemini 키 | `GEMINI_API_KEY` | 선택 사항. 용도별 키가 비어 있을 때만 사용. 같은 키를 두 용도에 넣어도 됨 |
| HeyGen | `HEYGEN_API_KEY`, `HEYGEN_AVATAR_ID`, `HEYGEN_VOICE_ID` | 키와 아바타·음성 ID |
| Supabase | `SUPABASE_URL`, `SUPABASE_SECRET_KEY` | 서버에서 Storage에 접근하는 주소·secret 키. 기존 service_role 키도 호환 |
| DB | `DATABASE_URL`, `LERNY_DATABASE_POOL_MODE` | 비밀번호가 포함된 PostgreSQL 연결 주소. 현재 개발용 로컬 DB 설정을 유지 |
| 공유 임베딩 | `LERNY_RAG_STORAGE` | `supabase`는 공유 벡터 저장·검색, `local`은 기존 로컬 인덱스. Supabase 주소와 서버 키 필요 |
| Vercel 자동화 | `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` | CLI 자동 배포용 선택 항목. 웹사이트 실행에 필요한 API 키가 아님 |
| 기존 클라우드 작업 큐 | `LERNY_AI_WORKER_TOKEN`, `CRON_SECRET` | 해당 배포 구성을 쓸 때만 각각 32자 이상의 서로 다른 값 |

현재 프론트는 Supabase에 직접 로그인하거나 데이터를 읽지 않으므로 publishable/anon 키가 필요하지 않다. DB 연결 주소의 비밀번호는 URL 인코딩한다. 임베딩 모델은 현재 코드상 `gemini-embedding-2`, 768차원으로 고정되어 있다. 모델을 바꾸려면 어댑터와 인덱스를 함께 변경해야 하므로 작동하지 않는 모델 환경 변수는 만들지 않았다.

## 읽는 순서

서비스 설정은 기존 app.json → 통합 파일의 비어 있지 않은 값 → 프로세스 환경 변수 순으로 우선한다. 같은 계층의 `LERNY_*` 이름이 별칭보다 우선한다. 기존 `GEMINI_MODEL`, `LERNY_GEMINI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`도 호환된다. 파일의 빈 값은 기존 값을 지우지 않는다.

통합 파일에는 비밀 값과 연결 정보를 저장한다. 파일만으로 실행 모드·학생 코드 실행·모델 호출을 켜지 않는다. Gemini API/worker 실행은 기존처럼 사용자가 `-EnableApiCalls`를 지정해야 한다. HeyGen 생성은 기존 CLI의 실행·확인 플래그를 유지한다. Vercel 토큰을 읽는 것만으로 배포하지 않는다.

```powershell
cd C:\Users\USER\dev\Lerny
.\scripts\Start-Team.ps1 -Component check
```

`check`는 실제 키를 출력하지 않고 임베딩용·콘텐츠용 키와 DB 설정의 유무만 확인한다. 통신·과금·모델 품질 검증이 아니다.

HeyGen의 두 CLI와 팀 RAG·미디어 엔진도 같은 파일의 키를 읽는다. HeyGen의 명시적인 `--env-file`은 해당 호출만 별도 파일을 사용할 때 유지한다. Vercel CLI가 설치된 환경에서는 `python scripts/run_vercel.py <Vercel 인자>`로 같은 파일의 배포 관련 3개 변수만 읽어 실행할 수 있다. 이 래퍼는 키를 명령줄 인자로 전달하지 않는다. 아무 인자 없이 실행하면 안내만 출력한다.

## Vercel 배포 환경

로컬 파일 하나로 관리해도 그 파일이 Vercel에 자동 전달되지는 않는다. 배포 대상의 Development/Preview/Production 환경에는 필요한 서버 변수를 별도로 등록해야 한다. 로컬 DB URL과 운영 DB URL을 섞지 않는다. Gemini 서비스 어댑터의 기존 local-only 제한과 클라우드 작업자 구조는 이번 환경 파일 통합에서 변경하지 않았다. 환경 변수 등록만으로 클라우드 Gemini 실행이 활성화되는 것은 아니다.

Vercel 실행 환경에서는 로컬 team.env와 app.json을 읽지 않고 배포 환경 변수를 사용한다. Vercel 토큰을 런타임 API에 넣을 필요는 없다.

## 검증

환경 파일·키별 전송 헤더·공통 키 대체·프로세스 우선순위·클라우드 격리·HeyGen·기존 Gemini 흐름 관련 124개 검사를 합성 값과 가짜 HTTP 전송으로 통과했다. 임베딩 키만 있는 경우 색인 작업은 재개되고 콘텐츠 작업이 큐를 막지 않는 것도 확인했다. 실제 키를 로그·모델 캐시에 남기지 않는다. 실제 API 호출·키 발급·회전·배포·운영 DB 변경은 수행하지 않았다.
