# Lerny 실행과 시각화 명세

버전 0.1 · 2026-10-09 · C·Java·Python 최종 제출은 모두 서버 검증

공식 채점 실행과 학습용 시각화 실행을 분리한다. 채점은 테스트 결과를 결정하며 시각화는 관측한 실행 사실만 보여준다. 시각화 상한 초과·미지원 값은 채점 실패가 아니다. 실행 기록에 없는 값·포인터 관계·반환값을 AI가 만들어 채우지 않는다.

## 언어와 지원 범위

| 언어 | 초기 실행 기준 | 시각화 지원 | 초기 제외·명시적 제한 |
| --- | --- | --- | --- |
| Python | CPython 3.12 계열 고정 이미지 | 지역 변수, int/float/str/bool/None, list/tuple/dict/set, 함수·재귀·예외·객체 참조 | 외부 패키지·네트워크·스레드·서브프로세스, native 확장 내부 추적 제외 |
| Java | OpenJDK 21 계열, 단일 Main.java 진입점 | 기본형·문자열·배열·사용자 객체 필드·참조·호출 스택·예외 | Maven/Gradle 의존성, GUI, reflection 기반 구조 해석, 다중 스레드 추적 제외 |
| C | GCC의 C17, 단일 main.c, 고정 Linux ABI | 기본형·배열·구조체·단일 포인터·연결 리스트·함수·malloc/free 사건의 관측 가능한 범위 | 임의 주소 역참조 시각화, 함수 포인터·복잡한 다중 포인터·union 해석·멀티스레드 제외 |

실행 도구의 patch 버전·이미지 digest는 환경 구성 시 고정한다. 문제는 이 지원 목록 안에서 생성한다. 컴파일이 된다는 이유만으로 모든 언어 기능이 시각화된다고 표시하지 않는다. 지원 불가 값은 unsupported, 깊이/길이 초과는 truncated로 표시한다.

## 작업 종류와 입력

RunRequest는 job_id, submission_id nullable, question_revision_id, variant_id, language, source_sha256, source, execution_profile, public_input_refs를 갖는다. 실행 제어 워커가 서버 저장소에서 검증한 테스트 묶음을 가져온다. 사용자가 runtime image·컴파일 명령·호스트 경로·제한을 지정할 수 없다. source는 최대32KiB, UTF-8만 받고 내부 생성 파일명으로 저장한다. CLI 인수를 고정된 배열로 넘기며 학생 텍스트를 shell 명령으로 조합하지 않는다.

문제의 기본 인터페이스는 표준입력/표준출력이다. 빈칸 문제도 완성한 전체 코드를 격리 실행한다. 예측 문제는 서버 모범 프로그램을 실행해 실제 출력을 비교한다. 문자열 비교는 CRLF를 LF로 바꾸고 마지막 개행1개만 무시하는 exact 규칙을 기본으로 한다. 공백 토큰 비교·부동소수 허용오차가 필요하면 문항에 명시적으로 고정한다. 학생 실행 후 비교는 신뢰된 실행 제어 프로세스에서 수행한다.

## 격리와 초기 자원 제한

API 프로세스에서 학생 코드를 직접 실행하지 않는다. 전용 Linux 실행 환경에서 작업별 새 비권한 컨테이너를 생성한다. 네트워크 없음, 비루트 UID, read-only root filesystem, cap-drop ALL, no-new-privileges, PID·메모리·CPU 제한, 제한된 tmpfs를 적용한다. 학생 코드가 쓸 수 있는 파일은 해당 작업의 임시 디렉터리뿐이다. 호스트 파일·다른 학생 파일·DB·비밀·Docker socket은 mount하지 않는다.

| 항목 | 초기 제한 |
| --- | --- |
| 실행 병렬수 | 워커 전체2개부터 측정 |
| 컴파일 | wall20초, 메모리 C256MiB·Java768MiB |
| 채점 실행 | 테스트당 CPU2초·wall5초, 전체 wall30초 |
| 실행 메모리 | C128MiB·Python256MiB·Java512MiB, JVM heap256MiB 이내 |
| 프로세스/스레드 | C·Python32, Java128. 이미지 smoke test 후 조정 |
| 임시 파일 | 작업당64MiB, 종료·취소·만료 후 삭제 |
| 출력 | stdout+stderr 합64KiB, 초과 시 output_limit |
| 코드·테스트 | 코드32KiB, 최대20테스트, 테스트 입력1MiB |
| 시각화 | wall10초, 최대20,000이벤트·직렬화6MiB·객체 깊이4·컬렉션 표시20개 |

이 값은 출제 가능한 문제 크기의 일부다. 더 큰 입력이 필요한 문제는 제한을 묵시적으로 늘리지 않고 실행 profile을 새로 검증한다. 메모리·시간 상한은 채점과 tracing profile을 분리하고 추적 부하로 학생을 오답 처리하지 않는다.

컨테이너는 완벽한 악성코드 방어라고 가정하지 않는다. 같은 커널을 공유하므로 실제 학생에게 공개하기 전 전용 실행 VM/호스트 격리와 탈출·자원 고갈 방어를 검증한다. Linux seccomp 정책은 언어별 정상 실행 및 디버거 요구와 함께 시험한다. GDB/JDI를 위해 웹 서비스 전체를 privileged로 실행하지 않는다. [Docker 보안](https://docs.docker.com/engine/security/).

## 결과와 오류

verdict는 `accepted | wrong_answer | compile_error | runtime_error | time_limit | memory_limit | output_limit | infrastructure_error`다. 앞7개는 학생 제출의 검증 결과이며 infrastructure_error는 학습 오답 분모에서 제외한다. 컴파일·런타임 오류도 문제를 풀려는 유효 제출로 기록하되 네트워크 장애와 구분한다. OOM kill은 커널/cgroup 근거로 판별하고 알 수 없는 종료를 임의로 memory_limit으로 추측하지 않는다.

공개 테스트는 입력·기대·실제 출력을 제공할 수 있다. 비공개 테스트는 통과 개수와 일반 오류 유형만 제공한다. 실제 입력·기대값·stderr·trace에서 정답 자료가 새지 않게 응답을 분리한다. 보안용 프로세스 종료와 학생 예외를 구분하고 source line은 학생 파일에 해당하는 범위만 반환한다.

## 실행 기록 계약

TraceEnvelope는 schema_version, language, source_sha256, runtime_digest, events, status, truncation_reason을 갖는다. 이벤트 공통 필드는 seq, kind, frame_id, parent_frame_id, observed_line, caused_by_line, locals_delta, objects_delta, stdout다. kind는 line/call/return/exception/allocation/free/diagnostic이며 allocation/free는 실제 관측한 C 사건에만 사용한다.

값은 primitive/reference/unsupported로 구분한다. reference는 실행 안에서 안정적인 object_id를 참조한다. C 메모리 주소는 `region_id + offset`으로 치환하고 raw 주소를 학습 의미나 정답으로 사용하지 않는다. 수명을 확인할 수 없는 포인터는 unknown으로 표시하며 화면을 위해 강제로 역참조하지 않는다. 객체 alias는 같은 object_id일 때만 같은 객체로 표시한다.

Python 줄 이벤트는 실행 전 관측인지 실행 후 변화인지 구분해야 한다. observed_line과 caused_by_line을 분리하고 반환·예외는 프레임 수명과 함께 기록한다. 디버거가 값을 읽기 위해 사용자 getter, repr, toString 등의 코드를 호출하지 않도록 한다. trace 파일은 프론트에서 HTML로 삽입하지 않고 문자열·구조 데이터로만 렌더한다.

Python은 sys.settrace를 기반으로, Java는 JDI, C는 GDB/MI를 후보 구현으로 삼는다. 디버거를 통과한 실행값만 시각화한다. JDI/GDB 연결 포트는 작업 내부에만 두며 외부에 게시하지 않는다. C 진단 실행에는 sanitizer를 별도 profile로 사용할 수 있지만 모든 미정의 동작을 탐지한다고 약속하지 않는다. [Python 추적 API](https://docs.python.org/3/library/sys.html#sys.settrace), [JDI](https://docs.oracle.com/en/java/javase/21/docs/api/jdk.jdi/module-summary.html), [GDB/MI](https://sourceware.org/gdb/current/onlinedocs/gdb.html/GDB_002fMI.html).

## 기존 코드 취급

기존 프론트 디자인과 구조는 새 제품 설계의 기준이 아니다. TraceLens의 TraceEvent에는 line/call/return/exception과 observedAtLine/causedByLine, localsDelta/objectsDelta가 있어 Python 어댑터 검토 자료로만 활용할 수 있다. 현재 타입에 C 메모리 수명·Java 지원이 있다고 간주하지 않는다. 실제 재사용 전에 코드·라이선스·회귀 결과와 새 계약의 차이를 기록한다.

검토한 `feat/cinematic-stage`의 고정 커밋 `ae29f9dbc16990a0ef79b8005e16803d4b527e61`에는 Gemini 직접 호출 어댑터가 있었다. Lerny에는 그 외부 호출·VITE_GEMINI_API_KEY 흐름을 가져오지 않는다. AI 연출 실패 시 사실 기반 일반 변수·배열·스택 보기로 돌아간다. [TraceEvent 소스](https://github.com/jun030426/TraceLens__jmj/blob/ae29f9dbc16990a0ef79b8005e16803d4b527e61/src/trace/types.ts), [기존 외부 호출](https://github.com/jun030426/TraceLens__jmj/blob/ae29f9dbc16990a0ef79b8005e16803d4b527e61/src/director/gemini.ts).

## 언어별 통과 사례

Python은 리스트 alias·재귀·예외·빈 컬렉션·한도 초과를 검증한다. Java는 기본형 배열·객체 alias·중첩 호출·NullPointerException·스택 제한을 검증한다. C는 배열 접근·구조체 연결 리스트·할당/해제·null·해제 후 참조 진단·종료 신호를 검증한다. 공통으로 같은 코드의 공식 채점 결과가 시각화 성공/실패에 영향받지 않고, 숨은 테스트가 화면에 노출되지 않아야 한다.
