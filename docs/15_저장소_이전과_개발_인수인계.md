# 저장소 이전과 개발 인수인계

2026-10-12. 제품 이름은 **Lerny**이며, 이후 개발 저장소는 [jun030426/TraceLens__jmj](https://github.com/jun030426/TraceLens__jmj), 기본 브랜치는 **master**다. 사용자가 현재까지의 작업으로 대상 저장소의 기존 파일을 교체하도록 요청했다.

## 작업 기준과 이전 방식

- 이전 소스 기준은 `jun030426/Lerny`의 `main` 커밋 `c9ffafb`와 이 Windows 노트북에서 누적한 로컬 변경 전체다.
- 대상 저장소의 교체 전 `master`는 `729f9a646351e6f83eb8726d39419464e3098dd1`이었다. 그 커밋의 후속 커밋으로 현재 프로젝트 파일 전체를 반영한다. 이전 프런트의 파일을 혼합하지 않으며, 과거 내용은 Git 이력에서 복구할 수 있다.
- 원격 강제 푸시나 저장소 자체의 삭제 대신 기본 브랜치 파일을 교체한다. 다른 기존 브랜치·이슈·저장소 설정은 별도 개발 범위다.
- 현재 노트북 체크아웃은 `C:\Users\USER\dev\Lerny` 그대로 사용한다. `origin`은 새 저장소, 이전 Lerny 원격은 로컬에서 `lerny-archive`로 구분한다. 이후 작업 전 `git remote -v`와 `git status -sb`로 확인한다.
- 원래 소스 이력과 로컬 변경 스냅샷은 로컬 `main`에 보존한다. 새 개발 기준은 `master`다. 두 브랜치를 자동 병합하거나 예전 `origin/main`을 새 기준으로 간주하지 않는다.

## 현재까지 반영한 내용

- 실제 C: 환경에서 외부 런타임, PostgreSQL 마이그레이션, 로컬 모델과 RTX 4060 연결을 구성했다. 합성 교수·학생·강의·분반·16주 자료·학습 기록을 만들어 학생·교수 화면을 확인했다.
- 학생 홈은 다음 학습 행동과 최근 기록을 우선한다. 강의실 이름의 불필요한 ‘16주 학습’ 표현을 정리했다. 사용자가 제외한 AI 강의의 큰 영상 영역과 진입 정책은 유지했다.
- 개념 학습 기록은 요약·주차·학습 상태·검색·페이지 이동으로 탐색한다. 전체 개념과 답안·해설은 계속 열람할 수 있고, 기록 없는 개념을 오답이나 0%로 단정하지 않는다.
- 강의·수강 신청·자료·질문 기록·지난 학습·시험 대비 목록에 검색, 필터, 펼침과 페이지 이동을 적용했다. 질문·학습 기록 API의 기간·검색·페이지 조회도 연결했다. 학습 중 작성한 답안과 질문 초안을 목록 탐색 때문에 지우지 않는다.
- 교수 학습 현황에서 개념명·정답률·집계 건수·막대를 가까이 배치하고 개념/학생 보기를 분리했다. 학생 답안 상세에 기간·개념·서버 페이지 조회를 연결했다. 시험 대비 카드와 편집 버튼의 여백·저장/취소 흐름을 정리했다.
- 학생·교수 모바일 메뉴는 펼침 방식으로 통일했다. AI 질문은 메시지만 스크롤하고 입력부는 보이도록 배치했다. 교수 자료는 이름·주차·상태 필터 및 8개씩 페이지를 제공한다.
- 퀴즈의 상단 소개와 카드 여백을 줄였다. 정답의 중복 답안 표시는 합치고 오답은 비교하며 해설과 서술형 근거를 보존한다. 질문 출처와 자료 원문/개념·문항 생성 상태를 읽기 쉬운 문구로 구분한다.

## 실행 환경과 저장소에 포함하지 않는 데이터

현재 소스는 `C:\Users\USER\dev\Lerny`, 런타임은 `C:\Users\USER\LernyData`다. 기존 PC의 D: 경로나 DB 복원 상태를 가정하지 않는다. 자세한 설치·실행 명령과 버전은 README 및 docs/14를 따른다.

- 웹 `127.0.0.1:5173`, API `127.0.0.1:8000`, PostgreSQL `127.0.0.1:55432`, Ollama `127.0.0.1:11434`.
- 모델은 로컬 `qwen3:4b-instruct`, `qwen3-embedding:0.6b`. 외부 LLM API나 자동 클라우드 대체를 사용하지 않는다.
- 소스·잠금 파일·마이그레이션·테스트·기획/개발 문서는 Git에 포함한다.
- DB, 계정 비밀번호, 업로드 자료, 모델, 가상환경, 패키지 캐시, 로그, 화면 증거, 합성 데이터 구성 및 실행 파일은 외부 런타임에 보관한다. GitHub만 clone해도 기존 계정·자료가 복원되는 것이 아니다.
- 다른 PC에서는 새 런타임과 DB를 구성하고 비밀정보 없이 합성 데이터를 다시 준비한다. 로컬 합성 계정의 자격 정보는 docs/14에 적힌 외부 secrets 경로에서만 확인한다.

## 검증된 범위와 남은 문제

프런트 빌드·회귀 9개, 개별 API 회귀와 합성 다량 데이터의 브라우저 검증 이력은 docs/14에 있다. 마지막 프런트 작업이 중단된 뒤 저장 상태, 빌드, 테스트, 교수 자료 목록·모바일 메뉴를 다시 확인했다. 기존 변경은 유실되지 않았다.

저장소 이전 준비 시 전체 API 회귀 **35개가 64.13초에 통과**했다. 테스트는 전용 `lerny_test` DB를 사용했고, 테스트 임시 파일·캐시는 외부 런타임에 저장했다. 업로드 대상 114개 파일에서 외부 런타임 파일, 로컬의 실제 비밀번호/DB 접속 정보와 일치하는 내용, 주요 토큰·개인키 패턴은 발견되지 않았다.

다음 사항은 아직 완료가 아니다.

- 자동 문항 생성: 합성 16주 자료의 원문 처리는 완료됐지만 자동 문항은 검증 단계에서 차단됐다. 화면 검증용 직접 작성 문항 3개를 자동 생성 성공으로 보고하지 않는다. 상세 오류와 실제 모델 측정은 docs/14를 참조한다.
- 텍스트 질문: 원문 근거 연결은 동작하지만 답변 종류 판정 정확성과 자유 설명 품질은 미검증/미완료다.
- 실습: 실제 문제 배정·Linux 격리 실행·서버 채점·trace·학습 기록 연결이 남아 있다. **학생 코드를 Windows 호스트에서 실행하지 않는다.**
- AI 강의: 자료 선택과 화면은 있지만 실제 영상 제작·재생, 강사 자산·음성 대화는 연결 전이다.
- 추가 학습·예습·개인정보/종료 정책·다중 사용자/품질 검증은 확정 기획과 docs/13의 후속 과제다.
- `/health/live`의 성공은 프로세스 응답이며 운영 준비 완료가 아니다. 격리 환경 미완료로 `/health/ready`는 503일 수 있다.

이전 업로드 요청은 이번 저장소 교체를 위한 승인이다. 이후 별도 원격 변경은 다시 해당 작업의 사용자 지시 범위에 따라 수행한다.
