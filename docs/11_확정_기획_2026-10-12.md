# Lerny 확정 기획

버전 0.4 · 기준일 2026-10-12 · 사용자(팀장)의 대화상 확정 사항

이 문서는 2026-10-09 기능 명세 v0.3과 이후 기획 문답을 통합한 최신 기능 정책이다. 팀 전체의 승인이나 구현 완료를 의미하지 않는다. 충돌하는 기존 문구는 이 문서를 우선하며, 변경하지 않은 권한·공개 경계·보안·로컬 모델 운영 원칙은 유지한다. 비교 대상은 저장소의 `Lerny 기능 명세 초안.md` v0.3이다. 외부 원본 기획서 v2·Page·PDF·DOCX는 이번에 직접 대조하거나 수정하지 않았다.

관련 문서: [변경 대조표](12_기획_변경_대조표.md), [남은 개발 작업](13_남은_개발_작업.md), [기존 개발 기준](00_개발_착수_기준.md).

## 1. 목표와 원칙

- 교수자의 자료를 기반으로 설명·문제·실습·복습·시험 대비를 연결하고, 학생과 교수자에게 학습 현황을 제공한다.
- 매력적인 실사형 AI 강사의 개념 강의가 핵심 콘텐츠이며, 코드 실행 시각화도 주요 학습 경험이다.
- 외부 공개를 위한 최소 기능 출시보다 프로젝트 전체의 완성도를 목표로 한다. 구현 단계는 후속 출시가 아니라 프로젝트 내부의 개발·검증 순서다.
- 퀴즈·실습 결과를 학교의 공식 성적이나 공식 출결에 직접 반영하지 않는다. 시험 대비는 실제 시험 성적 향상을 돕고, 교수자는 이해 수준을 파악하는 데 활용한다. 성적 향상 자체를 검증 없이 보장하지 않는다.
- 무료 로컬 도구·직접 실행 모델을 사용한다. 외부 LLM API·자동 클라우드 대체는 사용하지 않는다.
- 학생 코드는 호스트에서 실행하지 않는다. 격리 환경 검증 전 실제 실행을 활성화하지 않는다.
- GitHub 푸시와 원격 변경 없이 로컬에서 작업한다.

## 2. 교수자의 기본 운영

1. 과목·분반과 학기 일정을 등록한다.
2. 자료 업로드 시 주차와 공개 여부를 함께 지정한다. 이후 변경 가능하다.
3. 공개 자료에서 개념과 콘텐츠를 자동 준비한다.
4. 시스템 검증 통과 콘텐츠는 학생에게 자동 제공하고, 실패 콘텐츠는 보류한다.
5. 개념 편집·문제 관리·기출 추가·진도 조정은 필요한 경우에만 사용한다. 교수자의 사전 콘텐츠 검토를 필수로 요구하지 않는다.

공개는 수강 권한이 있는 학생에게 공개한다는 뜻이다. 비공개 자료는 학생용 검색·답변·문제·영상의 직접 생성 근거에서 제외한다. 기존 정책상 허용된 비공개 정답의 내부 검증·채점 활용은 별도 동의와 권한 아래 유지하며, 학생에게 원문이나 비공개 기준을 전달하지 않는다.

처리가 필요한 알림은 자료 처리 실패, 생성·검증 실패, 수강 승인 대기 중심으로 제공한다. 참여 현황·취약 개념·시험 대비 현황은 참고용 분석으로 제공한다. 개별 오답·채점 보류마다 교수자 알림을 보내지 않는다. 실패에는 재시도를 제공하고 교수자에게 직접 문항 작성을 강제하지 않는다.

## 3. 학기·주차·실제 진도

- 학기는 16주로 구성한다. 시작일을 기준으로 주차가 자동 진행한다.
- 기본 학습 범위는 해당 주차까지의 배운 개념을 누적해서 사용한다.
- 실제 수업이 밀리거나 빨라지면 교수자가 배운 주차·개념 지점을 지정한다.
- 수동 조정 후에는 다음 주가 되어도 지정 범위를 유지한다. 추가 조정 또는 '일정대로 자동 진행' 복귀가 가능하다.
- 자료 공개와 진도는 독립적이다. 미래 자료 공개만으로 일일 범위를 앞당기지 않는다.
- 시범 강의의 2026년 9월 일정은 해당 학기 설정으로 관리하며, 모든 과목에 임의의 동일 날짜를 강제하지 않는다.

## 4. 일일 학습과 연속 학습

| 구분 | 확정 기준 |
| --- | --- |
| 일일 이론 | 객관식 2문제 + 서술형 1문제, 총 3문제 |
| 일일 실습 | 시작 코드·함수 틀을 제공하는 핵심 로직 직접 구현 2문제 |
| 하루 인정 | 한 강의실의 이론 묶음 또는 실습 묶음 중 하나를 최종 제출 |
| 정답 여부 | 오답·부분 정답·채점 보류·도움받은 풀이도 완료 인정 |
| 미완료 | 시작·일부 답변·코드 실행만으로는 인정하지 않음 |
| 날짜 | 한국 시간 자정 기준, 실제 최종 제출일로 인정 |
| 중복 | 여러 강의실 또는 두 유형을 완료해도 전역 하루 1회 |
| 주말 | 매일 제출 필요. 하루를 빠지면 다음 완료일부터 1일 |

그날 처음 학습을 시작할 때 묶음을 배정하고 재접속·새로고침에도 유지한다. 진행 중 자료·진도가 추가되어도 묶음을 임의 변경하지 않는다. 자정 이후 제출하면 제출일에만 인정하며 같은 묶음으로 이틀을 인정하지 않는다.

유효하지 않은 문제는 대체하고 이미 제출한 유효 답안은 유지한다. 문제가 부족하면 준비된 수만 제공하며 모두 제출하면 완료 인정한다. 이론·실습 중 하나만 준비되면 그쪽으로 학습할 수 있다. 둘 다 서비스 사유로 제공 불가인 날은 연속 기록을 유지하되 학습 일수는 증가시키지 않는다. 이 예외는 학생이 학습하지 않은 날과 구분한다.

완료 후 '오늘의 학습 완료'와 '더 풀기'를 함께 제공한다. 추가 풀이로 같은 날 연속 일수를 더하지 않는다.

## 5. 추가 학습·예습·난이도

- '추천 문제 더 풀기'가 기본 행동이며 추천 이유를 표시한다.
- 배운 범위의 복습 시점·취약 개념을 우선하되 같은 개념만 반복하지 않는다.
- '개념 골라 풀기'와 공개된 미래 주차의 '미리 학습'을 보조로 제공한다.
- 새 문제가 부족하면 기존 문제임을 '다시 풀기'로 표시한다.
- 예습은 자료만 보는 기능이 아니다. 공개 자료·개념 설명·검증된 이론·실습·준비된 영상을 제공한다.
- 일일 학습과 예습은 진입 화면·목록을 구분한다. 풀이 화면은 재사용하되 목적·주차와 돌아갈 위치를 명확히 한다. 별도 문제 은행을 중복 구축하지 않는다.
- 추가·예습 기록은 이해도에 활용하지만 일일 묶음 밖의 풀이로 연속 학습을 인정하지 않는다.
- 예습 오답을 현재 진도의 취약점으로 섞지 않는다. 진도가 도달했을 때 기록이 부족하거나 복습 시점인 경우에만 확인한다.
- 기록이 없으면 기본 난이도에서 시작한다. 독립 풀이 기록에 따라 난이도와 시작 코드 양을 조절하며 단일 오답으로 수준을 단정하지 않는다. 학생에게 능력 등급을 붙이지 않는다.

## 6. 실습 언어·실행·채점·시각화

### 언어와 문제

C·Java·Python 중 교수자가 분반별 언어를 지정한다. 학생이 다른 강의실에 들어가면 그 분반 언어를 따른다. 예: A교수 Java 분반에서는 Java, B교수 Python 분반에서는 Python. 코드·제출·분석은 해당 과목·분반과 연결한다. 학생의 자유 언어 선택과 언어별 대시보드는 기본 흐름에서 제외한다.

초기 실습은 핵심 로직 구현이며 시작 코드와 함수 틀을 제공한다. 결과 예측·빈칸을 일일 필수 문제로 구성하지 않는다. 문제·시작 코드·테스트·시각화 학습 목표를 함께 설계한다.

### 실행과 제출

- '실행하기'는 공개 예제 또는 학생 지정 입력의 출력·오류·시각화를 확인하는 반복 가능한 연습이다.
- '최종 제출'은 별도 정상·경계 테스트로 서버 재실행·채점한다. 클라이언트 판정을 신뢰하지 않는다.
- 제출 후 통과 현황·오류 유형과 대표 실패 사례의 입력·예상 결과·실제 결과, 가능한 시각화를 제공한다. 모든 채점 테스트를 사전 공개하지 않는다.
- 실패 사례·힌트·정답·예시 코드를 확인한 재제출은 독립 풀이와 구분한다.
- 컴파일·실행 오류·시간 초과도 제출 결과이며 완료 인정 대상이다. 빈 코드 또는 시작 코드 그대로는 구현 필요 안내 후 완료를 막는다.
- 서버 장애는 오답으로 처리하지 않고 재시도를 제공한다. 수정·재제출이 가능하며 첫 제출과 재도전을 구분한다.

### 시각화

정답 알고리즘 애니메이션을 학생 실행처럼 제시하지 않는다. 틀린 코드도 실제 실행된 줄·변수·자료구조·출력을 보여준다. 무한 반복·오류는 안전 한도에서 중단하고 중단 전 상태와 원인을 표시한다. 이전·다음 단계, 재생, 실행 줄 강조를 제공한다.

| 내부 구현 순서 | 범위 |
| --- | --- |
| 1차 | 배열, 반복문, 탐색, 정렬, 스택, 큐 |
| 2차 | 연결 리스트, 재귀, 트리 |
| 3차 | 그래프, 복잡한 알고리즘 |

세 언어의 모든 문법·메모리를 지원한다고 주장하지 않는다. 언어별 검증된 지원 목록을 제공한다. 시각화 목적 문제는 공개 전 시각화까지 검증하며, 일반 실습은 지원 여부를 명시한다. 시각화 실패와 실행·채점 실패는 분리한다. 시각화만 실패하면 채점 결과를 유지하고 재시도를 제공한다. 1·2·3차는 프로젝트 내부 순서이며 최종 범위 축소가 아니다. '복잡한 알고리즘'의 구체적 지원 목록은 실행 명세에서 작성해야 한다.

## 7. 채점·AI 도움·복습·분석

### 불확실한 채점

근거가 충분하면 자동 채점하고 불확실하면 '채점 보류'로 표시한다. 보류는 오답·취약점과 정오 분모에서 제외하지만 일일 완료에는 포함한다. 시스템 재채점과 학생의 '채점 다시 확인'을 지원한다. 교수자의 개별 답안 검토는 필수가 아니다. 기존 서술형 요소별 100/50/0점·70% 정답 기준은 이번에 변경하지 않았다.

### 풀이 중 도움

단계별 힌트를 먼저 제공한다. 학생이 명시적으로 정답·예시 코드 보기를 선택하면 도움받은 풀이로 기록됨을 안내한 뒤 공개한다. 공개 가능한 해당 연습문제의 답안만 제공하며 비공개 정답·진행 과제 해설의 접근 경계를 우회하지 않는다. 힌트·정답·해설·실패 사례 열람을 구분해 기록하고 독립 정답률·숙달 판단에 섞지 않는다. 도움받아 제출해도 일일 완료 인정, 이후 다른 문제의 독립 정답은 숙달 근거로 활용한다.

### 복습과 통합 기록

오답·부분 정답 개념은 일일 이론 3·실습 2 안에서 복습한다. 별도 필수 숙제를 추가하지 않는다. 답을 본 직후 같은 문제를 맞혀도 복습을 해제하지 않는다. 이후 독립 풀이에 따라 간격을 늘리고 반복 성공하면 집중 복습에서 제외한다. 기존 1·3·7일 간격 및 마스터 정량 기준은 유지하되, 확장된 학습 맥락과 도움 이력에 맞춰 상세 계약·테스트를 갱신한다.

이론·실습·시험 대비 기록은 개념별로 연결하되 유형·목적·분반·첫 풀이·재풀이·도움 여부를 보존한다. 시험 대비의 독립 결과도 취약점과 복습 간격에 활용한다. 예정 간격이 없는 재풀이를 무조건 단계 성공으로 처리하지 않는다. 이론·실습 상태를 하나의 점수로 덮지 않는다.

학생은 취약 개념 → 설명/영상 → 문제 → 복습으로 이동할 수 있다. 기록이 부족하면 분석 부족으로 안내한다. 교수자는 과목·분반 전체와 학생별 상세를 확인하며 참여·첫 결과·재학습 변화·개념별 어려움·분모를 구분한다. 미래 예습과 현재 진도 분석을 구분하고, 기록 없는 학생을 낮은 수준으로 평가하지 않는다.

## 8. 시험 대비

- 시간 제한 모의고사는 제외한다. 기출·연습 문제를 자유롭게 풀고 개념을 공부하는 것이 목적이다.
- 교수자는 주차 범위를 지정하고 최초 '시험 대비 공개' 시점을 결정한다.
- 공개 이후 추가 콘텐츠는 검증 통과 시 자동 제공한다. 일일 진도에는 영향을 주지 않는다.
- 기출 업로드는 선택이며 범위의 공개 자료로 문제를 준비할 수 있다.
- 원본 열람과 사이트 내 풀이를 함께 제공한다. 정답 근거까지 검증된 문제만 자동 채점한다.
- 추출·정답이 불확실한 경우 원본 학습용으로 제공하되 채점·취약점 분석에는 넣지 않는다. 비공개 정답이 합쳐진 원본은 그대로 공개하지 않는다.
- 제출 전에도 '해설 보기'가 가능하다. 해설 참고 학습과 독립 풀이를 구분한다.
- 문제별 제출 후 채점·해설을 확인하고 자유 재풀이할 수 있다.
- 시험 대비 기록은 학생·교수 분석과 일일 복습에 연결하지만 시험 대비 자체는 연속 학습에서 제외한다.

## 9. 자료 변경·종료·개인정보

### 자료 변경

자료 추가는 기존 유효 문제를 유지한다. 교체·내용 수정은 영향받는 콘텐츠를 재검증한다. 비공개 전환·삭제 시 학생용 검색·생성·원문·해설·영상 제공에서 해당 내용을 차단한다. 진행 중 무효 문제는 대체하고 유효 제출은 유지한다. 과거 풀이 이력은 보존하되 철회된 근거 내용을 노출하지 않는다. 이미 인정된 일일·연속 학습은 취소하지 않는다.

### 학기 종료

종료 강의실은 보관 상태다. 공개 자료·본인 기록·준비된 문제·시험 대비로 자유 복습할 수 있다. 새 일일 배정·주차 자동 진행은 종료하며 자유 복습은 연속 학습으로 인정하지 않는다. 교수자는 분석·공개 상태를 관리할 수 있다.

### 학생 정보와 권한

가입 필수: 이름·아이디·비밀번호·이메일·전공·학번. 사진은 선택이다. 교수자는 담당 분반의 이름·전공·학번·학습 현황을 확인한다. 이메일과 다른 교수 강의의 기록은 기본 비공개다. 사진·비밀번호·이메일은 학생이 수정하며 이름·학번·전공 변경은 본인 확인 절차를 거친다. 기존 교수 수동 발급·공동 교수 권한·한 과목 한 분반·이동 이력 규칙은 유지한다.

### 보관과 삭제

- 학기 종료만으로 삭제하지 않는다. 계정·강의실이 유지되는 동안 보관·복습을 제공한다. 기존 '학기 종료 후 1년 삭제'와 충돌하는 학습 기록 정책을 대체한다.
- 탈퇴·강의실 삭제 시 접근 즉시 중단 → 30일 복구 기간 → 대상 개인정보·자료·학습 기록 삭제로 처리한다. 계정 탈퇴는 해당 회원 데이터, 강의실 삭제는 해당 강의 데이터에 적용하며 다른 강의까지 삭제하지 않는다.
- 음성 질의응답 원본은 기본 저장하지 않는다. 대화 텍스트·출처를 저장하고 학생이 직접 삭제할 수 있게 한다.
- 삭제한 학생의 기록은 식별 가능한 통계로 남기지 않는다.
- 기존 질문 원문 90일 보존 상한은 이번 문답에서 별도 폐지하지 않았으므로 유지한다. 학생 직접 삭제 또는 계정·강의 삭제 조건이 먼저 오면 먼저 적용한다.
- 백업의 기존 추가 30일 만료 상한은 유지하되 삭제 데이터의 재노출 방지·복구 시 삭제 재적용을 구현한다. 활성 데이터의 30일 복구 기간과 백업 만료를 구분해 고지한다.

이는 서비스 운영 결정이며 법정 보존 기간을 주장하는 내용이 아니다. 복구 본인 확인, 공동 교수 강의 삭제 권한, 감사 로그 수명 등은 기술·운영 상세로 작성한다.

## 10. AI 강사 콘텐츠와 프론트

### 캐릭터와 강의

- 독자적인 실사형 남녀 캐릭터 각 2명, 총 4명을 사전 제작한다.
- 학생은 자유 선택·변경한다. 개인 레퍼런스 업로드·캐릭터 생성은 제공하지 않는다.
- 기존 실존 인물 복제 금지·허용된 음성·모델 이용 조건·AI 표시 원칙은 유지한다.
- 실사형 강사가 전자 칠판 앞에서 자료·도표·코드·예시를 설명한다.
- 가로형 16:9, 개념별 2~3분 기본, 5분 미만으로 구성한다.
- 강사의 말·시선·손짓과 칠판 전개를 연결하고 복잡한 자료는 확대한다.
- 칠판 약 75%, 강사 약 25%는 샘플 조정 가능한 초기 구도이지 고정 품질 판정값은 아니다.
- 공통 개념·학습 목표·자료 구성 기반으로 캐릭터별 영상을 만들고 저장·재사용한다. 학생마다 재생성하지 않는다.

### 생성과 학습 연결

공개 자료는 미래 주차라도 영상 생성을 시작한다. 1명이라도 제작·검증을 마치면 먼저 제공하고 나머지는 준비 중으로 표시한다. 선호 캐릭터가 준비되지 않았다면 다른 강사를 선택할 수 있게 안내하며 선호 설정을 임의 변경하지 않는다. 영상 준비 중에도 공개 자료·검증된 문제는 먼저 이용한다.

주차별 영상 → 관련 퀴즈·실습을 권장하되 시청은 필수가 아니다. 시청 없이 바로 문제를 풀 수 있으며 시청만으로 연속 학습·정답을 인정하지 않는다. 시청 기록과 문제 이해도 기록은 구분한다.

### 질의응답

현재 영상의 개념·재생 시점을 연결한 텍스트 질의응답을 제공한다. 공개 자료를 근거로 답변하고 출처를 표시한다. 최종 목표는 선택한 AI 강사의 목소리와 음성 대화하며 텍스트·출처도 확인하는 것이다. 실시간 영상 통화는 범위에서 제외한다. 응답 속도·한국어 품질·중단 처리는 실제 장비에서 검증한다. 질문마다 새 강의 영상을 생성하지 않는다.

### 프론트 설계·구축 범위

주차별 영상 목록, 4명 강사 선택과 선호, 강사·칠판 플레이어, 자막·배속·구간 이동, 관련 문제 진입, 텍스트 질문·출처, 음성 대화 영역을 구축한다. 자료·영상 버전, 제작 중·부분 준비·실패·재시도·비공개·권한 없음·빈 상태를 포함한다. 기능 연결 전 상태를 실제 동작처럼 표시하지 않는다. 기존 학생·교수 디자인과 역할별 버튼 체계를 따른다. 이번 문서화 작업에는 UI 코드 수정이 포함되지 않는다.

## 11. 보류한 세 항목

다음은 사용자 요청으로 지금 결정하지 않고 개발 중 확정한다. 이 문서에서 임의의 상세 기준을 추가하지 않는다.

1. 영상 내용의 허용 범위와 정확성 검증 기준: 자료 밖 예시·비유의 범위 및 오류 영상 처리 기준.
2. AI 콘텐츠의 최종 품질·완료 기준: 외모 일관성, 한국어 발음, 입 모양·손짓·칠판 동기화, 음성 대화 품질 기준.
3. 캐릭터별 설명 분위기: 말투·속도·표현·성격의 차이와 적용 방식.

기존 공개 근거·비공개 유출 방지·권리 원칙은 계속 적용한다. 위 상세 결정을 완료했다고 표시하지 않는다. AI 강사 프론트 설계는 진행 가능하다.

## 12. 변경하지 않은 기준과 구현 상세

교수 계정 발급·공동 권한, 분반 이동 당시 제출 귀속, 서술형 배점, 복습 간격, 데이터 접근 제어, 학생 코드 격리, 파일 제한·성능 실측, 모바일 기본 학습·데스크톱 실습 우선은 기존 명세를 따른다. 정확한 난이도 알고리즘, 하루 배정의 자정 경계, 콘텐츠 부족일 증명, 코드 무수정 판별, 분반 언어 변경 시 기존 제출 처리 등은 위 정책을 만족하는 상세 계약과 테스트로 작성한다. 새 사용자 승인 사항처럼 취급하지 않는다.
