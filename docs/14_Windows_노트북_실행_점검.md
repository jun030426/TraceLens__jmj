## 작업 위치와 Git

- 요청 당시 OneDrive 바탕 화면의 `캡스톤디자인_Lerny` 폴더는 비어 있었다.
- 저장소를 `C:\Users\USER\dev\Lerny`에 새로 clone했다. 기존 파일·미커밋 변경을 삭제하거나 덮어쓰지 않았다.
- `main`과 `origin/main`은 `c9ffafb`. 마무리 시 fetch로 다시 확인했다. 커밋·푸시·원격 변경은 하지 않았다.
- AGENTS, README, docs/00·08·09·11·12·13을 확인했다. 최신 기능 정책은 11의 v0.4다.
- 기존 D: 드라이브는 이 노트북에 없다. 현재 런타임은 `C:\Users\USER\LernyData`다.
- 실행 스크립트·Python 설정의 D: 기본값을 `LERNY_RUNTIME_ROOT` 또는 사용자 홈의 `LernyData`로 변경했다. 중첩 실행 스크립트도 기존 환경변수를 유지한다.
- 기존 PC에서 이 변경을 사용할 경우 시작 전에 기존 런타임 경로를 명시해야 한다. 기존 DB·비밀번호를 새 기본 경로에 있다고 가정하면 안 된다.

문항 실패를 재현해 원인을 기록했다. 생성된 선형 탐색 객관식은 정답 내용이 보기 인덱스 2에 있는데 모델이 answer_index=0을 반환했다. 재검증은 올바른 보기 문자열을 선택해 이 불일치를 차단했다. 같은 출력에서 객관식 criteria 비어 있음, 서술형 criteria 2~4개, 해설의 내부 식별자 제외 조건도 지키지 않은 사례를 확인했다. 검증을 느슨하게 하거나 실패 문항을 활성화하지 않았다.

실제 질문 1건은 공개 자료에서 인덱스 1의 값이 20이라는 문장과 출처를 반환했다. 다만 명백한 충돌이 없는 이 예시를 `answer_kind=conflict`로 분류했다. 따라서 답변 근거 연결은 확인했으나 답변 상태 분류 정확성은 미통과다.

일괄 자료 처리의 자동 문항 생성이 질문·서술형 채점보다 먼저 실행되었다. 현재 워커는 생성 시각 순서의 단일 큐이며 실시간 요청 우선순위가 없다. 최종 확인 시 queued/running 작업은 0건이다.

## 후속 개념 탐색과 날짜별 기록 개선 (2026-10-12)
