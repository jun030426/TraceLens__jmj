# 팀 피드백 2차 반영 — 설계 (2026-08-16)

팀 테스트 + 1주차 교수 피드백("시각화가 애매하다, 완성도를 높여라")을 코드 작업으로 번역한 문서.
판정 기준(북극성): **영상 한 편을 보고 흐름이 이해되는가** — 컴공생 대상 설문("이 영상이 어떤 흐름인지 이해가 되시나요?")으로 검증한다.

## 핵심 설계 결정

### A. 폴백 구조 (피드백 3·10)

```
트레이스(사실) ──→ 규칙 콘티 choreograph ──→ 완성된 영상   ← 항상 성립 (Core)
                                   ↑
AI 대본(장식) ── salvage 검증 ── decorateShots ← 있으면 디테일 (Quality)
```

- **영상 본편은 AI 없이 완성된다** (기존 유지). AI 실패 = 장식 없음, 빈 화면 없음.
- **salvage**: 장면 단위 검증 — 유효 장면 채택, 무효 장면 폐기, 빠진 구간은 규칙 장면으로 충전. 유효 장면이 0이면 전체 규칙 폴백. 채택+충전 혼합이면 DirectorMode `ai-partial`("AI 연출·일부 보강") — 정직성 원칙에 따라 섞였음을 표시한다.
- **decorateShots**: AI 대본의 `pacing`(slow ×1.5 / fast ×0.6, 220~1800ms 클램프)과 `focus`(slow 장면에서 변수 펄스)만 소비. 모션 종류·값·좌표는 건드리지 않는다. timelapse 샷은 제외. 규칙 대본에는 적용하지 않는다(choreograph가 이미 자체 완급을 가짐 — 이중 감속 방지).

### B. 지연 최적화 (피드백 4)

1. **비차단**: `executeRun`은 규칙 영상을 즉시 setRun하고 재생 시작. AI 호출은 백그라운드로 진행, 도착 시 `screenplay/steps/shots(장식)`만 교체. 재생 중이면 샷 인덱스로 위치 복원(장식은 샷 수를 보존하므로 인덱스가 유효). run 토큰으로 이전 실행의 늦은 응답 폐기. 대기 중 상태 태그 "AI 연출 준비 중…".
2. **thinkingBudget 0**: 2.5-flash의 기본 thinking이 지연의 주범 — 이 태스크(구조화 JSON 선택)에는 불필요. 벤치(6샘플)로 검증 통과율 재확인(키 있을 때).
3. **프롬프트 슬림화**: 스팬에서 `eventKinds`·`funcs`·`sourceSeqRange` 제거(순서는 배열 순서로 전달), stdout 80자 절단.
4. fetch 20초 AbortController — 매달린 요청이 폴백을 영원히 막지 않게.

### C. 대표 시각화 어휘 (피드백 7·8) — 전부 결정적

| 어휘 | 트리거(트레이스 근거) | 화면 |
|---|---|---|
| 칸 번호 | 항상 | 각 칸 아래 인덱스 숫자 (TraceDiagram 관례와 동일: 칸 밖 아래, ink-3 모노) |
| `loop` | digest 스팬 iterations>1, 헤더 라인 재방문 | 좌상단 배지 "반복 N회차 / 총 M회" — 반복문이 돌고 있음을 상시 표시 |
| `compare` | line 이벤트의 소스 라인에 비교 연산자 + 양변이 트레이스 값으로 해석됨 | 상단 중앙 칩 "5 > 4 → 참" + 비교 대상 칸/변수 하이라이트 펄스 |
| `swap` | 같은 크기 리스트에서 정확히 두 인덱스가 서로 값을 교환 | 두 칸이 실제로 자리를 바꾸는 이동 애니메이션 (확대 동반) |
| `raise` | exception 이벤트 | 상단 오류 스트립에 오류명 표시, 끝까지 유지 + 기존 shake |
| setCell 정밀화 | 크기 같음 + 내용 변경 | 바뀐 인덱스"들"을 정확히 짚음 (기존: 마지막 칸만) |

- **compare 접지 규칙**: 이름 → 그 프레임의 지역 값(prim), `이름[첨자]` → 첨자가 리터럴이거나 지역 prim int일 때 그 리스트 칸. 양변이 접지될 때만 표시(못 하면 침묵 — 지어내지 않는다). 참/거짓 판정은 양변이 숫자일 때만 표기.
- 값의 신뢰성 원칙 유지: 표시되는 모든 값은 TraceEvent에서 온다. compare의 판정은 트레이스 값에 대한 산술이지 생성이 아니다.

### D. 오류 시각화 (피드백 1)

- 이벤트 있음: 터지는 지점까지 재생(기존) + `raise` 스트립(오류명 mono, 슬라이드 인, 끝까지 유지) + shake + 느린 템포(기존). 무대 안 색은 Drawn-State Rule 준수 — 강조는 모션·위치·내용으로, verdict 빨강은 배너(기존 관례)에만.
- 이벤트 0개(구문 오류 등): 무대에 오류 장면(중앙 카드: "실행이 여기서 멈췄습니다" + mono 오류 전문) — 빈 프레임 금지 원칙의 오류판.

### E. 줌 (피드백 5)

WorldStage를 `.film-viewport`(relative)로 감싸고 SVG 내용을 카메라 `<g>`로 감싼다. 휠 줌(중심 기준, 0.4~3배) + 배율≠1일 때 드래그 팬 + 우하단 버튼(축소/맞춤/확대). GSAP 타깃은 카메라 그룹의 자식이므로 간섭 없음. 새 실행(plan 변경) 시 리셋 — AI 장식 교체(shots만 변경)로는 리셋되지 않게 plan을 키로 쓴다.

## 하지 않는 것 (YAGNI)

- 카메라 자동 연출(샷 focus로 줌 인) — 수동 줌이 먼저. 필름 엔진 계획서의 보류 결정 유지.
- LLM이 좌표·효과·값을 직접 지정하는 확장 스키마 — spanRef 계약 위반.
- 재귀 전용 새 그림 — 프레임 스택 + recursionIndex로 이미 표현됨.
- PixiJS, 서버리스 프록시 전환(별도 트랙), maxSerializedBytes.

## 리스크

- `thinkingBudget: 0`이 대본 품질을 떨어뜨릴 가능성 → llmPass 벤치로 확인(키 없으면 "미검증" 기록하고 수동 확인 항목으로).
- compare의 소스 라인 정규식 오탐 → 문자열·주석 제거 후 매칭, 접지 실패 시 침묵. 표시가 안 되는 쪽으로만 실패한다.
- AI 도착 시 타임라인 재구축 → 샷 수 보존 + 인덱스 복원으로 위치 유지. 등록 순서(자식 effect 먼저)가 seek 가능성을 보장.
