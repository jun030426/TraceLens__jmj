# 학습자 시선 필름 (Learner-Flow Film) — 진단과 설계

**목적:** 비전공 학습자가 영상만 보고 실행의 흐름을 따라갈 수 있게 한다. "흐름이 읽히고, 중요한 순간이 임팩트 있게 남는" 필름으로 재연출한다.

## 진단 — 2026-08-18 버블 정렬(5원소) 31샷 전수 프로브 실측

| # | 문제 | 증거 |
|---|------|------|
| 1 | **주인공 상자가 출렁인다** — 변수만 바뀌는 샷마다 arr 상자가 중앙(s=1, x=612)↔우측 대기열(s=0.55, x=1005)을 왕복 | 샷 3→7 사이 4번 이동·축소 반복 |
| 2 | **자막이 화면과 어긋난다** — 교환이 재생되는 샷의 자막이 "같은 반복이 계속됩니다"/"j이(가) 1로 설정됩니다" | 대본은 3회차부터 접고, 필름은 10회까지 전체 재생 — 압축 규칙 불일치 |
| 3 | **모순된 숫자** — 배지 "반복 5회차 / 총 4회" (seen=헤더 방문 수, total=span 내 최소 방문 수 — 단위 불일치), 동시에 자막은 "(총 6회 반복)" | 화면에 서로 다른 숫자 3개 |
| 4 | **살아있는 변수가 사라진다** — LINGER(6샷) 미접촉이면 i·n·arr 알약 퇴장. 커튼콜에도 안 돌아오고, 최종 프레임 i=2 (실제 i=4) | 학습자: "i 어디 갔지?" + 마지막 화면이 거짓말 |
| 5 | **인과가 잘린다** — "5 > 2 → 참" 칩이 0.5초 만에 사라지고, 다음 샷 교환 때 이유가 화면에 없다 | 비교(판단)→교환(행동) 사슬 단절 |
| 6 | **읽기와 쓰기가 같은 모양** — 비교 펄스·대입 펄스 모두 동일한 scale 펄스, 색 구분 없음 | 시선 유도 부재 |
| 7 | **리터럴 탄생이 한꺼번에 터진다** — `arr = [5,2,4,1,3]` 다섯 칸 동시 팝 | "칸이 차오른다"는 서사 없음 |

| 9 | **비교를 읽을 시간이 없다** — 비교 샷도 BASE 520ms | 읽기 전에 사라짐 |

유지 확인(회귀 금지): 커튼콜에서 정렬 완성([1..5]) ✓, stdout 정산 ✓, seek 스크럽에서도 칸 텍스트 갱신 ✓, 격자 파이프라인.

## 설계 원칙

1. **한 샷 = 한 문장.** 모든 샷은 자막 한 문장으로 설명되고, 그 문장은 모션에서 결정적으로 생성된다 — 화면과 자막이 원리적으로 일치한다.
2. **주인공은 중앙을 지킨다.** 구성 변화는 이야기가 바뀔 때만 일어난다.
3. **판단은 파랗게 머물고, 변화는 따뜻하게 번쩍인다.** 읽기/쓰기의 색 언어.
4. **값은 순간이동하지 않는다.** 출발지를 알 수 있으면 날아간다.
5. **살아있는 것은 사라지지 않는다.** 최종 프레임은 항상 진실이다.

## 변경 설계

### A. compose — sticky focus·살아있는 변수·완전한 커튼콜
- **객체 sticky focus:** 이번 샷에 닿은 객체가 없으면 직전 focus 객체가 focus를 유지한다(무대 체류도 갱신). 다른 객체가 focus를 가져갈 때만 대기열로 물러난다. → 문제 1 해소.
- **변수 스트립 = 생존 기준:** `life` 안의 변수는 퇴장하지 않는다. MAX_VARS(8) 초과 시에만 가장 오래 안 닿은 것부터 내린다. → 문제 4 전반부.
- **커튼콜 = 살아있는 전원:** 마지막 샷은 lastTouch가 아니라 "최종 seq에 살아있는" 배우 전원을 무대에 올린다.

### B. choreograph — 필름 자막 (`Shot.caption`)
모션에서 결정적으로 생성하는 학습자용 한 문장. 우선순위: raise > swap(+직전 비교 참이면 "5 > 2 참 — 두 칸이 자리를 바꿉니다") > travel > compare("비교: 5 > 2 → 참") > grow/setCell/shrink > bind(별칭 강조) > setVar("j = 1") > push/popFrame("f() 호출 — 새 작업 공간") > stdout > loop. 조사 문제를 피하는 무조사 템플릿("{name} = {v}", "새 칸에 {v} 추가"). 압축 샷 기존 문구 유지. → 문제 2 해소.
- **마지막 프레임 진실:** 커튼콜 직전(모듈 return 처리 시) 살아있는 프림 변수의 최종값 setVar 정산 — flushLapse의 변수 정산과 같은 원리. → 문제 4 후반부(i=2 낡은 값).

### C. choreograph — travel 모션 (값의 이동)
새 모션 `{ v:'travel', from: {kind:'cell'|'var',…}, to: {…}, text }`. WorldStage의 shrink+setVar 추론을 choreograph 방출로 이관(의미층 소유). 소스 라인 접지(resolveOperand 재사용, `causedByLine` 기준)로 확장:
- `x = NAME[i]` → 칸→알약 여행
- `NAME.append(x)` / `NAME[i] = x` (x가 변수) → 알약→칸 여행
값·좌표는 전부 트레이스와 구성에서. 해석 실패 시 침묵(지어내지 않는다). → 문제 8.

### D. 인과 사슬 — 비교 echo + 완급
- swap 샷에 직전 비교(같은 객체, ≤2샷 전, 참)의 칩을 재표시 — 판단이 행동 위에 머문다. → 문제 5.
- 비교 샷은 MED_MS(850ms)로. → 문제 9.

### E. 반복 배지 정직화
"반복 N회째"(카운트업)만 표시, "/ 총 N회" 제거 — seen과 total의 측정 단위가 달라 모순을 만들었다. 압축 샷의 "남은 N회 빨리감기"는 digest 수치라 유지. → 문제 3.

### F. WorldStage — 등장의 리듬
- 같은 샷의 여러 grow는 칸 순서대로 계단식(캐스케이드) 등장. → 문제 7.
- 커튼콜: 칸들이 0→n 순서로 잔잔한 settle 웨이브 — "완성"의 마침표.

### G. 읽기/쓰기 색 언어 (CSS + 오버레이)
- 칸·알약에 플래시 오버레이 rect(fill=강조색, opacity 0) 상시 배치. **쓰기**(setVar/setCell/grow/swap)는 오버레이 opacity 1→0 트윈(따뜻한 번쩍임, 스크럽 안전). **읽기**(compare 대상)는 파란 링 stroke 트윈. 클래스 토글이 아닌 타임라인 트윈이라 되감기에도 안전. → 문제 6.

### H. App 자막 배선
`PlaybackStep.folded` 마커(expand의 fast·다중 seq 스텝). 자막 선택: 규칙 연출 = 항상 `shot.caption`, AI 연출 = 접힌 구간만 caption, 나머지는 AI 문장(의도 설명은 AI가 더 잘한다). Demo(파일럿) 화면은 자막 비표시라 실험 오염 없음.
