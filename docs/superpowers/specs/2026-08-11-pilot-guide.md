# 영상 이해도 파일럿 진행 가이드

- 대상: 컴퓨터공학 2학년
- 자료: **녹화 영상 6편 + 설문지** (코드·자막·챕터명 없음, 영상만 — `/demo` 전용 화면은 2026-08-19 삭제, 녹화 방식으로 전환. 아래 "녹화 제작" 절 참조)
- 검증 대상 가설: **텍스트 없이 영상만으로 "메모리에서 무엇이 어떤 순서로 일어났는지"가 읽힌다**
- 검증 대상이 아닌 것: 이 코드가 무엇을 하는 코드인지(의도). 실행 기록에 의도는 없으므로 묻지 않는다.

## 진행 절차

1. 참가자에게 **코드를 보여주지 않은 채** 영상 하나를 재생한다 (10초 내외, 다시 보기 허용)
2. 질문: **"방금 본 영상에서 무슨 일이 순서대로 일어났나요? 두세 문장으로 적어주세요."**
3. 답을 적은 뒤에 설문지의 다음 장에서 코드를 보여준다 (설문지에서 코드가 영상보다 먼저 노출되지 않게 배치)
4. 보조 질문: "영상이 이 코드와 맞았나요?" (5점 척도) + "영상만으로 이해되셨나요?" (5점 척도)
5. 다음 영상으로 (영상 순서는 참가자마다 섞는다 — 학습 효과가 순서에 묻어난다)

## 채점 기준

서술을 두 층으로 나눠 채점한다. 각 영상마다 아래 항목을 맞혔으면 1점.

| 영상 | L1 — 무슨 일이 일어났나 | L2 — 어떤 구조인가 |
|---|---|---|
| 영상 1 (fill) | 칸이 하나씩 늘어났다 | 같은 동작이 반복됐다 |
| 영상 2 (alias) | 이름이 두 개가 됐고 한쪽에 값을 넣었는데 상자가 하나였다 | **두 이름이 같은 상자를 가리킨다** |
| 영상 3 (copy-vs-alias) | 상자가 두 개가 됐고 각각 다른 값이 추가됐다 | **하나는 같은 상자에, 하나는 새 상자에 연결됐다** |
| 영상 4 (call) | 새 칸(프레임)이 나타났다 사라졌다 | **함수 안의 변수는 그 안에서만 존재한다** |
| 영상 5 (recursion) | 칸이 여러 겹 쌓였다가 하나씩 사라졌다 | **쌓인 역순으로 풀린다** |
| 영상 6 (dict-fill) | 항목이 하나씩 채워졌다 | 이름표와 값이 짝으로 들어간다 |

- **L1 정답률**이 1차 성공 지표다. 여기서 70% 이상이면 "영상이 사건을 전달한다"가 성립한다.
- **L2 정답률**은 도전 지표다. 특히 영상 2·3·5의 L2는 텍스트 설명으로도 학생들이 자주 틀리는 부분이라, 여기서 점수가 나오면 강한 근거가 된다.
- 코드를 본 뒤 "맞았나요?" 점수는 **영상이 거짓을 보여주지 않았는지**의 확인용이다. 여기서 낮은 점수가 나오면 시각화 정확성 문제이므로 최우선으로 고쳐야 한다.

## 층화 (체리피킹 방지)

영상은 두 등급으로 나뉜다. 결과는 **반드시 등급별로 나눠 보고**한다.

- **core** (우리가 잘하는 유형): 영상 1, 2, 4
- **mid** (더 어려운 유형): 영상 3, 5, 6

"전체 82%"가 아니라 "core 90% / mid 65%"로 보고하는 편이 신뢰를 얻고, 다음에 무엇을 개선할지도 알려준다.

## 파일럿에서 확인할 것 (효과 검증이 아니라 절차 검증)

이 파일럿의 목적은 "성공/실패 판정"이 아니라 본 실험 설계를 다듬는 것이다.

- 서술형 문항이 채점 가능한 답을 유도하는가 (너무 짧거나 너무 막연하지 않은가)
- 영상 길이(3~11초)가 적당한가, 다시 보기를 몇 번 하는가
- 재생 속도가 빠르거나 느리지 않은가
- 참가자가 어디를 봐야 할지 몰라 헤매는가 → 카메라(시선 유도)의 필요성 판단 근거
- 전체 소요 시간

## 현재 데모 사양 (실측)

| 영상 | 길이 | 무대에 등장 | 등급 |
|---|---|---|---|
| 1 fill | 10.9초 | 상자 1, 끈 1, 칸 8개가 차례로 채워짐 | core |
| 2 alias | 3.3초 | 상자 1, **끈 2**, 칸 3개 | core |
| 3 copy-vs-alias | 4.6초 | **상자 2**, 끈 3, 한쪽엔 99·다른쪽엔 -1 | mid |
| 4 call | 4.1초 | 프레임 1→**2**→1 | core |
| 5 recursion | 8.3초 | 프레임 2→**5**→3 (쌓였다 풀림) | mid |
| 6 dict-fill | 6.4초 | 칸이 `kim: 3` … `choi: 4`로 채워짐 | mid |

## 알려진 한계 (참가자 반응 해석 시 감안)

- **카메라가 없다.** 화면 어디를 봐야 하는지 안내하는 확대·이동이 아직 없어서, 무대가 넓으면 시선이 분산될 수 있다. 파일럿에서 이 문제가 관찰되면 다음 개발 1순위가 된다.
- **분기(조건문)와 계산 과정이 보이지 않는다.** `if`에서 왜 그 길로 갔는지, `a + b`가 어떻게 계산됐는지는 아직 모션이 없다. 그래서 데모에 조건 분기 중심 코드를 넣지 않았다.
- 영상 2가 3.3초로 짧다. 파일럿에서 "너무 빠르다"가 나오면 페이싱 기본값(520ms)을 올린다.

## 갱신 (2026-08-18) — 파일럿 진행 전 반영할 변화

위 절차·채점 기준은 그대로 유효하다. 다만 무대가 크게 바뀌어 사양·한계 절의 일부가 낡았다:

- **끈(전선)은 없다.** 연출 무대 전환으로 끈이 제거되고 **상자가 쥔 변수명 이름표**를 단다. 사양 표의 "끈 N" 설명은 이름표 기준으로 다시 읽을 것. 별칭(영상 2·3)은 "이름표 두 개 달린 한 상자"로 보인다.
- **카메라가 생겼다.** 오토 프레이밍 + 구성(포커스 중앙·대기열)이 시선을 유도한다 — "카메라가 없다" 한계는 해소. 관찰 항목은 "그래도 시선이 헤매는가"로 바꿔 읽는다.
- **비교가 보인다.** 저울(양팔 기울기 + 참/거짓 도장)과 값 막대(음수 없는 숫자 리스트)가 추가됐다 — 은유 스킨이 /demo에도 적용된다. 다만 데모 6편은 여전히 분기 중심 코드가 아니므로 채점표는 그대로다.
- **영상 길이 재실측 필요.** 완급 변경(비교 850ms·압축 정산·자막 축 정렬)으로 위 실측 표의 길이가 달라졌다. 녹화하면서 실제 길이를 표에 갱신할 것.

- 크롭 범위: 무대(필름) 영역만 — 코드 에디터·자막 바·콘솔·진행바는 **프레임 밖** (무자막 원칙 유지. 무대 안의 반복 배지·저울 도장은 원래 실험에 포함되던 무대 요소이므로 그대로)
- 설정: 배속 1× · 모션 줄이기 꺼짐 · 실행 후 자동 재생 켜짐
- 파일명: `pilot-1-fill.mp4` … `pilot-6-dict-fill.mp4` (라벨은 참가자에게 "영상 N"으로만)
- 녹화 후 위 사양 표의 길이 칸을 실측값으로 갱신

### 녹화용 코드 6편 (구 /demo 픽스처에서 회수 — 코드 변경 금지, 바꾸면 채점표와 어긋난다)

**영상 1 — fill (core)**
```python
numbers = []
for i in range(8):
    numbers.append(i * 2)
```

**영상 2 — alias (core)**
```python
first = ["kim", "lee"]
second = first
second.append("park")
```

**영상 3 — copy-vs-alias (mid)**
```python
base = [1, 2, 3]
linked = base
copied = base[:]
linked.append(99)
copied.append(-1)
```

**영상 4 — call (core)**
```python
def double(value):
    doubled = value * 2
    return doubled


start = 7
result = double(start)
```

**영상 5 — recursion (mid)**
```python
def countdown(n):
    if n == 0:
        return 0
    return n + countdown(n - 1)


total = countdown(4)
```

**영상 6 — dict-fill (mid)**
```python
ages = {}
for name in ["kim", "lee", "park", "choi"]:
    ages[name] = len(name)
```
