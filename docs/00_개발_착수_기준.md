## 우선순위와 변경 관리

최신 명시적 사용자 결정 → 기능 명세의 팀장 결정/팀 규칙 → 이 기술 명세 → 기존 기획서v2 순으로 해석한다. 기능 변경은 조용히 기술 결정으로 덮어쓰지 않고 이유와 영향을 기록한다. 사용자 후속 결정으로 TraceLens-test의 화면 이동·버튼 흐름을 참고한다. 디자인과 목업 데이터는 복제하지 않는다. [화면 흐름 변경 기록](10_화면_흐름_참고_반영.md)을 따른다.

기능 명세의 “팀장 결정”은 팀 전체 확정이 아니다. 이 묶음의 기술 스택·타임아웃·파일 크기·세션 경계 세부 규칙은 구현 기준 초안이며 실측 또는 팀 협의로 바꿀 수 있다. 공개/비공개 경계, 외부 LLM API 금지, 세 언어 서버 검증, 학습용 평가라는 원칙은 구현 편의로 바꾸지 않는다.

기능 기준의 원본 Page는 [Lerny 기능 명세 초안](https://chatgpt.com/space/page_b313c077eebc8191bea412f42befe39c)이다. 개발 기술 명세의 정본은 사용자가 지정한 이 로컬 폴더의 docs다. Page 요약과 충돌하면 기술 내용은 로컬 문서를 우선하고 기능 정책 변경은 두 위치의 변경 이력을 맞춘다.

## 문서 완료와 실제 준비

문서상 요구·상태·실패·검증 기준은 구현 시작에 사용할 수 있다. 실제 교수 자료와 수업별 개념 범위는 확보 여부 확인이 필요하며, 준비 전에는 합성 자료로 구조만 시험한다. Docker/WSL·언어 이미지·모델은 아직 설치·검증했다고 간주하지 않는다. 학교 요구사항의 원문 최종 대조와 팀 협의도 별도로 남는다.

다음 실행 순서는 P0 환경 검증 → P1 계정·과목·분반 → P2 자료 → P3 AI → P4 학습 기록 → P5 Python 전체 루프다. 이후 Java, C, 통합, 숏츠 순서다. 세 언어 최종 목표를 유지하면서 각 관문을 독립적으로 완료한다.
