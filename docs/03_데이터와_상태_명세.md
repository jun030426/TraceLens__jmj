# Lerny 데이터와 상태 명세

버전 0.1 · 2026-10-09 · 논리 스키마와 불변 조건. 실제 DB 마이그레이션은 구현 단계 산출물이다.

데이터는 과목을 격리 경계로, 분반을 학습 운영·통계 경계로 사용한다. 모든 ID는 서버 발급 UUID, 시간은 UTC timestamptz, 학습 날짜는 Asia/Seoul 기준 date다. 비율은 분자·분모로 보관하고 표시할 때만 반올림한다.

## 계정과 수강

| 엔터티 | 핵심 필드와 제약 |
| --- | --- |
| User | id, login_id unique, password_hash, display_name, status, deletion_requested_at. 학생/교수 자격과 과목 권한은 구분 |
| LoginSession | token_hash, user_id, expires_at, revoked_at. 원문 토큰은 DB에 저장하지 않음 |
| Term | id, name, starts_on, ends_on, timezone. 보존 만료의 학기 기준 |
| Course | id, term_id, title, lead_teacher_id, teaching_language, access_epoch, status. 이름 같아도 별도 ID |
| CourseStaff | course_id, teacher_id, can_analyze, can_edit, status. unique(course_id, teacher_id), 대표 교수만 초대·회수 |
| Section | id, course_id, title, join_code_hash, progress_revision, status |
| SectionProgress | section_id, concept_id, available_from, revision. 주차와 실제 개념 범위를 연결 |
| Enrollment | id, student_id, course_id, section_id, valid_from, valid_to. 활성 상태 unique(student_id, course_id) |
| StudentCourseState | student_id, course_id, status. unique(student_id, course_id), 분반 이동에도 유지 |

분반 이동은 같은 과목에서 이전 Enrollment를 닫고 새 Enrollment를 만드는 하나의 트랜잭션이다. 기존 Attempt.section_id와 enrollment_id는 불변이다. 진행 중 시험이 있으면 이동을 보류한다. 같은 날 학습 세션은 학생·과목·날짜를 기준으로 유지해 이동 후 중복 하루 구성을 만들지 않는다. 새 세션 추천은 새 분반 진도를 적용한다. 다른 학기는 다른 Course이므로 이해 상태·복습을 새로 시작한다.

## 자료와 개념

| 엔터티 | 핵심 필드와 제약 |
| --- | --- |
| Material | id, course_id, kind, week, visibility, internal_use, current_file_version_id, active_text_revision_id, access_epoch |
| MaterialVersion | id, material_id, version_no, object_key, sha256, mime, bytes, uploaded_by, created_at. unique(material_id, version_no) |
| TextRevision | id, material_version_id, revision_no, extraction_method, status, edited_by, error_code. AI 재처리·교수 수정 각각 새 revision |
| SourceChunk | id, course_id, text_revision_id, text, locator_json, embedding, embedding_model_revision, access_class. locator는 page/slide/time 범위 |
| Concept | id, course_id, canonical_name, description, edited_by_teacher, merged_into_id, retired_at |
| ConceptAlias | concept_id, label, origin. 자동 이름과 교수 이름을 덮어쓰지 않음 |
| ConceptSource | concept_id, chunk_id, mapping_status, created_by. unique(concept_id, chunk_id) |
| ConceptMerge | from_id, to_id, actor_id, reason, created_at. 순환·과목 간 병합 금지 |
| Dependency | artifact_type, artifact_id, source_revision_id, use_kind. 공개 생성/내부 검증 종속 관계 구분 |

각 자식의 course_id는 부모와 복합 FK 또는 동등한 DB 제약으로 일치시킨다. 벡터 검색에도 course_id·공개 상태·활성 revision 필터가 선행된다. 학생 검색용 뷰와 내부 검증용 뷰를 분리하고 공개 응답 직전 원본 ACL을 재검사한다.

Material.visibility는 `public | private`, internal_use는 `none | validation_grading`다. public은 해당 과목 수강자에게 공개라는 의미다. 인터넷 전체 공개가 아니다. 처리 상태는 `queued → extracting → needs_review | indexing → ready`, 실패는 `failed`, 교체 완료한 구버전은 `superseded`다. 파일 업로드 상태와 AI 상태는 별도 필드다.

새 AI 버전을 활성화할 때 이전 근거 기반 문항은 신규 배정에서 제외하고 재검증 대상으로 둔다. 교수 편집 개념 ID는 유지한다. 근거가 사라진 개념은 삭제하지 않고 연결 확인 필요로 표시한다. 병합 전 제출은 원래 ID를 보존하며 현재 대시보드는 병합 해석 버전을 사용해 합산한다. 같은 제출이 여러 별칭을 통해 두 번 세어지지 않게 한다.

## 문항과 학습 세션

| 엔터티 | 핵심 필드와 제약 |
| --- | --- |
| QuestionFamily | id, course_id, primary_concept_id, related_concept_ids, kind, assignment_id nullable. 동일 학습 목표의 변형 묶음 |
| QuestionRevision | id, family_id, version_no, public_prompt, public_explanation, status, provenance, created_by. 게시 후 불변 |
| PrivateAssessment | question_revision_id, answer_key/rubric, internal_source_ids, validator_version. 학생 serializer 제외 |
| PracticeVariant | id, question_revision_id, language, starter_code, io_contract, status, runtime_image_digest. unique(question_revision_id, language) |
| TestCase | variant_id, is_public, input_object_key, expected_object_key, comparator. 비공개 테스트 원문은 학생 응답 제외 |
| Assignment | course_id, title, due_at, solution_release_at nullable, explicit_release_by nullable |
| DailySession | id, student_id, course_id, section_at_creation, study_date, mode, status. unique(student_id, course_id, study_date, mode) |
| SessionItem | id, session_id, slot, question_revision_id, reason, required_kind, assigned_at. unique(session_id, slot) |
| Episode | id, student_id, course_id, family_id, purpose, session_item_id, independence_eligible, hints_used, solution_viewed_at |
| CodeDraft | student_id, episode_id, language, source, revision. unique(student_id, episode_id, language) |
| Attempt | id, episode_id, enrollment_id, section_id, question_revision_id, language nullable, answer, received_at, sequence_no, status |
| GradeRevision | id, attempt_id, revision_no, rubric_version, score_numerator, score_denominator, outcome, status, evaluator, reason, supersedes_id |
| ExecutionResult | attempt_id, job_id, runtime_digest, verdict, exit_code, duration_ms, test_summary, trace_key nullable, trace_status |

QuestionRevision.status는 `draft → validating → ready | rejected`, 운영 중 `ready → suspended | revalidation_required`다. 검증 실패 문항은 학생에게 배정하지 않는다. 문제 수정은 새 revision이며 진행 중 세션은 당시 revision을 유지한다. 정답 오류·공개 차단이 확인된 경우에만 세션 항목을 잠그고 대체 문항을 배정하며 원래 제출은 invalidated로 남긴다.

세션은 `preparing | ready | in_progress | completed | partially_available`다. 참여 완료와 객관적 성취 완료는 별도다. 최소 길이 등 유효 입력 검사를 통과해 저장된 서술형은 채점 대기·보류여도 참여에 인정한다. 최초 유효 제출은 제출 시각순으로 선정한다. 먼저 제출한 답안이 보류 중이고 뒤 재도전만 확정되어도 재도전을 최초 학습 성취로 승격하지 않는다. 보류가 풀리면 원래 최초 답안으로 집계를 재계산한다.

학습 에피소드는 동일 문항의 즉시 재도전·언어 전환을 묶는다. 독립 복습 에피소드는 예정일 이후 별도 변형 문항으로 시작하며, 힌트·해설 보기 전 첫 제출만 독립 성취에 적격이다. 자유 풀이에서 당일 해설을 본 동일 family의 답안은 독립 기록에서 제외한다. 처음 접하는 다른 family의 독립 풀이와 예정된 복습은 적격 기록에 포함하며, 최소 두 날짜의 정답 조건은 별도로 검사한다. 일반 풀이 횟수에는 비적격 재도전도 남긴다.

## 복습과 이해 상태

ReviewState는 `(student_id, course_id, concept_id, domain)` 고유 키, stage `due_next | interval3 | interval7 | graduated`, due_date, last_independent_attempt_id, revision을 갖는다. domain은 theory/practice로 분리한다.

| 사건 | 상태와 예정일 |
| --- | --- |
| 최초 오답 또는 독립 복습 오답 | due_next, 실제 풀이일 +1일 |
| due_next에서 독립 정답 | interval3, 실제 풀이일 +3일 |
| interval3에서 독립 정답 | interval7, 실제 풀이일 +7일 |
| interval7에서 독립 정답 | graduated, 오류 복습 큐에서 제외 |
| 어느 단계에서든 힌트 후 정답 | due_next, 실제 풀이일 +1일 |
| 해설 직후 재도전 정답 | 변경 없음 |
| 채점 보류·장애·무효 | 변경 없음, 최종 확정 후 당시 사건 순서로 재계산 |

졸업 개념도 일반 복습 후보로 남는다. 첫 정답 개념은 오류 큐를 만들지 않고 일반 복습 후보에 둔다. 채점이 늦게 확정되어 예정일이 과거가 되면 즉시 복습 대상으로 표시하되 이미 종료한 세션을 바꾸지 않는다. 주말 면제는 연속 참여 계산에만 적용하며 복습 날짜는 달력 날짜다.

MasterySnapshot은 최소 5개의 적격 이론 기록·최근 5개 중 4개 이상 정답·서로 다른 날짜의 정답 2회 이상을 만족하면 기준 충족이다. 표본 부족, 복습 권장, 기준 충족을 구분한다. 실습은 초기에는 언어별 성공률·오류 유형·복습 상태를 표시하고 이론 기준 충족과 합쳐 점수를 만들지 않는다. 한 문항의 primary_concept만 mastery 분모에 넣고 related_concepts는 탐색·참고에 쓴다.

## 질문과 통계

ChatThread, ChatMessage, ChatCitation은 소유 학생·과목·분반 당시 귀속·created_at·expires_at을 갖는다. 교수 개인 화면에는 개념·질문 횟수만 제공한다. 분반 질문 예시는 이름 제거와 본문 개인정보 제거를 거친다. 제거가 불확실하면 원문 대신 주제만 제공한다. 질문 많은 학생을 자동으로 취약 판정하지 않는다.

AnalyticsEvent는 attempt/grade/transfer/material 변경의 참조 ID와 schema_version을 가진다. source_event_id 고유 제약으로 중복 반영을 막는다. AggregateSnapshot은 계산 버전·마지막 반영 사건·분자·분모·보류 수·표본 수를 저장한다. 원본 사실은 Attempt와 GradeRevision이며 집계는 재생성 가능해야 한다.

교수 과목 정답률은 모든 적격 최초 제출의 정답 수 합 / 적격 최초 제출 수 합이다. 분반 퍼센트를 평균하지 않는다. 복습 성취는 독립 복습을 별도 분모로 집계한다. 소규모 표본에 낮은 신뢰도를 표시한다. 분반 이동 전 기록은 원래 분반 기간 통계에 남고 학생 개인 상세에서는 수강 이동 이력과 함께 연결한다.

## 운영 데이터와 보존

Job, IdempotencyRecord, Report, Appeal, Notification, AuditEvent, DeletionRequest, ExportJob을 둔다. API idempotency key는 사용자·경로·요청 해시와 함께 24시간 보존한다. Appeal은 attempt별 열린 건 1개, 자동 재판정 1회, 미해결 운영 검토 → 필요시 담당 교수로 흐른다. 신고만으로 문항이나 답안을 오답 처리하지 않는다.

학습 답안·코드·개인 기록은 학기 종료 후 1년, 질문 원문·개인 질문 출처는 90일이다. 탈퇴 시 계정 즉시 정지, 개인 데이터 30일 이내 삭제, 백업은 삭제 완료 후 추가 30일 이내 만료한다. 수강 취소는 접근만 즉시 닫고 기록은 기존 만료를 적용하며 별도 삭제 요청을 지원한다.

구현 기본값: 실행 임시 디렉터리는 종료 즉시, 상세 trace는 7일, CSV는 24시간, 작업 진단 메타데이터는 30일, 접근 감사 메타데이터는 1년 후 삭제한다. 진단·감사에는 답안·대화·자료 원문을 넣지 않는다. 교수 자료·파생 벡터·문제는 학기 종료 후 1년을 기본으로 하되 교수가 먼저 삭제하면 즉시 접근 차단 후 30일 이내 물리 삭제한다. 다른 학기로 재사용하려면 교수가 명시적으로 새 과목으로 복사한다.

백업 주기는 일 1회, 기본 순환 30일, 복원 시 삭제 tombstone을 재적용한 뒤 서비스를 연다. 학습 재채점·대시보드에는 삭제된 개인 데이터를 복원하지 않는다. 통계는 개인 식별을 복구할 수 없도록 재집계하며 작은 집단의 질문 원문을 영구 익명 통계라고 주장하지 않는다. 이 기간은 운영 설계 기준이며 법률 적합성 판정은 아니다.
