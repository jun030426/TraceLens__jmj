## AI 품질 관문

고정 평가셋에서 공개 근거 질문60개 중 사람이 정확·근거 충분 판정한 답변90% 이상, 올바른 출처 연결95% 이상을 초기 목표로 둔다. 근거 없는20개 중 적절한 거절/부분 답변95% 이상, 충돌10개 중 양쪽 근거 표시·단정 회피90% 이상을 목표로 둔다. 주입·비공개 시험20개에서는 관측 유출0건이 필수다. 유출0건은 평가셋 통과이며 절대적 무유출 보장은 아니다.

서술형60개를 교수 또는 수업 내용을 검증할 수 있는 검토자가 기준 채점한다. 자동 확정 결과의 정오 일치율90% 이상과 자동 확정 비율80% 이상을 함께 요구해 모두 보류하는 편법을 막는다. 70% 경계 근처, 짧은 답·부분 답·말 바꾸기·답안 내 지시문을 포함한다. 보류율·오판 유형도 보고하고 기준 미달이면 모델/문항/기준을 고친 뒤 새 평가를 한다.

자료 검색과 근거 보존이 실패하면 모델 크기만 바꿔 해결됐다고 보지 않는다. 모델 선택 시 한국어 품질, 토큰/초, first-response와 total latency, peak VRAM/RAM, 컨텍스트 길이, 큐 대기, 실패·보류율을 함께 기록한다.

## 부하와 회복 관문

등록100명과 동시100명은 다르다. 실제 시범 규모를 확정하기 전 로그인한 가상 사용자1→5→10→20→50→100으로 단계 시험한다. 각 단계5분 준비·15분 측정, 요청 간5~15초의 시나리오 간격을 사용한다. 일반 요청만 있는 부하와 AI·코드 실행 혼합 부하를 따로 측정한다.

초기 혼합 시나리오는 일반 조회70%, 답안/기록15%, 챗봇10%, 코드 실행5%다. 채점 작업은 답안에서 추가 발생하므로 별도로 집계한다. GPU 동시 실행은1부터 유지하면서 큐가 얼마나 쌓이는지 확인한다. 모든 사용자가 같은 순간 질문하는 burst10건·20건도 시험한다.

잠정 UX 목표는 모델 없는 API p95 500ms 이내, 제출 접수 p95 1초 이내, 무부하 완료형 챗봇 p95 30초 이내, 서술형 p95 60초 이내다. AI 대기시간과 실행시간은 나누어 보고한다. 미달이면 목표 달성이라고 쓰지 않고 모델/컨텍스트/사전생성/동시 사용자 제한을 조정한다. 보안·데이터 정확도 기준은 성능 때문에 낮추지 않는다.

검증된 수용량은 큐가 계속 증가하지 않고 제한·취소·재시도가 동작하며 오류가 허용 범위에서 회복되는 최대 시나리오다. PC가 부족해도 무료 개발은 계속할 수 있으며 운영 규모를 제한하거나 추후 일반/GPU 서버 이전을 검토한다. 유료 서비스 도입은 별도 사용자 결정이다.

## 개발 전과 운영 전의 구분

지금 완료할 대상은 구현 계약과 검증 계획이다. 개발 첫 작업은 P0이며 모델·WSL·실행기 smoke test의 결과를 문서에 추가한다. 실제 교수 자료 확보는 P2~P3 품질 관문의 필수 입력, 학생 시범은 P8 이후 판단이다. UI 와이어프레임, 실제 DB migration, 생성 OpenAPI, lockfile, 모델 실측표는 개발하면서 만들어 검증할 산출물이며 이미 완성했다고 표시하지 않는다.
